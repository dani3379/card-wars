## Project overview

"Burning Meadow" — a lane combat roguelike deckbuilder built in Godot 4.6 (gl_compatibility renderer, 2D). Inspired by Card Wars (combat) and Slay the Spire (roguelike structure). 4 lanes × 2 rows per side (front/back), simultaneous combat with Swift pre-phase, floop, spells. 3 acts with branching maps, shop/rest/event nodes, premade encounter lineups with fight passives.

## Running the project

Open in Godot 4.6+ and press F5. Main scene is `scenes/main_menu.tscn`. There is no build step or formal unit-test suite; `tools/_probe_*.gd` scripts are the headless regression harness.

For headless parse-checks during development: `Godot_v4.6.x-stable_win64_console.exe --headless --path "D:\Godot" --editor --quit-after 5 res://scenes/combat.tscn` — opens combat.tscn in the headless editor, which force-compiles Combat.gd and Card2D.gd. Any parse errors print to stderr. **CAUTION (2026-07-17): this recipe can silently pass on a broken script when the editor serves a cached compile** — it green-lit a Combat.gd with a real parse error. The honest gate is `--headless --path "D:\Godot" --check-only --script res://scripts/scenes/Combat.gd`: only "Parse Error" lines matter there ("Identifier not found: <autoload>" is a false positive of bare script checks — autoloads aren't loaded).

## Architecture

### Scene flow

`MainMenu → run setup (hero + ascension + daily/seed, one screen) → war-chest blessing → MapView → Combat/Shop/Rest/Event/Recruit/Treasure/Wayside → Reward → MapView → ... → Combat (boss) → GameOver`

Scene transitions use `get_tree().change_scene_to_file()`. Each scene is a `.tscn` in `scenes/` with a matching script in `scripts/scenes/`. The whole run-opening flow (setup screen, then the blessing pick) runs from MainMenu before the first map appears, building UI programmatically over the menu background. The war chest (remade 2026-07-03) rolls 3 honest + 1 priced opener from run-shaping pools (advance gold / sharpen / transform 2 / pick-1-of-3 uncommons / +7 max HP / 2 potions / relic — vs black ledger / widow's coin / butcher's kindness / hollow levy); every entry is alive at run start (the old Heal-12 and full-heal tiles were dead — the march begins at full HP). The menu column itself is 7 items max (CONTINUE / NEW MARCH / SKIRMISH / COLLECTION / HOW TO PLAY / SETTINGS / QUIT, + LOAD GAME only when 2+ slots are filled); daily run and custom seed live inside run setup, not the column. GameOver's MARCH AGAIN sets `RunState.rematch_request` and MainMenu consumes it on ready, jumping straight to the war chest with the same hero/ascension.

### Autoload singletons

- **RunState** (`scripts/state/RunState.gd`) — current run state: HP, deck, relics, gold, potions, map data, card upgrades, `phoenix_heart_consumed`. `start_new_run()` delegates deterministic topology/content creation to `scripts/campaign/CampaignMapGenerator.gd`; RunState retains persistence and `get_current_act_map()` / `get_available_nodes()` / `visit_node()` navigation. Card upgrades are tracked by `deck_uid`.
- **HeroDB** (`scripts/data/HeroDB.gd`) — 5 playable heroes (Raider/Stalwart/Acolyte/Pyromancer/Kindler). Each entry has `deck` (10-card list of CardDB ids) and `relic` (id of a `tier:"starting"` RelicDB entry). Picked at the start of every run from MainMenu — replaces the old "pick 1 of 3 starting relics" screen. **The starter contract (2026-07-06 progression pass): hero decks use ONLY starter-rarity cards** (the original 8 + the levy set Outrider/Palisade/Mourner/Spark; Kindler's plain doom commons are the sanctioned exception) — never seed a hero deck with pool commons/uncommons, that's what flattened the run's power curve. Drafted cards must always outrank the opener. Generals additionally offer a chosen "+" forge on the Reward screen (The General's Forge), and Recruit slates richen gently by act (65/30/5 → 55/38/7 → 45/42/13 c/u/r; flattened 2026-07-16 — commons stay the majority of offers every act, rares stay events; late-run power comes from c4+ pieces/tribes/forges, not rarity inflation. Same pass: 10 tribe-glue uncommons demoted to common and 6 vanilla commons added, one per tribe — see CardDB's rarity-floor block). **Cross-run muster unlocks (2026-07-04, options not stats)**: `relic_alt` (choice of signature relic, unlocked by the hero's first win) and `deck_alt` {name, tagline, deck} (alternate 10-card start, a 2-3 card swap on the default; unlocked by a win at Ascension 4+). The run-setup detail pane shows them as toggles (locked = dim hint lines); MainMenu hands the picks to `RunState.start_new_run` via `pending_signature_relic` / `pending_deck_variant` (consumed + cleared there). MARCH AGAIN rematches use defaults.
- **MetaState** (`scripts/state/MetaState.gd`) — cross-run persistence: win/loss counts, `unlocked_ascension`, per-hero `hero_stats` ledger (wins/losses/best_asc, shown on the run-setup detail pane), and the `daily_record` (today's Daily March: date/hero/result). Transient `last_victory_unlocked_tier` / `last_victory_was_fastest` flags let GameOver announce what a win just changed. Saved as JSON to `user://meta.save`.
- **CardDB** (`scripts/data/CardDB.gd`) — 192 total card entries: ~130 draftable (starter + common + uncommon + rare, incl. the 2026-07-07 fun slate: Rat Piper / Slow Match / The Petard / The Volunteer / Trebuchet / Muster the Fallen; the 2026-07-13 stolen-classics slate (7 cards; a second 8-card damage-leaning wave was built and REVERTED the same day — user verdict "weird for my game" — leaving only its `_desert_enemy_to_player` conversion refactor live): Grave Clutch / Pressed Man / The Undying / The Long Roll / Wolf-Pits / The Informer / Forgefire — genre-classic shapes (Nerubian Egg, Zombie Chow, Ouroboros/Feed, Reno, traps, Cabal Therapy, Apotheosis) retold in BM verbs, all but Grave Clutch skirmish-denylisted, verify `tools/_probe_stolen_slate.gd`; and the 2026-07-09 removal slate: Sapper's Charge / Ballista Bolt / Scatter the Line — Into-the-Breach push physics via `Combat._flank_push`, one universal rule: a push blocked by the field's edge or another body CRASHES, each party taking the card's printed crash damage (Shove — reworked onto the same rule — and Scatter crash at 2; Sapper's Charge is ALL physics: 1 scorch on the target, its throws crash at 4, the "+" rides the crash); Earthquake now shakes BOTH front lines back) + 18 enemy-only + tokens/curses. **Curses are a 6-card branded pack** (curse, wound, craven, deserters_mark, grave_debt, war_debt): `curse_playable: true` marks the one playable-at-a-price curse (Cowardice — costs 2, does nothing, Exhausts); `curse_on_draw: {type, value}` fires a draw sting in Combat (`lose_command` / `hero_damage` / `lose_gold`). Unplayability is ENFORCED by a gate in `Combat._on_card_played` (before 2026-07-03 curses silently resolved as free no-op spells). `random_curse_id()` rolls weighted (plain Curse commonest, Wound rarest); events can hand a specific mark via the `add_curse_id` effect. Card types: "creature" (ATK/HP/keywords) and "spell" (spell effect + targeting). `roll_card_reward(act, is_elite, is_boss)` for rarity-weighted picks.
- **RelicDB** (`scripts/data/RelicDB.gd`) — ~135 relics across tiers (starting, combat, utility, including 4x4-specific relics like Vanguard Banner / Rear Guard Charm). Each has hooks, effect ID, and value.
- **KeywordEffects** (`scripts/data/KeywordEffects.gd`) — 26 keywords. Dispatchers: `dispatch_on_enter`, `dispatch_on_death`, `dispatch_start_of_round`. On-enter types include: damage_opposing, damage_random_player, damage_all_enemies, draw, gain_gold, damage_face, debuff_opposing_atk, discard_random, copy_friendly, copy_opposing_keywords, copy_last_dead, look_top, cast_random_spell. On-death types: damage_opposing_lane, damage_all_enemies, summon, bonus_mana, damage_face, debuff_all_player_atk, damage_adjacent.
- **EncounterDB** (`scripts/data/EncounterDB.gd`) — 55 premade fight lineups across 3 acts (incl. the 5 rival-lord kits + 5 amalgam finales). Each encounter has ordered creature deck, reinforcement, HP, and optional fight passive. `REACTIVE_PASSIVES` dictionary defines per-encounter reactive triggers (e.g. `necromancer_tower` doubles enemy on_death via `_dispatch_reactive("ON_CREATURE_DEATH", ...)`). `build_enemy_deck(id)` returns Array[Dictionary] of card data. `get_reinforcement(id)` for infinite backup creature.
- **SetPieceDB** (`scripts/data/SetPieceDB.gd`, 2026-07-20) — **SET-PIECE HOLDS, the named actions of the war**: 3 authored scenarios (one per act) fought on the ordinary combat engine, each with an opening board someone placed on purpose, ONE twisted rule, and an objective on a clock. Thronebreaker's puzzle battles are the model; the house translation is *your deck + one twisted rule + a clock* (a handed deck would bypass the build, which is the standard complaint about the form). **A set-piece is NOT a new node type — it is a `combat` node wearing a `setpiece_id`**, the same precedent as `wayside_id`/`mutator_id`, so every routing, save, medallion, music and gold path works untouched. Five objective kinds live in `Combat._sp_evaluate_objective` (`hold_rounds` / `slay_marked` / `protect` / `break_face` / `clear_board`). **Failure is NOT death**: when the clock runs out the army WITHDRAWS — the toll is paid in HP, the trophy is forfeit, and the march continues (stated on the map tooltip before the player can commit). Trophies are tier `"event"` relics granted on the field, so they never leak into a roll pool. The one rule enforced by a GATE rather than a hook is `closed_lanes` (checked in `_play_creature`, `_place_enemy_card`, `_find_empty_enemy_slot`, `_pick_empty_for_summon`); closed lanes wear the `ClosedGround` exclusion hatch instead of a station mark, because a refusal the player can't see reads as a drag bug. Verify: `tools/_probe_setpiece.gd` (data + map) and `tools/_probe_setpiece_fight.gd` (boots the real combat scene per scenario).
- **EventDB** (`scripts/data/EventDB.gd`) — static event definitions only. `scripts/scenes/Event.gd` owns gates, effect execution, and presentation.
- **AudioBank** (`scripts/AudioBank.gd`) — central SFX/music dispatcher: `play_sfx(name, jitter, volume_db, pitch_base)` (`pitch_base < 1.0` deepens a cue — the low-HP heartbeat, boss horn, and doom tick are repitched stand-ins; those call sites check `has_own_sfx` so a real clip plays straight once it lands), `play_music(name)` (remembers each track's playback position and resumes there when it re-enters rotation — intros don't wear out), and `duck_music(depth_db, hold)` (dips the Music bus under victory/defeat/boss-entrance stingers as a relative offset, then restores the user's slider level). Every screen picks music from a pool via `play_music_random` (49-track library, all Buckley/Nakarada/RandomMind/Pablo-tier after the 2026-07-18 AAA pass: per-act map anchors, per-rival-lord boss leitmotifs in Combat's boss branch, mood-matched event pools, skirmish muster + credits + victory-variant slots — see `assets/audio/music/MUSIC_CREDITS.md` and `docs/MUSIC_AAA_PLAN_20260718.md`); `tools/_probe_music_wiring.gd` (headless) fails if any pooled name lacks a file. A cue whose `assets/audio/sfx/<name>/` dir is missing/empty plays its `SFX_FALLBACKS` stand-in (real clips in the primary dir auto-win); `tools/_probe_audio_cues.gd` (headless) fails if any `play_sfx` call site resolves to silence. Clash audio ownership: struck survivors sound via `Card2D._flash_hit` ("hit_creature"), kills sound ONCE at the impact beat via Combat ("creature_death" + `death_cue_played` flag that `_die()` respects) — don't add a second cue on either path.
- **CardTextureCache** (`scripts/state/CardTextureCache.gd`) — preloads card frames/art textures to avoid per-card disk reads. **Deck-sized work goes through the BATCHED path** (`bake_many` / `bake_battlefield_many` → `_bake_batch`, 2026-07-26): the real cost of a bake is not pixels but the two `await RenderingServer.frame_post_draw` (vsync-bound, ~33 ms/card at 60 Hz) plus the synchronous GPU flush inside `get_image()` (godotengine#75877) — and BOTH are per PASS, so a pass lays up to `BATCH_MAX_CARDS` cards out in a grid and takes ONE readback, then slices with `Image.get_region`. Construction (`BATCH_BUILD_PER_FRAME`) and slicing (`BATCH_SLICE_PER_FRAME`) both yield frames, because the first version of this traded 30 small stalls for one 513 ms frozen frame. Both batch entry points take an optional `validity: Callable` polled between passes (that is how `ScenePreload.cancel_deck_warm` stands the idle map warm down). **Never add a `for cd in list: await bake(cd)` loop** — that is the shape this replaced.
- **ScenePreload** (`scripts/state/ScenePreload.gd`, 2026-07-06) — warms and PINS every screen's PackedScene + the script-loaded big backgrounds (per-act arenas/campfires, map paper fiber) on ResourceLoader worker threads right after boot, so `change_scene_to_file()` hits the resource cache instead of re-parsing .tscn + re-decoding ~2MB backgrounds on the main thread per transition. After the queue drains it bakes one creature + one spell via CardTextureCache (windowed only) to pull the card-font glyph atlases and bake pipeline warm behind the menu. Music has the matching treatment inside AudioBank: `play_music` threaded-loads each track once per session into `_music_streams` (files run up to 18MB — the old sync `load()` was a per-transition hitch); `_pending_music_track` arbitrates races, `stop_music` cancels in-flight plays. Verify both: `tools/_probe_perf_pass.gd` (headless).
- **GameTheme** (`scripts/GameTheme.gd`) — fonts, colors, panel styles, and the enemy-name→art-alias map (now `scripts/data/CardArtAliases.gd`).

### Combat scene (`scripts/scenes/Combat.gd`)

Largest file (~20,400 lines after the 2026-07-14 backend restructure). **The online-skirmish layer lives in `scripts/net/CombatNet.gd`** (~4,750 lines, 132 functions: net turn machine, sealed orders, clash replay, practice bot, spell/potion mirrors, rematch) — a plain child Node created in `Combat._init` holding `combat` as its ctx (KeywordEffects precedent). The compatibility contract: **all net/sealed STATE stays on Combat** (probes and saves read it there), and Combat keeps a thin same-name delegator for every CombatNet function (await-forwarding for coroutines), so probes, `ctx._net_*` calls from KeywordEffects, and core call sites never mention `net.` — new net functions should follow the same pattern (body in CombatNet with `combat.`-prefixed member access, delegator + any new state var in Combat's tail section). Board painters (StationMark, TablePlate) live in `scripts/ui/painters/`, preloaded under their old names. `scripts/combat/CombatOps.gd` owns seeded gameplay randomness and side-aware hero/creature routing; combat-affecting code must use it, while cosmetic jitter may remain global. Core systems:
- **THE OPENING IS INTERLEAVED, and it is measured, not guessed** (2026-07-26). `_ready` hands the frame back between the build stages (`_build_board` → ambient/grade → `_build_hud` → `_init_decks`), and `_build_hud` / `_build_left_info_column` are **coroutines that callers MUST await** — run as one block they were ~340 ms during which NOT ONE FRAME RENDERED (a frozen bare arena, then everything popping in at once). Adding a build stage means adding a yield, not another 150 ms to that block. `_prewarm_enemy_art` fires ONE parallel decode wave (`CardArtAliases.prewarm_texture_paths`, requests first then join) plus ONE batched `bake_battlefield_many` — it used to serialise a threaded load AND a 2-frame GPU bake per creature. Measure with `--combat_trace` (after a bare `--`): `Combat._trace` stamps every opening milestone, and `tools/_probe_coldentry.gd` (WINDOWED, `--mode=ab` or the realistic `--mode=viamap`) reports board-visible / playable / per-frame gaps. **Judge a change by the frame-gap list, never by time-to-playable alone** — hiding work inside a synchronous block that renders nothing improves neither.
- **Round flow**: draw 4 → player plays creatures/spells, toggles floop, banks ≤2 mana → resolve floops → Swift phase → simultaneous combat (both rows attack each turn; front attacks first and is attacked first — back row is queue space, not a separate combat tier) → deaths/on-death → discard hand → enemy places creatures (escalates at `ESCALATION_REINFORCE_ROUND`) → passives → new round. Combat runs EVERY round.
- **THE MUSTER DELAY (2026-07-21, Cross Blitz's summoning sickness)**: a creature does NOT swing in the clash that ends the round it arrived in — it forms up and fights from the next round on. State is `CreatureInstance.ready_to_swing`, which **defaults FALSE so every arrival path gets the delay for free** (there is no single board-entry funnel — seven placement sites plus six *move* sites — so stamping arrivals by hand would miss one and re-stamp the moves). `Combat._start_round()` sweeps every body on the board to true; **CombatNet routes its round starts through that same function**, so solo and skirmish share one rule for both sides. The gate lives in `Card2D.can_attack()`, so everything reading it (the lane forecast, intents, sniper/ranged phases) inherits it automatically.
- **It stops a body INITIATING, never defending.** A mustering creature still trades with whatever strikes it — `_defender_is_mustering()` arms the counter in solo/sealed, where mutuality otherwise comes from both sides taking their own swing. Without this, arriving would mean offering a free kill.
- **Swift is the exception** (`Card2D.ignores_muster_delay()`, also honoured for granted Swift — War Cry / the Drummer). It keeps its pre-phase meaning and gains Cross Blitz's Swiftstrike role. **But Swift may not reach the FACE on its arrival round** — Hearthstone's Rush line, guarded in `_creature_hits_face`, so the keyword can't double as a burst finisher.
- **Round 1 is therefore a MUSTER round**: both lines deploy and neither swings; the first real clash ends round 2. This REPLACES the former "no setup-only turn" rule — player copy that implied round 1 always clashes is now wrong (see the `_update_hud` round-label comment).
- Verify: `tools/_probe_muster_delay.tscn` (23 checks — one round of delay on both sides, the counter, the Rush rule, snapshot replication, and legacy saves defaulting to READY). Measured cost via `_probe_autorun`: 21W/35L → 19W/37L over 56 fights, i.e. within noise — both sides pay it.
- **Board (4×4)**: `_player_field[4]` and `_player_back[4]`, mirrored `_enemy_field[4]` / `_enemy_back[4]`. `_row_array(is_enemy, row)` is the canonical accessor; `ROW_FRONT = 0`, `ROW_BACK = 1`. `_all_creatures_both_sides()` iterates everything.
- **Enemy deck**: `Array[Dictionary]` of card data, loaded from EncounterDB or built from legacy random pool. `_place_enemy_card(data, lane)` creates Card2D from card data dict directly.
- **Spells**: targeted spells enter `_targeting_spell` mode (click to resolve). Non-targeted resolve immediately. Exhaust pile separate from discard. `_last_spell_played_this_turn` enables Echo. `_auto_target_for(card_data)` picks a sensible target for self-resolving spells (used by Chaos Imp / Echo / Reposition fallback).
- **Sacrifice**: NOT a free player action. The player cannot kill their own creatures on command. Sacrifice only happens via specific card effects: the `blood_sacrifice` floop ability, the Offering / Fuel the Pyre spells (target-friendly sacrifice via 999 damage), and any future card with the "sacrifice" keyword as its play cost. All three paths route through `_trigger_player_sacrifice(victim)` so Bone Pile, Butcher's Cleaver, Reaper's Scythe, and the `ON_PLAYER_SACRIFICE` reactive fire uniformly. Same model as Slay the Spire.
- **Floop**: creatures with floop can toggle `will_floop`. Types include damage_any, summon_random, kill_adjacent_summon, steal_atk, heal_all_friendly, summon_token, redirect_adjacent, copy_opposing_floop, swap_atk, become_copy, drain, blood_sacrifice, etc.
- **Keywords**: Armored (-1 dmg), Swift (pre-phase), Thorns (1 back), Piercing (excess → face), Last Stand (survive once at 1 HP), Sniper (skips its column clash; fires in the post-clash ranged phase at its aimed quarry — drag the sniper onto an enemy to set a standing order in `_sniper_marks`, right-click to clear — else it culls the lowest-HP enemy; chains on each kill; enemy snipers always run the cull-the-weakest drill), Regenerate/Wither (start of round). Royal Guard passive grants adjacent-friendly -1 dmg and gains +1 ATK when hit (in addition to its redirect floop).
- **Encounter passives**: `_dispatch_passive_start_of_round()`, `_dispatch_passive_end_of_round()`, `_dispatch_encounter_on_enemy_death()`, `_dispatch_encounter_on_player_death()`, `_dispatch_encounter_on_enter()`. `_has_encounter_passive_keyword(card, kw)` grants piercing/thorns/armored to enemy creatures based on encounter passive ID.
- **Reactive passives**: `_dispatch_reactive(trigger, source_card, lane_idx)` fires per encounter's `REACTIVE_PASSIVES` entry. Triggers: ON_PLAYER_SPELL, ON_PLAYER_SACRIFICE, ON_PLAYER_FLOOP, ON_PLAYER_SUMMON, ON_CREATURE_DEATH, ON_PLAYER_DRAW.
- **Relic effects**: checked inline via `_has_relic()`. Major hooks: combat_start, turn_start, creature_played, hero_damaged, creature_death, sacrifice, bonus_draw, combat_end.
- **HUD**: built programmatically. Shows encounter name and passive description. Parchment-styled panels, screen shake via CanvasLayer offset. **Battle log** (2026-07-08): the top-left LOG tab opens a chronicle drawer; every beat routes through `_log_event(bb, data, side, icon_override, icon_tint)` / `log_status(card, text)` — new mechanics should log through those funnels, and paths that already feed them (keyword chips, `spawn_keyword_callout_kw`, strike/death/face-damage/potion/spell hooks) must not add a second call. Each row is illustrated (Hearthstone-style): actor call sites pass `_log_data(card)` + `_log_side(card)` so the entry shows a 34px card-art thumbnail with a side-tinted rim (gilt=you / ember=foe), and hovering a card-bearing row floats the full live-baked Card2D beside the drawer (`_show_log_preview`). Battlefield tokens carry a LIVE status rail (Card2D `_refresh_status_rail`, signature-polled) — transient statuses (Shield/Frozen/Stunned, temp Armored/Thorns) render tinted ahead of the gilt printed keywords; verify all three with `tools/_shot_battle_log.tscn` (shoots status/log/hover).

### Map system

CampaignMapGenerator (called by RunState) generates a branching map per act: 18 rows tall × up to 7 columns wide, 3 paths with a 3× merge bias (trunk road + branches). The act is a fixed **row skeleton** (Kaycee's-Mod model; lengthened 2026-07-07 from 12 rows / 5 combats — the act ended in 3-4 fights, too short for the deck/veterancy/relics to snowball): fight rows (`FIGHT_ROWS [0, 3, 9, 15]`, elite bands at `ELITE_ROWS [6, 12]`) alternate with PAIRS of wayside rows, so every between-fight gap is exactly two non-fight stops (Inscryption cadence) dealt from event / wayside verb / recruit / shop / treasure; `REST_ROW = 16`, `BOSS_ROW = 17`. Fight count per route is constant by construction — **7 combats: 6 holds + keep — but their COMPOSITION varies by lane (2026-07-07 war-road pass)**: each elite band carries ONE General (dodgeable when the band is ≥2 lanes), and one wide plain fight row per act hides a THIRD, optional war-road General — the StS elite-hunt trade (greedy routes break up to 3 Generals for 3 relics; `_war_road_ok` makes the acceptance loop reject lattices where the fork couldn't land). One Reliquary (R7) and one Arsenal (R13) and two musters (R4, R10) ride the longer road (the Reliquary is the fixed relic-bearing stop; the Arsenal pays Forge/potions/gold). An acceptance loop in `CampaignMapGenerator.generate_act` reseeds until the act has 24–36 sites and every route carries enough fights to open the lord gate. **Wayside halts** (`scenes/wayside.tscn`, `scripts/scenes/Wayside.gd`) are one-decision roadside verbs assigned at gen (`node.wayside_id` → `RunState.current_wayside_id`): drill_yard (push-your-luck +1/+1), standard_bearer (move a keyword between creatures), supply_cache (pick 1 of 3 war-material spoils — gift creature / next-fight boons / a commissioned card, never plain gold/heal). muster_scale was RETIRED 2026-07-02 (its sell-a-card verb moved into the Shop as the sutler's buy-back); the handler stays so old saves resolve, but the deal never deals it. Their permanent card changes ride the card-upgrade mod stack (`apply_wayside_upgrade`, paths `drill`/`grant_kw`/`strip_kw`) — mods compose Inscryption-style (a drilled creature can also carry a banner and be forged); the drill entry keeps a TOTAL stacks counter capped at `DRILL_MAX_STACKS`.

The map screen is two layers: **MapTerrain** (`scripts/scenes/MapTerrain.gd`) draws the static plate, and since 2026-06-29 it renders in **war-table mode** (`SIMPLE_BACKDROP := true`): nodes on a fixed left→right lane grid (camp 0.075·w → keep 0.80·w, `cy 0.535·h`, lane pitch `0.100·h` — tuned so the outer lanes clear the top cartouche and the sheet edge; the bottom legend band was RETIRED 2026-07-07 — unstruck tokens print their own engraved site names (SITE_LABEL in _draw_sites, waysides print their verb) and hover tooltips carry the deep intel), dead-straight roads, and a **generated deckled coastline** built per act around the node field (`_build_simple_coast`: convex hull over all stops + camp + Etna's foot, inflated 86px, noise-resampled — every stop is on land BY CONSTRUCTION). ### Card upgrade system

Slay-the-Spire-style **"+" upgrades**: every draftable card has one hand-crafted upgraded version. Rest sites offer the "Forge +" action — the player picks a card, sees a before/after preview, and confirms. No path picking, no random rolls. Camp also offers **Hold a Wake** (2026-07-04, only when the Roll of the Fallen has names): pick one fallen soldier; its shade (folded stats while the card still marches, printed stats if mustered out) opens the NEXT fight in front-left via `next_combat_gift_creature` — a real 3-way camp fork (heal / forge / wake), and since camp sits right before the keep, the wake usually arms the boss fight.

**Veterancy ladder** (solo campaign memory, `RunState.creature_kills` per deck_uid): 3 kills = epithet ("Pikeman the Grim"), 6 = +1/+1, **10 = the war school** — a modal at the top of the next player phase offers Armored / Swift / Thorns, written as a permanent `war_school` mod entry (Combat `_offer_war_school`; round-1 catch-up sweep covers thresholds crossed on a fight's last kill and pre-rung saves; headless sessions auto-pick the first school so probes/autorun never stall).

- Per-card upgrade deltas live in `CardDB.UPGRADES` (atk/hp/cost/value/keywords/sub-effect bumps, plus optional desc override). `CardDB.get_plus_upgrade(id)` returns the delta; `CardDB.is_upgradeable(id)` filters out curses.
- The upgrade is applied by `RunState._apply_upgrade` via the `"plus"` path → `_apply_plus_upgrade(data)` merges the delta into the card data and stamps `is_upgraded: true`.
- Custom-spell resolvers in `Combat.gd` read `dmg_bonus`, `slay_draw`, `extra_draw`, `extra_mana`, `ricochet_hits`, etc. from the merged card_data, so + versions actually hit harder / draw more / give more mana.
- A handful of creature passives (Royal Guard, Corpse Eater, Vengeance, Vampire Lord, Riteforge, Warchief) read `card_data.is_upgraded` directly and bump their tick value.
- Specialty upgrade paths — `butcher` (now granted by the War Chest's "Butcher's Kindness" opener), `mirror_twin` / `fortify_neg` (legacy — their events were cut in the 2026-07-03 pool remake; the arms stay so old saves fold) — keep their dedicated paths in `_apply_upgrade`. Events also write the wayside `grant_kw` path: the Old Drill Master (event id `the_lame_master`; renamed from "The Pensioned Master" in the 2026-07-18 prose pass) teaches a chosen creature Armored/Swift/Thorns permanently.

Mods are tracked in `RunState.card_upgrades` keyed by `deck_uid` — **each value is an ordered Array of mod entries (Inscryption stacking model)**: a card can be drilled, carry a transferred keyword, AND be forged; entries fold in the order earned. The "+" forge is the only once-per-card path — `has_upgrade_path(i, "plus")` is the forge filter; `is_card_upgraded(i)` now means "carries any mod"; the " +" name suffix marks the forged state only. `get_upgraded_card_data(uid)` returns the folded data. **Upgrades are applied at draw time in Combat** via the `deck_uid → card_data` lookup — drawing a card looks up its uid and uses the upgraded data dict. Legacy single-entry saves are shape-migrated (wrapped into arrays) on load.

The Whetstone relic upgrades the "Reforge" rest banner to forge **two** cards instead of one (once per act).

### Card2D (`scripts/Card2D.gd`)

PanelContainer-based card (~4,600 lines after retiring alternate renderers). `CreatureInstance` owns typed gameplay state and versioned save/network snapshots; Card2D is its input/render adapter. **The writ-kit painter classes (WritLeaf, InkCartouche, WaxSeal, StatCaret, ParchmentPlate, TallyMarks, EmptyPlateSigil, WritDetailDiamond, PolyBadge, StatGem) live in `scripts/ui/painters/`** (extracted 2026-07-14), preloaded as same-name consts so `Card2D.WaxSeal`-style references still work; new diegetic painters belong there, not inline. Supports creatures (ATK/HP display) and spells (SPELL label, no stats). Drag from hand above play threshold to play. Battlefield creatures show floop indicator. `take_damage()` handles Armored and Last Stand. `temp_atk_buff` for this-turn buffs; `persistent_atk_buff` + `persistent_atk_buff_rounds` for multi-round buffs (Butcher's Cleaver). `effective_atk()` is the canonical "what's my real ATK right now" — always prefer it over raw `current_atk + temp_atk_buff` reads.

## Gotchas

- Combat.gd builds all HUD in code, not in the scene editor
- Spell targeting uses `_input()` override, not the card drag system
- `KeywordEffects` accesses combat state via the ctx (Combat instance) directly — Combat is always the ctx
- Enemy deck is `Array[Dictionary]` (card data dicts from EncounterDB), not card IDs. Legacy fallback builds random dicts from CardDB
- Token creatures have synthetic card_data created in `summon_token()`, not from CardDB
- MapView, Shop, Rest, Event, and the starting-relic-pick screen all build UI programmatically; their `.tscn` files only have Background + script (map.tscn has no Background at all — the MapTerrain plate is the background)
- `current_atk + temp_atk_buff` should never be read directly — always go through `card.effective_atk()` so `persistent_atk_buff` (Butcher's Cleaver) is included
- Reactive `double_on_death` re-runs the dying enemy's on_death effect directly via `KeywordEffects._run_on_death(...)` to avoid recursion through `dispatch_on_death → _dispatch_reactive`
- `_short_pause(duration)` is a real timer-based pause (uses `create_timer().timeout`) — the parameter is honored, not ignored
- **Combat beat constants live on the shared Motion clock** (`scripts/ui/Motion.gd`, 2026-07-16): Combat's `LUNGE_APEX`/`POST_HIT_BEAT`/`HITSTOP_BEAT` alias `Motion.*`, and Card2D's lunge/recoil/death tweens build from the same constants via `Motion.time()` (anim-speed scaling). New combat-visible tween durations should be wrapped in `Motion.time()`; shell/kit animations stay unscaled by policy. `LUNGE_APEX` is DERIVED (anticipation + strike) — never hardcode an impact delay. Screen shake is GameTheme's trauma service (`set_shake_target`/`add_trauma`; `Combat.screen_shake` delegates, mapping legacy 4–28 px magnitudes) — impulses compound; don't re-add per-call jitter tweens. Verify: `tools/_probe_anim_clock.gd`. Audit + remaining plan: `docs/ANIMATION_AUDIT_20260716.md`.
- **Motion grammar + Reduce Motion contract** (2026-07-16): `Motion.ANTICIPATE/PUNCH/SETTLE/SETTLE_SLOW/EXIT/EXIT_SLOW/LOOP` are the named beat tokens (SINE-out / QUAD-out / BACK-out / EASE_IN / SINE loop respectively); prefer a kit verb — `deal_in`, `hover_lift` (opt. `target`/`raise_z`), `punch` (the juice_up impact, keyed kill-before-restart), `claim_pop`, `fade_exit`, `pocket_away`, `tick_number`, `write_on` (typewriter), `ken_burns`, `card_reveal` (the shared slate entrance, rarity shine + companion button included), `ring_pulse`, `rarity_reveal`, `forge_strike`, `reroll_sweep`, `pulse_label` — over hand-rolling a tween. **The verbs live as statics in `scripts/ui/Motion.gd` (extracted 2026-07-16, R6); GameTheme keeps same-name delegators** so `GameTheme.deal_in(...)` call sites still work — new verbs go in Motion.gd (+ a GameTheme delegator only if shell code will call it). Every animation is either **informational** (carries game state: lunge/recoil, mortal slump, floating numbers, threat/danger overlays, log chips — always plays; persistent overlays hold steady instead of pulsing under Reduce Motion) or **decorative** (idle bob, ambient FX, entrances, bursts, reveals, hover lifts, Ken Burns — gated OFF; the kit verbs gate themselves, incl. snapping to end-state where content must still land). - **Card2D `rotation` has ONE writer; stat feedback has ONE funnel** (2026-07-16, C1/C2): `Card2D._process` is the card-LEAN driver and nothing else — armed only while a hand card is dragged (leans into cursor velocity, ±0.35 rad) or hovered (tilts toward the cursor, ±0.10 rad; this REPLACED the old straighten-to-0 hover tween), `set_process(false)` at `_ready`, self-disarming. ### Card text positioning (v3 layout — superseded)

Text on cards (cost, name, type, description, ATK, HP, FLOOP) is positioned by **pixel-measured POINT_* constants** in [scripts/Card2D.gd](scripts/Card2D.gd), each pointing at the center of a painted region in the 300×400 source frame texture.

**To tune or re-derive these positions, run:**

```
python tools/measure_frame.py
```

It scans `assets/frames/frame_creature_common.png` pixel-by-pixel — looking for the red orb's bright-red core, the banner's dark-gray interior, the gold divider scroll, the tan parchment well, etc. — and prints a copy-pasteable block of `POINT_* := Vector2(...)` constants with the bbox center of each region. Replace the matching constants in `Card2D._build_full_layout_v3`'s header.

**Eyeballing positions does not work.** Earlier attempts had `POINT_NAME` 20px above the actual painted banner because the banner's gold trim above the dark interior visually fooled the measurement. The script reads pixel values directly, so it can't be fooled the same way.

**Layout uses point-anchored centering, not anchor rects.** The helper `_center_at_point(label, point, size)` anchors a label to a single point with symmetric `offset_left/right/top/bottom = ±size/2`. This avoids two Godot quirks: (1) `Label.vertical_alignment = CENTER` misaligns when the rect is smaller than the font's line box; (2) asymmetric anchor rects make `horizontal_alignment = CENTER` compute the visual midpoint inconsistently. POINT_* is "where the center goes," SIZE_* is "how much room the label gets" — keep SIZE_* generous (≥36px tall) so Godot's centering works.

**Font setup** lives in [scripts/GameTheme.gd](scripts/GameTheme.gd) `_load_assets()`. Three fonts:
- `font_display` — Cinzel Variable wrapped in FontVariation with `wght: 600` (SemiBold) for names, type, FLOOP
- `font_stat` — same Cinzel but `wght: 800` (Black) for cost / ATK / HP numerals — matches AAA card-game stat-orb conventions (Hearthstone, MtG Arena)
- `font_body` — Nunito Regular for descriptions

Both Cinzel variations set `spacing_bottom = -3` to optically center caps-only text (caps don't use descender space, so geometric center renders ~1.5px high). If text still looks high, increase the negative value; if low, push toward 0.
