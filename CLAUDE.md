## Project overview

"Burning Meadow" — a lane combat roguelike deckbuilder built in Godot 4.6 (gl_compatibility renderer, 2D). Inspired by Card Wars (combat) and Slay the Spire (roguelike structure). 4 lanes × 2 rows per side (front/back), simultaneous combat with Swift pre-phase, floop, spells. 3 acts with branching maps, shop/rest/event nodes, premade encounter lineups with fight passives.

## Running the project

Open in Godot 4.6+ and press F5. Main scene is `scenes/main_menu.tscn`. There is no build step or formal unit-test suite; `tools/_probe_*.gd` scripts are the headless regression harness.

**Compile gate — finish every script edit with this one command:**

```
Godot_v4.6.x-stable_win64_console.exe --headless --path "D:\Godot" res://tools/_probe_parsecheck.tscn
```

`_probe_parsecheck` runs as a SCENE (so autoload names resolve) and does a real `ResourceLoader.load()` + `GDScript.reload(true)` over every script under `scripts/` (~113). A script that does not compile takes the WHOLE GAME down, so nothing less is worth trusting. It is one of the three probes in `tools/run_safe_probes.ps1` (with `copy_lint` and `event_art`) — the CI-safe set to run before any commit.

**THE UI / FEEL GATES — `tools/run_ui_gates.ps1` (2026-09-02).** A second, SLOWER runner holding the ten pixel-and-layout gates, kept out of `run_safe_probes` for two reasons: they run for minutes (that set is the seconds-long pre-commit loop), and **three of them measure PIXELS and cannot run `--headless`** — a "CI-safe" set that silently needs a display is not CI-safe. Pass `-SkipWindowed` to drop exactly those three on a headless box. Contents: `occlusion` · `cfg_diff` · `input_reach` · `alignment` · `uiscale` · `popup_layering` · `spring` (headless) and `boil` · `smear` · `modal_scrim` (windowed). It tolerates a short, named list of Godot's exit-time noise (`resources still in use at exit`, `ObjectDB instances leaked at exit`) because every gate here builds scenes and would otherwise fail for something none of them did — anything not on that list still fails the run. **Run it after any change to Card2D, Combat's HUD/modals, Event's layout, or `scripts/ui/`.**

**`uiscale` is CLASS C32 (2026-09-03), and it is the only gate that changes the VIEWPORT.** Every other gate runs at the 1600×900 project canvas — but `SettingsOverlay._add_ui_scale_row` offers the player **UI Scale 60–100%**, which sets `Window.content_scale_factor`, and under `canvas_items` stretch that DIVIDES the logical canvas: at 60% the UI lays itself out on **2667×1500**. Anything placed from a CONSTANT is therefore wrong at four of the five settings offered, and nothing could see it. The oracle is DIFFERENTIAL so it needs no taste — it never asks whether a screen *should* fill the canvas (some are a small centred dialog), only whether it covers the SAME FRACTION at every scale; a drop is the finding. It found `GameTheme._make_decorative_frame` placing its corners from `ProjectSettings` — which an earlier pass had already moved off a hardcoded 1600×900, with a comment warning the edges would "float inward", not noticing that **ProjectSettings is STATIC and the runtime canvas is not**. At 60% the frame drew 1876×877 inside a 2667×1500 canvas, so the border sat in the top-left corner on every screen with atmosphere; it is now built on ANCHORS and is correct at any scale with no resize handler. **Sensitivity limit worth knowing:** the oracle measures the ink's BOUNDING BOX, so it catches a layout pinned WHOLESALE, not one piece of it — shortening a single rule does not fire.

**`alignment` is CLASS C30 (2026-09-03), and it is the only gate here that judges a control against the ones laid out BESIDE it.** Every other layout gate judges a control against ITSELF — does the text fit its box, is anything painted over it, can the click reach it — and a control can pass all of them and still be the thing a player points at and calls wrong: it fits, it is uncovered, it clicks, and it sits four pixels left of the column it belongs to. "Off centre" is a matter of taste judged one rect at a time, so the pass judges RELATIONALLY: the odd one out of a peer group, a near miss in the 1–8px band (alignment is binary — zero is intent and forty is intent, three is a slip), a contradicted `CenterContainer`, a one-sided invisible gutter, and worded controls compared **by their INK across the Button/Label divide** (`Button.flat = true` stops the box being DRAWN, not its margins being SPENT). **THE RULE THAT MAKES IT CORRECT: a group declares its own alignment, and only that declaration is judged** — judging CENTRE in a left-flush column reported a deliberately short chip row as 102px off, and judging EDGES in a centred row reported the map HUD's purse coin (50px, deliberately sharing the 40px row's mid-line) as a 5px near-miss top AND bottom, those two deviations being equal, opposite, and the signature of a correctly centred object. It excludes anything under a Card2D and any ROTATED or SCALED control, because a scaled control is mid-animation and its axis-aligned rect is not the rect the layout produced (the menu title breathes on a looping 1.0→1.025 tween). It also gates one HELPER CONTRACT — `_make_ornament_row(width)` must draw `width` — because a shared builder wrong the SAME way at every call site is invisible to a relational oracle. See [`docs/BUG_SWEEP_METHOD_20260829.md`](docs/BUG_SWEEP_METHOD_20260829.md) §C30 for the five defects it found and for the ink oracle that shipped FAKE (it demanded a majority, and the title column legitimately has two rails).

**THE SYSTEMATIC SWEEP (2026-08-29) — [`docs/BUG_SWEEP_METHOD_20260829.md`](docs/BUG_SWEEP_METHOD_20260829.md).** Ad-hoc hunting in skirmish found 13 bugs, then 1, then 0 — that curve is why the hunt was replaced by a method: nine classes organised by HOW A BUG HIDES, since that decides the technique that finds it, each with an inventory and a stopping condition. Three standing gates came out of it, all whole-codebase and all cheap: **`tools/_probe_reachability.gd`** (C1 — every dispatch table diffed against its emitters in BOTH directions, plus dangling ids across every DB; this is the class that let six dead minigames survive for months), **`tools/_probe_guard_audit.gd`** (C3 — 1,204 functions scanned for a predicate applied in one sibling and forgotten in another, the shape of THREE of this session's bugs), and **`tools/_probe_campaign_walk.gd`** (C5/C7 — the routing twins, generator coverage, and camp→boss walkability; `_probe_autorun` soaks combat, nothing soaked the RUN). Two more followed: **`tools/_probe_persistence.gd`** (C8 — every `CreatureInstance` field enumerated from `get_property_list()` and round-tripped through both snapshot formats, so the next `effect_immune` fails a gate instead of needing a human; plus same-seed run reproduction) and **`tools/_probe_upgrade_merge.gd`** (C2/C9 — every `CardDB.UPGRADES` key diffed against the key set `_apply_plus_upgrade` actually consumes, extracted from that function's own source; an unmerged key is the Counterorders bug, where the "+" advertised 9 damage and dealt 6). Both orphan gates carry WAIVER dictionaries: an entry there is visible debt, not absolution. Two further classes came from the published test-design literature rather than from generalising found bugs, and both cover ground the first nine did not. **`tools/_probe_metamorphic.gd`** (C10) answers the ORACLE PROBLEM that stopped the text-vs-data pass dead: instead of comparing a clash to a known-correct output — which would need an oracle the engine itself is — it asserts RELATIONS between two related runs. A board and its MIRROR must resolve identically (any side-biased branch breaks it), one snapshot applied twice must equal applied once, and damage must be non-decreasing in attack. Each mirror fixture carries a vacuity check, because a symmetry test passes trivially if the transform was a no-op. **`tools/_probe_interruption.gd`** (C11) is Lewis et al.'s TEMPORAL class — invalid state / interrupted event / action not performed — which is where this codebase actually breaks: three bugs this session were one shape each, and the 2026-08-07 audit's "await-during-live-button" class was a fourth. It interrupts on purpose: the same action fired twice in one frame (the double-click that produced four latch bugs across MainMenu/Collection/Credits/MapView), the scene freed while a coroutine is parked mid-clash, and peer-loss delivered at three phases. Two more test the things the others cannot. **`tools/run_mutation_check.sh`** (C12) tests the TESTS: nine faults, each re-creating a bug actually fixed, are injected into production code and the gate that should notice is required to FAIL (files byte-copied, restore checksum-verified). It found TWO FAKE GATES on its first run — the soak stayed green with `_is_sealed()` forced false, because it was proving "cards can be played" rather than "Sealed Orders ran", and the boundary probe could not see its own founding defect since scroll content is exempt from the off-canvas rule. Both fixed; score 9/9. **`tools/_probe_fuzz_wire.gd`** (C13) is the only pass that feeds the game input it did not write itself, and it found a REMOTE ABORT VECTOR: every intent handler read peer fields with a bare `int(...)`, which THROWS on a Dictionary or Array and aborts the function where it stands, so `{"t":"play_creature","lane":{}}` stopped a host handler half-finished. `NetProtocol` cannot catch that — the envelope contract is about SHAPE and that payload is well-shaped — so the coercion was made total (`_wire_int`/`_wire_str`, all 44 peer-supplied reads, host and client). **`tools/_probe_invariants.gd`** (C14) is the only pass that watches the game WHILE IT MOVES — every other one inspects a settled state, and plenty of defects exist only in transit. It asserts always-true properties on EVERY FRAME of a driven match (one body per slot, no dead body standing outside the deferred-death window, no freed node in the entity registry, Command never negative, no duplicate uid in hand), and it found one immediately: **`Combat.gd` never called `unregister_entity` anywhere**, so every creature that died on the host stayed in `NetMatch.entities` pointing at a freed node — stale on 26,033 frames of one match, and invisible to every end-state check because the registry is cleared wholesale at `_enter_combat_local`. Its own first run was a FALSE PASS worth remembering: naming `Card2D` at parse time in a `--script` probe drags Card2D.gd into the pre-autoload compile, so `card_2d.tscn` instantiates as a bare `PanelContainer` and the whole match runs scriptless while the audit reports green — load such classes at RUNTIME. **`tools/_probe_pairwise.gd`** (C16) is the first pass to test the SPACE rather than the axes: every gate before it varies one parameter with the rest held still, so a defect living only where two features MEET is invisible. It builds an ALL-PAIRS covering array over {style, first, best_of, relic, potion} — 35 combinations covering all 119 pairs out of a 280-match cross product, with the coverage VERIFIED before the matches run — then adds the part with teeth: a (relic × style) CELL MATRIX requiring each relic's delta from the no-relic baseline (max Command, opening hand) to be IDENTICAL in both battle styles. Nothing about what a relic ought to do is hardcoded, so it survives any retune; a vacuity guard requires the matrix to observe a real effect first (4 relics move the opening today). **`tools/run_two_process_match.sh`** (C17) CLOSES THE ONE INFRASTRUCTURE GAP the method doc has listed since it was written: two real Godot processes playing a match over a real ENet socket, each writing a digest the driver DIFFS. Everything else runs host and client in one process, where the wire is a function call and a payload handed across is THE SAME OBJECT — so serialisation, real delivery ordering, and the earned three-term handshake are reachable nowhere else. Its own build produced three traps worth keeping: **the driving node must not be `current_scene`** (the match path ends in `change_scene_to_file`, which frees it — and reparenting is a no-op because the main scene is already on root, so hand the work to a second node beside `current_scene`); **both peers must stop on a SHARED clock** (stopping on local turn counts made whichever finished first tear the socket down, freezing the other mid-match and reading as a board desync that was two snapshots of different instants); and **a sealed stand-in is not a desync** — `_sealed_pending` holds local previews at `entity_id == -1` until the reveal, so the digest distinguishes a TRACKED stand-in from an ORPHANED one (an untracked `-1` body IS a real defect, since the host addresses every net beat by entity id and could never reach it). Verified by mutant: `MAX_ARRAY_ITEMS` 256→4 overruns the clash-reel envelope and the gate catches it while every other net gate stays green. **`tools/_probe_silent_refusal.gd`** (C18) is the only pass aimed at code that is CORRECT and a bug anyway: a control that declines and says nothing — no message, no sound, no recoil — is a dead button to the player, has no state to assert against, and was the shape of the two worst skirmish bugs in this sweep. It reads FEEDBACK ASYMMETRY (only functions that already speak on some refusal; a silent sibling there is the finding) and ignores any branch that CALLS something, since a dispatch or a visible snap-back is the opposite of the defect. It found the discard-mark right-click refusing in silence under the exact rules the left-drag explains, and a potion belt that is never disabled (so a mid-clash click was a dead button). Waivers are keyed `function::guard-needle`; one of them is a STANDING TRAP — the combat belt draws whatever the slot holds without filtering `usable_in`, so the first map-only potion added to PotionDB renders a lit, clickable, completely dead slot. **`tools/_probe_await_audit.gd`** (C19) is the exhaustive static complement to C11: `await` suspends a function and lets the game run, so a node it holds may be FREED on resume — and a freed-object write silently ABORTS the function, so the symptom is an animation that stops halfway with NO error printed. 594 awaits is not an eyeball pass. Two probe rules earn their keep, both language facts: a MULTI-LINE await is one statement (its args evaluate BEFORE the suspension, so a continuation-line mention is a pre-await use — missing this flagged the correctly-guarded `_ordered_strike`), and an await nested in a branch does NOT dominate code at a shallower indent (`_sniper_fire`'s sits in an `if` that returns). It found the COIN TOSS on both peers: `layer` is a child of the combat scene, peer-loss arms a scene change 2s out, so a drop mid-toss frees it and leaves the winner with a coin and no choice buttons. Waivers are keyed `function::variable`; the recurring reason is GUARD-BY-OWNER (validating the container, not the leaf), which is sound and not safely automatable. **`tools/_probe_content_census.gd`** (C20) asks the question C1 cannot: C1 is STATIC (is this id dispatched), this is EMPIRICAL — content can be perfectly wired and still never appear because an act, a rarity band, a deck predicate or a pool filter never lets the roll through. It rolls the SHIPPED generators 12,000× per context and tallies what falls out (cards 193/193, relics 70/70+9/9+6/6, encounters 48/48). ITS OWN THREE BUGS ARE THE LESSON, each having produced a confident wrong report: the card/relic rolls return an Array SLATE not one id (read as a string, it announced 193 unreachable cards — so it now refuses to print a "never appeared" list when its generator produced ZERO); encounter types are `combat`/`elite`/`boss` and a draft querying `"normal"` built its ELIGIBLE set from the SAME wrong query, so it agreed with itself and PASSED at 18-of-18 against 55 authored lineups; and rolling relics with an empty `hero_id` made `filter_pool_for_run` drop every `restricted_to` relic and call 32 reachable ones dead (it now rolls per hero and unions, and excludes `retired`). Finally, A GATE IS ONLY CORRECT IF IT CAN OPEN — "deck-gated" and "dead content" are the same observation, so the pass builds the deck each potion gate asks for and PROVES it becomes rollable. **`tools/run_chaos_save.sh`** (C21) injects faults into the ENVIRONMENT rather than the code: 14 corruptions (truncated mid-write, numbers-as-strings, empty object, NUL bytes, trailing garbage) across run/meta/settings saves, plus backup recovery. This is the class a player calls "my run is gone" and nothing else here pointed at it — C8 round-trips WELL-FORMED saves and never asks what happens when the file is wrong. The save system passes all 42: the `.bak` fallback recovers the REAL save and, with both copies wrecked, `load_run()` reports failure instead of proceeding on an empty run. It writes garbage into `user://`, so the driver moves APPDATA to a temp dir (GODOT_USER_HOME is a no-op on Windows) and the probe REFUSES to run without that isolation. Its own three harness bugs all produced the SAME wrong answer — 14 of 14 "unusable state" — and a uniform failure across every case is almost always a broken oracle: a predicate naming `player_hp` (the field is `hero_hp`), a typed `Array[String]` compared against `null` (an invalid operand that ABORTS the lambda rather than returning false), and multi-line lambdas written inline in an argument list, which parse unreliably — bind each to a local first. **`tools/_probe_invariant_mining.gd`** (C22) is the only pass that does not test a property a human chose: it MINES them. Phase 1 records every numeric field across seeds/styles and keeps the bounds plus pairwise `<=` relations that always held; phase 2 replays them against unseen seeds and the other battle style. A break is an OVERFIT or a real rule violated, and the report splits them because a widened RANGE is the expected cost of a finite sample while a broken RELATION was a structural claim. Survivors are ranked by INFORMATION — only relations whose two fields have OVERLAPPING ranges are interesting, since `hand_size <= player_hp` is arithmetic (2..5 vs 15..30), not a rule. It rediscovered **`bodies_foe <= entities`** unaided — every enemy body must be in the entity registry, which is exactly the invariant whose violation C14 caught when `Combat.gd` never called `unregister_entity`. **`tools/_probe_dominance.gd`** (C23) is the only pass that compares two pieces of content TO EACH OTHER (dominance by the rarity curve; every "+" forge strictly better than its base). It found ZERO defects, and its VALUE IS THE FALSE POSITIVES, which are facts about this codebase: **a forged bonus is driven from FOUR places** — a merged UPGRADES delta, an `is_upgraded` read in the resolver (`_apply_armament` grants hooked_pike +1 ATK, tower_shield +2 HP, grave_bell/witchbrand +1/+1, forked_spear +2 ATK, repeating_arbalest +2 HP), a local `is_plus` in a custom-spell resolver (`long_roll` pays 7/16 forged vs 5/12 base entirely that way), and a resolver keyed on `spell.id` NOT the card id (Lock Shields resolves under "testudo", Countermarch under "baggage_train"). So a desc-only UPGRADES entry is NOT evidence of an inert "+". Also: abilities must be compared by PAYLOAD not by key (every spell carries a `spell` key and 0/0 stats, so key-comparison made the cheapest spell dominate the entire pool — 1,077 false hits); **Doom is a DOWNSIDE**, not a bonus keyword; and **tribe is not cosmetic** — a Dead 2/2 and a Beast 4/2 at one cost are not substitutes. **`tools/_probe_runaway.gd`** (C24) is the only pass that plays RANDOM decks drawn from the whole skirmish pool (145 distinct cards over 10 matches) rather than the same twenty every time — cards that never otherwise share a board get to meet, which is the only way an emergent interaction shows up. Its oracle is objective, so no balance judgement is needed: a stat driven without bound is an unbounded combo, and a match that cannot end is a softlock. Clean. TWO ORACLE LESSONS from building it: **a corpse below zero HP is legitimate mid-clash** (`Card2D.defer_deaths` holds dead bodies standing so a simultaneous trade resolves both ways — sampling inside that window reported nine healthy matches as broken), and **an "absurdly large number" ceiling is the WRONG oracle for unboundedness** — forcing Command to accumulate every round only reached 18 before matches ended, so a ceiling of 25 stayed green while the resource was genuinely unbounded; deriving the bound from the CONTRACT instead (`player_max_mana + MAX_BANKED_MANA`, what `_start_round` actually promises) catches it on the FIRST round at Command 6. **`tools/_probe_golden.gd`** (C25) is the standing regression net — approval testing for a codebase with no unit tests and one 20,000-line module: it records what a fixed set of seeded matches DOES into `tools/golden/combat_digests.json` (re-record deliberately with `-- --bless`) so any future diff is the alarm. It certifies nothing about correctness, and it proved one thing nothing else had: **a whole MATCH is deterministic** — same seed, both battle styles, identical digests within a process AND across separate processes (C8 covers run GENERATION only, so a divergence here would have meant a gameplay decision reading unseeded global RNG). ITS LESSON IS ABOUT COVERAGE and came from a mutant that ESCAPED: halving `MAX_BANKED_MANA` changed no digest, because the driver spent everything each turn and nothing ever banked — the constant was never load-bearing in any scenario, while a card-stat mutant fired instantly, proving the digest itself was sensitive. Adding a FRUGAL scenario that underspends (so Command carries to `mana=5/3`) made it fire. **A golden master pins only the behaviour its scenarios exercise, and a narrow corpus is worse than none because it reads as coverage.** **`tools/_probe_coverage.gd`** (C26) is the only pass that measures the SUITE rather than the game: which behaviours has any of it ever actually executed? That became urgent in C25, where a mutant escaped the golden corpus because no scenario banked Command — every gate is vacuous over code it never runs. GDScript has no line-coverage tool, so it measures BEHAVIOURAL coverage (for a card game the dispatch surface IS the content): 14 random-deck matches reach 114/153 skirmish cards, 39/52 spell effect types, 15/21 on-enter, 8/10 on-death, 19/22 keywords, with 29 further spell types campaign-only and outside its reach. **READ THE SCOPE** — that is ONE driver over 14 matches, not the whole suite; a card absent may simply not have been drawn, and `_probe_autorun` likely covers some campaign resolvers, so the honest claim is a FLOOR not a verdict. Its own bug was THE DENOMINATOR for the third time in the sweep: building the universe from the whole CARD_POOL counted `draftable: false` hero-retinue customs as blind spots of a SKIRMISH driver and reported 48% where the scope-matched figure is 75%. **A coverage number whose denominator does not match what the driver can reach is not a measurement.** Read the doc's "honest limits" section before assuming a class is covered — design/balance, true two-peer faults and emergent interactions are explicitly out of reach.

**parsecheck's ONE blind spot (2026-08-29): it runs as a SCENE, so autoload NAMES resolve.** That is what makes it trustworthy for everything Combat-shaped — and it means it cannot see a compile error that only happens in a `--script` context. A plain `RefCounted` that tools `preload` (e.g. `scripts/net/NetPlayerState.gd`) has its dependencies compiled BEFORE the autoloads register, so a bare `RelicDB` / `RunState` identifier inside one is a hard compile error there while parsecheck stays green — and it takes the whole depending probe down with it (`_probe_skirmish_combat` failed to load outright). **`preload()`ing the autoload's script instead is worse, not better**: it drags that script into the same early compile, where ITS own autoload reference fails, and the failure then poisons the real autoload for the entire run (every call site reporting "Nonexistent function 'get_relic' in base 'Node'"). Resolve through the tree at CALL time (`Engine.get_main_loop().root.get_node_or_null("RelicDB")`) with an explicit fallback. After touching any non-Node helper script, run one `--script` probe as well as parsecheck.

Two cheaper recipes exist and BOTH have shipped false passes; use them for a fast inner loop only, never as the final word:
- `--check-only --script res://scripts/scenes/Combat.gd` catches TOKEN/syntax errors only ("Identifier not found: <autoload>" is a false positive here — autoloads aren't loaded). **2026-07-28: it reported a clean Combat.gd that could not be `load()`ed at all** — a stray `var` left in the wrong `match` arm is a SCOPE error, resolved in a later pass than this runs. Note also that a syntax error MASKS semantic ones, so fixing a mangled token can reveal a second break further up the file.
- `--editor --quit-after 5 res://scenes/combat.tscn` force-compiles Combat.gd/Card2D.gd in the headless editor. **CAUTION (2026-07-17): it can silently pass on a broken script when the editor serves a cached compile.**

## Architecture

### Scene flow

`MainMenu → THE MUSTER (4 steps: I host · II banner · III terms · IV review) → MapView → Combat/Shop/Rest/Event/Recruit/Treasure/Wayside → Reward → MapView → ... → Combat (boss) → GameOver`

**The run opening is `MainMenu._show_muster_step(step)`, FOUR screens ordered by DEPENDENCY** (`_muster_step = clampi(step, 1, 4)`; a fourth step, **IV · REVIEW**, was added after the 2026-07-31 split and is now the ONLY step carrying START RUN — corrected 2026-08-25, this section had said three) (split 2026-07-31 — as one screen it asked for an identity, a build modifier, an economy pick and three session settings all drawn as equals, and read as overwhelming): the banner's card joins the host's opener, and the terms are weighed against the column those two produced. All step state lives on the object — `_muster_seed_text` and `_daily_pick` especially, because the seed field is built on step III alone while `_pending_run_seed()` is read by every step — so stepping is free and `start_new_run` is still called exactly ONCE, at START RUN (the button read TAKE THE FIELD before the 2026-08-06 plain-language pass). `_refresh_muster_deals` deals the slate as DATA at entry and step III merely paints it (`_begin_run_with` resolves the committed term out of `_muster_writ_slate` and can be reached without step III ever being built). See [`docs/RUN_OPENING_REDESIGN_20260728.md`](docs/RUN_OPENING_REDESIGN_20260728.md) §8; gates `tools/_probe_muster.gd` + `tools/_probe_menu.gd` + `tools/_shot_runstart.tscn`.

**THE MUSTER OFFERS THREE DECISIONS AND DEMANDS NONE (2026-08-01).** Every survey game hands a first-time player exactly ONE decision before gameplay (Slay the Spire: character; Balatro: deck; Hades: weapon) and staggers the rest; this asked for four. It is not fixed by deleting a step but by making the walk optional — **every rail chip is a live button, forward as well as back** (`_make_muster_step_rail`: `disabled = is_here`, and a step ahead of you stays DIM but answers a click), so a returning player reaches START RUN in two clicks while the guided path is unchanged. Safe by construction: nothing commits until that button, and `_show_hero_select` has seeded every default before step I is drawn. Same principle retires the difficulty stepper — **the ascension `−`/`+` pair is not built at all below the first win** (`_build_muster_settings`), because a permanently disabled control beside live build offers is the one pattern no surveyed roguelike ships; `_update_asc_rules_text` still prints the promise, and every `_asc_label` consumer already null-guards. Other fixes from the same pass, each now gated: THE COLUMN is drawn on step III too (three of the four ROLL terms name specific cards, and the deck was two screens back) with the max-HP denominator the PACT prices against; **THE ARSENAL previews the three relics it will actually offer** (`_writ_arsenal_preview`, reproducing `_pick_blessing`'s roll — `_muster_signature_relic` is the ONE writer of "which relic is already held" so the preview cannot drift from the deal); the PACT is dealt into the slot BESIDE its twin and carries no numeral; and the six banner cards got art aliases (they were the only blank cards in any opener, on the one screen whose whole claim is "your colours add THIS card").

**PLAY AGAIN (the rematch) goes through THE MUSTER, and must.** `_start_rematch` used to call `_begin_run_with` directly, skipping the only two things `_show_hero_select` does that a run cannot start without: it rolls `_muster_random_seed` (whose declaration default is 1 and which is randomised nowhere else — so **every rematch on every profile ran seed 1**, the same act 1 map and rival deal forever) and it deals `_muster_writ_slate` (so `chosen` came back empty and the rematch **silently forfeited the whole terms step**). It now restores the picks into `_muster_setup_preset` and calls `_show_hero_select(3)`, landing on THE TERMS one click from the field. `_probe_muster` asserts `_begin_run_with` has exactly one call site.

Scene transitions use `get_tree().change_scene_to_file()`. Each scene is a `.tscn` in `scenes/` with a matching script in `scripts/scenes/`. The whole run-opening flow runs from MainMenu before the first map appears, building UI programmatically over the menu background. **THE TERMS is dealt by `scripts/data/WritDB.gd`** — one tile from each of four fixed ROLE slots (I·ROLL the deck / II·ARSENAL choose-1-of-3 relics / III·PURSE the road / IV·PACT the price), so the player is never asked "which currency is worth most?" but "which axis of my run do I want moved?". Curses, boss relics, lump sums and SKIP are all permanently banned from the opening, each for an audited reason recorded in WritDB's header. **The three FREE tiles must stand on three DIFFERENT axes** — the pact doubles one by construction, so a fourth collision makes the row unreadable; THE PURSE was quietly a second ROLL (it granted `collectors_tome` and `whetstone`, both deck power) until 2026-08-01 and is now four road verbs, one each: BUY · SELL · EARN · MEND. Every pact must buy 1.00–2.00 "forges" over its own free twin (the road already prices one forge = two potions = ~90 gold = one common relic, via `Treasure._run_arsenal` and `Shop`), because the old spread ran 0.75–3.5 for one fixed price and made the loud tile dominated on half the deals and automatic on the other half. Gate: `tools/_probe_terms.tscn` reads the four dealt descs the way a player does and audits every granted relic against **RelicDB's own desc**, so the slot label cannot be made true again by rewording a tile. The menu column itself is 7 items max (CONTINUE / NEW RUN / SKIRMISH / COLLECTION / HOW TO PLAY / SETTINGS / QUIT, + LOAD GAME only when 2+ slots are filled); daily run and custom seed live inside run setup, not the column. GameOver's PLAY AGAIN button sets `RunState.rematch_request` and MainMenu consumes it on ready, opening THE MUSTER on step III (THE TERMS) with the same hero/banner/doctrine/ascension already restored — step III carries no commit button since REVIEW was added, so a rematch is the TERMS chip plus START RUN, i.e. two clicks (`_start_rematch`'s own comment still says one; it predates step IV).

Card upgrades are tracked by `deck_uid`.
- **HeroDB** (`scripts/data/HeroDB.gd`) — 5 playable heroes (Raider/Stalwart/Acolyte/Pyromancer/Kindler). Each entry has `deck` (10-card list of CardDB ids) and `relic` (id of a `tier:"starting"` RelicDB entry). Picked at the start of every run from MainMenu — replaces the old "pick 1 of 3 starting relics" screen. **The starter contract (2026-07-06 progression pass): hero decks use ONLY starter-rarity cards** (the original 8 + the levy set Outrider/Palisade/Mourner/Spark; Kindler's plain doom commons are the sanctioned exception) — never seed a hero deck with pool commons/uncommons, that's what flattened the run's power curve. Drafted cards must always outrank the opener. Generals additionally offer a chosen "+" forge on the Reward screen (The General's Forge), and Recruit slates richen gently by act (65/30/5 → 55/38/7 → 45/42/13 c/u/r; flattened 2026-07-16 — commons stay the majority of offers every act, rares stay events; late-run power comes from c4+ pieces/tribes/forges, not rarity inflation. Same pass: 10 tribe-glue uncommons demoted to common and 6 vanilla commons added, one per tribe — see CardDB's rarity-floor block). **Cross-run muster unlocks (2026-07-04, options not stats)**: `relic_alt` (choice of signature relic, unlocked by the hero's first win) and `deck_alt` {name, tagline, deck} (alternate 10-card start, a 2-3 card swap on the default; unlocked by a win at Ascension 4+). The run-setup detail pane shows them as toggles (locked = dim hint lines); MainMenu hands the picks to `RunState.start_new_run` via `pending_signature_relic` / `pending_deck_variant` (consumed + cleared there). PLAY AGAIN rematches use defaults. **THE HERO RETINUES (2026-07-28) — low-duplicate openers.** The complaint was "you have 50 of the same card". Every deck went from 4–6 uniques (2 copies each) to **9 uniques, max 2 copies**, built from ~20 new `rarity:"starter", draftable:false` cards in CardDB's "Hero retinues" block, so each hero now opens on a legible verb rather than a pile: Raider = mobility (relocate → Swift), Stalwart = adjacency/repair (`formation`), Acolyte = death bequests, Pyromancer = spell sequencing (differently-named casts), Kindler = Doom timers. Each hero also carries **two doctrine relics** (signature + `relic_alt`), all `tier:"starting"` with `campaign_only`/`restricted_to`. **Relic `effect` and `hooks` strings are DOCUMENTATION ONLY — there is no hook dispatcher; every relic is an inline `if _has_relic("<id>")` at the beat that owns it.** Grepping the `effect` id will make a wired relic look unwired. `restricted_to` IS enforced, but from *inside* RelicDB (`is_restricted_to_other_hero` → `filter_pool_for_run`), so it also escapes a naive grep; `campaign_only` is decorative — `tier:"starting"` is in no roll pool and both skirmish pools are explicit allow-lists. The 13 per-round latches these use are declared together in Combat.gd and reset in one block in `_start_round()`, which is the shared solo+skirmish round-open chokepoint. Verify: **`tools/_probe_retinue_spells.gd`** (42 checks — per-spell arithmetic, base and "+", both target contracts) and **`tools/_probe_retinue_hooks.gd`** (79 checks — the once-per-round latches really latch, "this round" buffs land on `temp_atk_buff` not `persistent_atk_buff`, the shared distinct-name latch fires *both* its consumers, and the adjacency HP aura comes back off without killing).
- **MetaState** (`scripts/state/MetaState.gd`) — cross-run persistence: win/loss counts, `unlocked_ascension`, per-hero `hero_stats` ledger (wins/losses/best_asc, shown on the run-setup detail pane), and the `daily_record` (today's Daily March: date/hero/result). Card types: "creature" (ATK/HP/keywords) and "spell" (spell effect + targeting). `roll_card_reward(act, is_elite, is_boss)` for rarity-weighted picks.
- **RelicDB** (`scripts/data/RelicDB.gd`) — ~135 relics across tiers (starting, combat, utility, including 4x4-specific relics like Vanguard Banner / Rear Guard Charm). Each has hooks, effect ID, and value.
- **KeywordEffects** (`scripts/data/KeywordEffects.gd`) — 26 keywords. Dispatchers: `dispatch_on_enter`, `dispatch_on_death`, `dispatch_start_of_round`. On-enter types include: damage_opposing, damage_random_player, damage_all_enemies, draw, gain_gold, damage_face, debuff_opposing_atk, discard_random, copy_friendly, copy_opposing_keywords, copy_last_dead, look_top, cast_random_spell. On-death types: damage_opposing_lane, damage_all_enemies, summon, bonus_mana, damage_face, debuff_all_player_atk, damage_adjacent.
- **EncounterDB** (`scripts/data/EncounterDB.gd`) — 55 premade fight lineups across 3 acts (incl. the 5 rival-lord kits + 5 amalgam finales). Each encounter has ordered creature deck, reinforcement, HP, and optional fight passive. `REACTIVE_PASSIVES` dictionary defines per-encounter reactive triggers (e.g. `necromancer_tower` doubles enemy on_death via `_dispatch_reactive("ON_CREATURE_DEATH", ...)`). `build_enemy_deck(id)` returns Array[Dictionary] of card data. `get_reinforcement(id)` for infinite backup creature.
- **SetPieceDB** (`scripts/data/SetPieceDB.gd`, 2026-07-20) — **SET-PIECE HOLDS, the named actions of the war**: 3 authored scenarios (one per act) fought on the ordinary combat engine, each with an opening board someone placed on purpose, ONE twisted rule, and an objective on a clock. Thronebreaker's puzzle battles are the model; the house translation is *your deck + one twisted rule + a clock* (a handed deck would bypass the build, which is the standard complaint about the form). **A set-piece is NOT a new node type — it is a `combat` node wearing a `setpiece_id`**, the same precedent as `wayside_id`/`mutator_id`, so every routing, save, medallion, music and gold path works untouched. Five objective kinds live in `Combat._sp_evaluate_objective` (`hold_rounds` / `slay_marked` / `protect` / `break_face` / `clear_board`). **Failure is NOT death**: when the clock runs out the army WITHDRAWS — the toll is paid in HP, the trophy is forfeit, and the march continues (stated on the map tooltip before the player can commit). Trophies are tier `"event"` relics granted on the field, so they never leak into a roll pool. The one rule enforced by a GATE rather than a hook is `closed_lanes` (checked in `_play_creature`, `_place_enemy_card`, `_find_empty_enemy_slot`, `_pick_empty_for_summon`); closed lanes wear the `ClosedGround` exclusion hatch instead of a station mark, because a refusal the player can't see reads as a drag bug. Verify: `tools/_probe_setpiece.gd` (data + map) and `tools/_probe_setpiece_fight.gd` (boots the real combat scene per scenario).
- **EventDB** (`scripts/data/EventDB.gd`) — static event definitions only. `scripts/scenes/Event.gd` owns gates, effect execution, and presentation.
- **AudioBank** (`scripts/AudioBank.gd`) — central SFX/music dispatcher: `play_sfx(name, jitter, volume_db, pitch_base)` (`pitch_base < 1.0` deepens a cue — the low-HP heartbeat, boss horn, and doom tick are repitched stand-ins; those call sites check `has_own_sfx` so a real clip plays straight once it lands), `play_music(name)` (remembers each track's playback position and resumes there when it re-enters rotation — intros don't wear out), and `duck_music(depth_db, hold)` (dips the Music bus under victory/defeat/boss-entrance stingers as a relative offset, then restores the user's slider level). Every screen picks music from a pool via `play_music_random` (49-track library, all Buckley/Nakarada/RandomMind/Pablo-tier after the 2026-07-18 AAA pass: per-act map anchors, per-rival-lord boss leitmotifs in Combat's boss branch, mood-matched event pools, skirmish muster + credits + victory-variant slots — see `assets/audio/music/MUSIC_CREDITS.md` and `docs/MUSIC_AAA_PLAN_20260718.md`); `tools/_probe_music_wiring.gd` (headless) fails if any pooled name lacks a file. A cue whose `assets/audio/sfx/<name>/` dir is missing/empty plays its `SFX_FALLBACKS` stand-in (real clips in the primary dir auto-win); `tools/_probe_audio_cues.gd` (headless) fails if any `play_sfx` call site resolves to silence. Clash audio ownership: struck survivors sound via `Card2D._flash_hit` ("hit_creature"), kills sound ONCE at the impact beat via Combat ("creature_death" + `death_cue_played` flag that `_die()` respects) — don't add a second cue on either path.
- **CardTextureCache** (`scripts/state/CardTextureCache.gd`) — preloads card frames/art textures to avoid per-card disk reads. **Deck-sized work goes through the BATCHED path** (`bake_many` / `bake_battlefield_many` → `_bake_batch`, 2026-07-26): the real cost of a bake is not pixels but the two `await RenderingServer.frame_post_draw` (vsync-bound, ~33 ms/card at 60 Hz) plus the synchronous GPU flush inside `get_image()` (godotengine#75877) — and BOTH are per PASS, so a pass lays up to `BATCH_MAX_CARDS` cards out in a grid and takes ONE readback, then slices with `Image.get_region`. Construction (`BATCH_BUILD_PER_FRAME`) and slicing (`BATCH_SLICE_PER_FRAME`) both yield frames, because the first version of this traded 30 small stalls for one 513 ms frozen frame. Both batch entry points take an optional `validity: Callable` polled between passes (that is how `ScenePreload.cancel_deck_warm` stands the idle map warm down). **Never add a `for cd in list: await bake(cd)` loop** — that is the shape this replaced.
- **ScenePreload** (`scripts/state/ScenePreload.gd`, 2026-07-06) — warms and PINS every screen's PackedScene + the script-loaded big backgrounds (per-act arenas/campfires, map paper fiber) on ResourceLoader worker threads right after boot, so `change_scene_to_file()` hits the resource cache instead of re-parsing .tscn + re-decoding ~2MB backgrounds on the main thread per transition. After the queue drains it bakes one creature + one spell via CardTextureCache (windowed only) to pull the card-font glyph atlases and bake pipeline warm behind the menu. Music has the matching treatment inside AudioBank: `play_music` threaded-loads each track once per session into `_music_streams` (files run up to 18MB — the old sync `load()` was a per-transition hitch); `_pending_music_track` arbitrates races, `stop_music` cancels in-flight plays. Verify both: `tools/_probe_perf_pass.gd` (headless).
- **GameTheme** (`scripts/GameTheme.gd`) — fonts, colors, panel styles, and the enemy-name→art-alias map (now `scripts/data/CardArtAliases.gd`).

### Combat scene (`scripts/scenes/Combat.gd`)

Largest file (~20,400 lines after the 2026-07-14 backend restructure). **The online-skirmish layer lives in `scripts/net/CombatNet.gd`** (~4,750 lines, 132 functions: net turn machine, sealed orders, clash replay, practice bot, spell/potion mirrors, rematch) — a plain child Node created in `Combat._init` holding `combat` as its ctx (KeywordEffects precedent). The compatibility contract: **all net/sealed STATE stays on Combat** (probes and saves read it there), and Combat keeps a thin same-name delegator for every CombatNet function (await-forwarding for coroutines), so probes, `ctx._net_*` calls from KeywordEffects, and core call sites never mention `net.` — new net functions should follow the same pattern (body in CombatNet with `combat.`-prefixed member access, delegator + any new state var in Combat's tail section). Board painters (StationMark, TablePlate) live in `scripts/ui/painters/`, preloaded under their old names. `scripts/combat/CombatOps.gd` owns seeded gameplay randomness and side-aware hero/creature routing; combat-affecting code must use it, while cosmetic jitter may remain global.

- **OVERKILL, AND WHY THE BLOCKER ECONOMY CHANGED (2026-07-28)**. Measured diagnosis: a body absorbed one WHOLE attack regardless of its size, so a 1-cost 1/2 and a 2-cost 3/4 both denied exactly **3.0 damage per Command**, and against an 8-ATK attacker a 1-cost Goblin was a **5× more efficient wall than a 5-cost 6/6** — the defensive curve INVERTED as threats grew. ### Map system

CampaignMapGenerator (called by RunState) generates a branching map per act: 18 rows tall × up to 7 columns wide, 3 paths with a 3× merge bias (trunk road + branches). The act is a fixed **row skeleton** (Kaycee's-Mod model; lengthened 2026-07-07 from 12 rows / 5 combats — the act ended in 3-4 fights, too short for the deck/veterancy/relics to snowball): fight rows (`FIGHT_ROWS [0, 3, 9, 15]`, elite bands at `ELITE_ROWS [6, 12]`) alternate with PAIRS of wayside rows, so every between-fight gap is exactly two non-fight stops (Inscryption cadence) dealt from event / wayside verb / recruit / shop / treasure; `REST_ROW = 16`, `BOSS_ROW = 17`. ### Card upgrade system

Slay-the-Spire-style **"+" upgrades**: every draftable card has one hand-crafted upgraded version. Rest sites offer the "Forge +" action — the player picks a card, sees a before/after preview, and confirms. No path picking, no random rolls. Camp also offers **Hold a Wake** (2026-07-04, only when the Roll of the Fallen has names): pick one fallen soldier; its shade (folded stats while the card still marches, printed stats if mustered out) opens the NEXT fight in front-left via `next_combat_gift_creature` — a real 3-way camp fork (heal / forge / wake), and since camp sits right before the keep, the wake usually arms the boss fight.

**Veterancy ladder** (solo campaign memory, `RunState.creature_kills` per deck_uid) — **the choosing rungs moved FORWARD 2026-07-30** because the old single choice sat 10 kills away and most runs never saw it: **3 kills = epithet ("Pikeman the Grim") AND the war school** (Armored / Swift / Thorns, a `war_school` mod entry), **6 = +1/+1**, **10 = the TRIBE DOCTRINE** — a second chosen keyword drawn from the creature's own `ctype` pair in `Combat.WAR_DOCTRINES` (soldier formation/guardian · beast charge/overrun · dead last_stand/lifelink · warlock piercing/poison · bastion regenerate/guardian · stray sniper/rampage), written as a `doctrine` mod entry. Both modals fire at the top of the next player phase, both have a round-1 catch-up sweep (which doubles as the migration path for live saves), and both auto-pick the first option headless so probes/autorun never stall. **`RunState.veteran_school_kills()` is deliberately an ALIAS of `veteran_epithet_kills()`** — that one function is how the rung moved without touching thirteen call sites; `veteran_doctrine_kills()` inherited the old threshold and the drill_book shave. Every doctrine keyword is drawn from `Combat.DEFECTION_STEALABLE`, the project's already-vetted list of grantable keywords, and none repeats a war school. Verify: `tools/_probe_progression.gd`.

- Per-card upgrade deltas live in `CardDB.UPGRADES` (atk/hp/cost/value/keywords/sub-effect bumps, plus optional desc override). `CardDB.get_plus_upgrade(id)` returns the delta; `CardDB.is_upgradeable(id)` filters out curses.
- The upgrade is applied by `RunState._apply_upgrade` via the `"plus"` path → `_apply_plus_upgrade(data)` merges the delta into the card data and stamps `is_upgraded: true`.
- Custom-spell resolvers in `Combat.gd` read `dmg_bonus`, `slay_draw`, `extra_draw`, `extra_mana`, `ricochet_hits`, etc. from the merged card_data, so + versions actually hit harder / draw more / give more mana.
- A handful of creature passives (Royal Guard, Corpse Eater, Vengeance, Vampire Lord, Riteforge, Warchief) read `card_data.is_upgraded` directly and bump their tick value.
- Specialty upgrade paths — `butcher` (now granted by the War Chest's "Butcher's Kindness" opener), `mirror_twin` / `fortify_neg` (legacy — their events were cut in the 2026-07-03 pool remake; the arms stay so old saves fold) — keep their dedicated paths in `_apply_upgrade`. Events also write the wayside `grant_kw` path: the Old Drill Master (event id `the_lame_master`; renamed from "The Pensioned Master" in the 2026-07-18 prose pass) teaches a chosen creature Armored/Swift/Thorns permanently.

Mods are tracked in `RunState.card_upgrades` keyed by `deck_uid` — **each value is an ordered Array of mod entries (Inscryption stacking model)**: a card can be drilled, carry a transferred keyword, AND be forged; entries fold in the order earned. The "+" forge is the only once-per-card path — `has_upgrade_path(i, "plus")` is the forge filter; `is_card_upgraded(i)` now means "carries any mod"; the " +" name suffix marks the forged state only. `get_upgraded_card_data(uid)` returns the folded data. **Upgrades are applied at draw time in Combat** via the `deck_uid → card_data` lookup — drawing a card looks up its uid and uses the upgraded data dict. Legacy single-entry saves are shape-migrated (wrapped into arrays) on load.

The Whetstone relic upgrades the "Reforge" rest banner to forge **two** cards instead of one (once per act).

**EVERY PERMANENT CHANGE TO A DECK CARD PLAYS A BEAT (2026-08-28).** The forge had `Motion.forge_strike` (Camp, the General's Forge); four other surfaces changed a card and showed the player *nothing* — the screen simply rebuilt with different numbers on it. `Motion.writ_amend(host, card, stamp_text, accent, opts)` is forge_strike's sibling and the shared beat for them. Its five stages are the standard juice grammar, each earning its place: **anticipation** (the page dips and dims for 90ms before it is struck — the wind-up is what separates "a thing appeared" from "a thing happened"), a **specular shine** (a tilted band crossing the card, drawn by a `canvas_item` shader on a child ColorRect in `blend_add` — the Balatro-foil setup, effect on a child rect never on the card's own material; layered trig gives the iridescent fringing and a white-hot core carries the CLAUDE.md contrast rule), then **contact**: a two-frame **impact frame** (the card blown to near-white — hand-drawn action animation's trick, one ColorRect, sized to the SQUASHED rect and centred on the pivot or its own corners stick out past the writ), a **squash** snapped on with no tween (a squash you can watch travel is a wobble), **two rings** (a thin fast shock ahead of a slow heavy swell — one ring reads as a bubble), sparks and a shake; **~70ms of hitstop** that simply refuses to start the settle; then the **settle** with embers lifting off the drying ink. Wired at the **drill yard** (+1/+1 per pass), the **standard-bearer** (the pinned keyword, on the taker's own tile), the **Arsenal** (whose forge called `show_deck_picker` → `upgrade_card` → `change_scene` in one frame and is now a `forge_strike` on a shown "+" card, `Treasure._show_forged_card`), **Event's forge + `grant_kw` pickers**, and **both veterancy rung modals**. Three rules the build cost: (1) **the stamp strikes the ART, not the card's centre** — dead centre on the v9 writ is the name cartouche, so the first version printed "+1/+1" through the creature's own name and "GUARDIAN" over a cream rules box; (2) **the word is fitted to the card width**, or a long keyword lands across the two neighbouring tiles as well; (3) the stamp is INFORMATIONAL so it still lands under Reduce Motion (settled, held, faded) while the lift/sweep/sparks/thump gate off. The drill yard's recruit is now a node that **survives `_clear_ui`** (`_drill_card`, freed by `_drill_dismiss` at every exit) so each pass stamps a card the player was already watching; its tiles carry a `_drill_busy` latch, because the beat is awaited with both tiles still live (Event's pickers got the same, `_picker_busy`, cleared in `_make_card_picker_grid`).

**A PICKER GRID IS BUILT BEFORE THE MUTATION**, so the clicked tile still prints the OLD numbers when the stamp lands on it — `Event._refresh_pick_tile(idx)` re-bakes that one writ from post-mutation data first (keeping the click catcher, which carries the hover lift), or "+2 HP" strikes a card the player can see says 4. Wayside's drill yard solves the same problem by swapping the writ inside the persistent wrapper. **Both veterancy rung modals now stand the veteran's own card in the overlay** (`_rung_overlay_writ` / `_rung_overlay_writ_strike`): they used to name the veteran in a title and show nothing but two keyword tiles, and the overlay no longer frees itself on the click — the lesson is struck onto the writ first, then the screen closes (one-shot `acted` latch on the tiles). Both modals also **moved onto their own CanvasLayer at 100** (the pile-viewer/glossary convention): parented to `self` they sat on the base canvas at layer 0, so the HUD (12) and the hand (20) drew straight over a modal that was blocking input — **`z_index` cannot reach across a CanvasLayer**. Eyes: `tools/_shot_writ_amend.tscn` (18 frames across all five surfaces + a same-instance assertion across two drill passes).

**THE IMPACT KIT — `Motion.impact_frame` / `shock_rings` / `foil_sweep`** were extracted out of `writ_amend` so every card moment speaks one language, and **`forge_strike` was rebuilt on them** (it had the flash and the anvil sparks but no wind-up, no squash and no hitstop, so the loudest card moment in the game was landing softer than its quieter sibling; it stays the BIGGER of the two — heavier squash, wider rings, full-weight shake, ~0.72s). **`rarity_reveal` gives a RARE the foil sweep** across the card itself — the halo says "the slate rolled well" from outside, the foil says it about the card; uncommons deliberately don't get it, because two tiers of shine is one tier of noise. All three primitives gate headless themselves; Reduce Motion stays the caller's branch. A `foil_sweep` on a target whose scale is mid-tween photographs as nothing — the settle is BACK-out and ~85% home within 0.16s, so shoot the hitstop, not after it.

### Card2D (`scripts/Card2D.gd`)

PanelContainer-based card (~4,600 lines after retiring alternate renderers). `CreatureInstance` owns typed gameplay state and versioned save/network snapshots; Card2D is its input/render adapter. **The writ-kit painter classes (WritLeaf, InkCartouche, WaxSeal, StatCaret, ParchmentPlate, TallyMarks, EmptyPlateSigil, WritDetailDiamond, PolyBadge, StatGem) live in `scripts/ui/painters/`** (extracted 2026-07-14), preloaded as same-name consts so `Card2D.WaxSeal`-style references still work; new diegetic painters belong there, not inline. Supports creatures (ATK/HP display) and spells (SPELL label, no stats). Drag from hand above play threshold to play. Battlefield creatures show floop indicator. `take_damage()` handles Armored and Last Stand. `temp_atk_buff` for this-turn buffs; `persistent_atk_buff` + `persistent_atk_buff_rounds` for multi-round buffs (Butcher's Cleaver). `effective_atk()` is the canonical "what's my real ATK right now" — always prefer it over raw `current_atk + temp_atk_buff` reads.

### Card data schema

Creatures: `id, name, type:"creature", cost, atk, hp, rarity, keywords[], desc`. Optional: `on_enter{}, on_death{}, floop{}, adj_buff{atk,hp}, wither:int, passive:String, extra_damage:int`. **Every draftable creature carries a `ctype`** (2026-07-10; system remade 2026-07-15 — see [`docs/TYPE_SYSTEM_DESIGN.md`](docs/TYPE_SYSTEM_DESIGN.md)): **SIX tribes** (expanded 2026-07-15), each with a payoff keystone: `soldier` (ENDURE — line/formation; keystone Warden-Sergeant `warden_line` → full front row grants Soldiers Armored+Thorns, in `_apply_start_round_passives`), `beast` (ARRIVE — on-enter reach/aggro; Bloodmoon Alpha `beast_encore` → a Beast's on-enter fires twice, via `_maybe_beast_encore` at every on-enter dispatch site), `dead` (DIE — the death spine; Gravepact `reap_on_ally_death` → a Wight per friendly death, in `_apply_ally_death_passives`), `warlock` (SPELLCRAFT — casters; Coven Mother `coven_spell` → Warlocks +1 ATK/fight per spell, in `_record_spell_cast_board_payoffs` + its CombatNet mirror), `bastion` (SIEGEWORKS — walls + siege; Siegewright `bastion_ramp` → Bastions +1 ATK/round, in `_apply_start_round_passives`), `stray` (the MASTERLESS — rogues/mercs/shapeshifters; MOBILITY + LARCENY since the 2026-07-24 rework that retired the old gold spine — keystone Free Company Captain, id `kingpin`, carries `defection`: on killing an enemy creature it loots one of that corpse's keywords as a persistent grant (`DEFECTION_STEALABLE`) or free-redeploys when there's nothing worth taking, and while it stands every other friendly Stray free-redeploys on a kill — `_stray_defection_active` / `_resolve_defection`, hung off `_apply_combat_strike_riders` host-side with NO `_is_net` guard, so larceny is skirmish-safe. No pool card carries `per_gold` any more). Effectively no untyped creatures remain. The old `engine`/`zealot` tags are GONE. The tag prints as the letterpress footer and is read by `type_buff {ctype, atk}` (Warchief — state-derived aura in `Combat._get_type_buff_atk`, rides `adj_atk_buff` + the net snapshot) and the `buff_ctype_keyword` on-enter (Siege Golem — retyped Bastion 2026-07-15 — grants its fellow **Bastions Thorns**). **The 2026-07-15 interest slate** (18 boring cards replaced, ids kept — verify `tools/_probe_interest_slate.gd`) added per-tribe texture: `buff_per_ctype` / `per_ctype` breath (Beast arrive-scaling), `buff_ctype_hp` (Warding Stone fortifies Bastions), the c1 wall cycle (Iron Rampart `reflect_strike` — reflects ACTUAL HP lost even on death, via `_apply_struck_passives`; Bramble Stockade `anvil_spawn`), the voltron pair (Oathbound Squire `bodyguard` + Honor Guard `column_ward` — both state-derived column wards refreshed in `_refresh_adjacency_buffs`, read in `Card2D.take_damage`; kill-convention 99+ damage bypasses both), Tallow Doll's `betray_opposing` (the opposing enemy strikes its own nearest ally, or its own face when alone — `_resolve_tallow_betrayal`), and spellcraft/potion payoffs (`spark_on_spell`, `shield_on_spell`, `tonic_vigor`). **Doom** stays a keyword sub-engine feeding Dead. Verify `tools/_probe_type_audit.gd` + `tools/_probe_type_keystones.gd`. Discover finds enter the hand costing 1 less (never free — floored at 1) (`_add_discovered_card_to_hand`, ephemeral). Unholy Bargain's end-of-turn bill = `_bargain_bill`, paid at the solo commit (card is skirmish-denylisted).

Spells: `id, name, type:"spell", cost, rarity, keywords[], desc, spell{type,value,...}, targeting:String`. Targeting: "enemy_creature", "friendly_creature", "any_creature", "any", "none". Untargeted board spells may carry an optional `scope` string ("ALL ENEMIES", "ALL CREATURES", "ENEMY FACE") — it prints as the contract on the card face's one-line footer (`Card2D._spell_footer_text`: "{contract} · {EXHAUST|RETAIN}"; the type word "SPELL" prints only as the fallback when there's nothing to declare — a grid of spells repeating the prefix was noise). Keyword words in rules text are gilded + carry the `[hint]` hover glossary (`KeywordEffects.decorate_keywords`); its inline device stamps exist but are OFF behind `KeywordEffects.INLINE_KEYWORD_STAMPS` until an icon set legible at 13px lands (flat bold silhouettes — painted icons mush below ~20px). The old bottom-margin roundel row is retired on hand cards (2026-07-10). Creatures have NO footer by design — the footer is a casting contract; add a creature type line only when a mechanic reads it (faction tags would live there).

### Adding content

- **New card**: add to `CardDB.CARD_POOL` (include all fields per schema above) AND add a `CardDB.UPGRADES` entry for its "+" version. **It also needs ART** — a file at `assets/creatures/<id>.png` (or `spells/`) or an entry in `CardArtAliases.ALIASES` / `SPELL_ALIASES`, or it renders the line-art stand-in: a blank writ with a thin gold glyph, which in a shop row beside four paintings reads as unfinished. `tools/_probe_card_art.tscn` (headless) lists every playable card that resolves to it — it was 16 on 2026-08-28 and is 0 now. **Armaments take the SPELL loader**, because `Card2D._find_card_art` gates on `is_spell() or is_armament()`; a probe that checks only `type == "spell"` reports six well-aliased weapons as artless, and re-adding them is a duplicate dict key, i.e. a parse error. Missing UPGRADES entries get a default fallback (+1/+1 creature or -1 cost spell) so they still upgrade cleanly, but hand-crafted entries feel better. A creature that introduces a NEW `on_enter`/`on_death`/`on_play` effect type must also be acknowledged in Combat's `TRIGGER_FX_ENTER`/`_DEATH`/`_PLAY` maps (kind + target shape) — `tools/_probe_creature_fx.gd` fails headless until someone decides its beat. **The desc must also FIT.** `Card2D._fit_desc_to_box` spends two budgets on long copy — leading -2 → -5, then ONE font step 18 → 17 — and then deliberately stops and lets the card clip, because the 18px reading floor is worth more than a fifth line. Nothing checked which cards landed past that line, so five base faces and six "+" faces were ending mid-sentence on the shop shelf, in the Collection and on the skirmish draft slate (The Last Man lost "Heal your hero 3 HP." outright), where the player cannot tell a cut rule from an absent one. **`tools/_probe_card_rules_fit.gd`** measures every playable face, base AND "+", and lists every overrun; the remedy is a copy edit, so it reports rather than fails, and the count is the signal. ## THE COACHING SYSTEM (2026-09-10) — the tutorial, its skip, and its replay

**Reasoning, sources and the rejected options: [`docs/ONBOARDING_20260910.md`](docs/ONBOARDING_20260910.md).** This section is the operational summary.

`scripts/ui/TutorialCoach.gd` is the LAYER (spotlight scrim with punched holes, breathing rims, pointing arrows, the drag arc, the step panel — layer 30, above the hand at 20 and the HUD at 12). `scripts/data/TutorialDB.gd` is the REGISTRY: **22 lessons, one dictionary entry each, and everything else derived from it.** Before the registry the teaching was six hand-rolled `_maybe_show_*` functions inside Combat.gd, and that shape had three faults the player paid for: the copy was unlistable and unshowable ("how do I see that again?" had no answer but a new profile), a flag was spent once ever with no way to un-spend one, and **nothing could count them** — so six lessons covered the first fight and nothing else in the game, and the omission was invisible because there was no list to compare against.

- **THE SKIP IS `UserSettings.coaching_mode`** (Settings › Coaching): **FULL** / **TIPS ONLY** / **OFF**. Three settings, not a checkbox, because the commonest returning-player state is "I know deckbuilders, I don't know THIS one" — TIPS ONLY drops the guided walkthrough and keeps the one-line rules that are peculiar to Burning Meadow (the muster, banking, overkill), which are exactly the rules a genre veteran otherwise mistakes for bugs. **`TutorialCoach.should_teach(id)` is the ONE definition of "off"** and every teaching site asks it; a `KIND_STEP` additionally requires FULL. The walkthrough also carries an in-panel `SKIP TUTORIAL` (named, not an X — NN/g), answers **Esc** (narrowly: only while a panel with a visible skip is up, so the pause menu keeps Esc everywhere else), and both endings state where the coaching went — a note on step 1 before the decision and an info line after it. **A skip whose content is unrecoverable is a trapdoor, not a skip.**
- **THE REPLAY IS PER-LESSON.** HOW TO PLAY grew a **COACHING** tab beside the primer: every lesson printed in full, ticked SEEN / NOT YET SEEN (a word, not a colour), each with SHOW AGAIN. **`make_how_to_play_overlay(open_tab)` takes 1 to land on that page directly**, and Combat's `?` panel has a **LESSONS** button that does exactly that — the list was reachable only from the main menu and the map, i.e. never at the moment a player is actually confused. That button forced the FIELD CARD's action row into **two rows**: four 124px buttons need 520px inside a 414px panel. `UserSettings.replay_lesson(id)` un-spends one; Settings' REPLAY ALL un-spends everything. **The replay button is offered once per distinct underlying flag**, keyed off `legacy` rather than a hand-listed set — which is why the three walkthrough steps share one button (a walkthrough is one thing; you cannot have seen step 3 and not step 1).
- **SAVE COMPATIBILITY IS THE `legacy` KEY.** The nine pre-registry lessons keep their own named `UserSettings` properties and are reached through it; everything since lives in the `lessons_seen` dictionary. A lesson that forgets its mapping would re-teach a rule the player was taught weeks ago. `_probe_tutorial` asserts every `legacy` name is a real property, because `get()` on a name that does not exist returns null — which reads as false forever AND can never be set.
- **COVERAGE went from 6 lessons to 22.** New in combat: `back_row` · `keywords` · `spells` · `relics` · `potions` · `overkill` · `hero_hp`. **`back_row` is a design-rule repair, not just coverage**: the walkthrough's own lane step used to say the back row "waits behind" the front, which teaches that four of your eight slots are a bench — the house rule is that the back row is play space and BOTH rows strike every round. The step was rewritten and `back_row` now fires at the decision point (the first time the front row fills, or the first body placed back there). New outside it, one per screen: `map_road` · `map_gate` (MapView) · `recruit_card` (Recruit — **not** the post-fight spoils screen; Recruit is the only place a card enters the deck) · `shop_trade` · `camp_choice` · `event_choice`. **Every one fires the first time its subject is ON SCREEN, not on a fixed round** — a tip that points at nothing is worse than no tip, because it is stamped seen the moment it fires. The two clash-shaped lessons latch instead (`_arm_overkill_lesson` / `_arm_hero_hit_lesson` set a bool inside the clash; the round ladder cashes it in on the next player turn, with the board that produced it still standing).
- **THREE GATES.** `tools/_probe_coach_a11y.tscn` (660 checks) is the newest and the only one that judges the LAYER rather than the lessons: reduce-motion must HOLD not remove, no colour-only signal, the panel must stay on-canvas and cover the full canvas at UI Scale 1.0 / 0.85 / 0.6 (the C32 class), the panel must never sit on its own spotlight, and focus/Esc must behave. **It found a defect the placement code's own header claimed to have fixed:** `_place_panel`'s four candidates are all-or-nothing at the panel's preferred width and the fallback was accepted UNCONDITIONALLY when they all failed — so a TALL spotlight (the lane column is ~632px of a 900px canvas, leaving no room above or below and side gutters narrower than an 820px panel) parked the copy squarely on the two creatures the sentence compares. The header had fixed the candidate ORDERING and never the "nothing fits at all" case. Fix: narrow into the roomier gutter down to `MIN_PANEL_W` (420), re-measuring height because the body rewraps — a narrow panel beside the thing beats a wide panel on top of it. **`_probe_occlusion` (C28) then caught the other half of the same rule**: the keep-out was only ever the SPOTLIGHT, so on any screen with prose OUTSIDE it the panel was free to bury that prose — it sat on Recruit's season subtitle at 63% and its GOT IT button at 67%. `_place_panel` now also scores `_host_text_rects()` (walked LIVE off the host, skipping `self` and nested CanvasLayers) via `_buried_area()`, and — the part that actually fixed it — offers a **LADDER of fallback heights** (0.06/0.18/0.44/0.58/0.70 of canvas). Two earlier attempts failed with BYTE-IDENTICAL overlap percentages, which is the tell that a decision procedure is being handed exactly one option: Recruit's spotlight is the card row in the MIDDLE, so all four side candidates were rejected and "least-worst" had nothing to choose between.
- `tools/_probe_tutorial.tscn` (in `run_safe_probes`) is STATIC — C1 reachability both directions, the copy contract, unresolved `{tokens}`, the legacy mapping, the seen/replay round trip, and that OFF silences everything. `tools/_probe_tutorial_live.tscn` (71 checks) is EMPIRICAL and answers what the static one cannot: it boots a real fight AND all five road screens, and requires each lesson to actually LAND, because a lesson gated on `_relic_chip_by_id` or `_potion_bar_root` can be perfectly wired and still never open — the C20 content-census lesson. **`lesson_seen` is NOT a sufficient oracle and the probe no longer treats it as one**: `teach()` stamps a lesson seen even when every target it was handed resolved to nothing, so each screen must now report what it actually LIT (the camp's banners are found by SHAPE, never by the name the lesson looks them up under — an oracle repeating the lookup it tests only agrees with itself). It carries a `_MUTANT` harness that sabotages one screen on demand; it ships disarmed and prints a banner when armed, and two mutants ESCAPED on their first run because Recruit and MapView build ASYNC — a mutation applied at `add_child` time is overwritten by the build that follows, so it re-applies every poll frame. **A mutant that does not mutate is the same false green as a probe that does not probe.** Eyes: `tools/_shot_tutorial_manual.tscn` (the manual + the settings row), `tools/_shot_tutorial_tips.tscn` (the guided fight), and **`tools/_shot_coach_devices.tscn`** — 22 frames of the DEVICES themselves, including **nearest-neighbour ZOOMS**, because a 2px rim and an 8px seam are not decidable at 1600×900. It settles on the coach's panel-rect + hole signature rather than a whole-screen fingerprint (the board's idle bob is ±3px forever, so a full-screen hash never holds) and prints each arrow's tip, direction and measured standoff from the target's ROTATED edge. **Judge the shine by these, never by the 1600×900 frame** — the craft pass that produced them found the arrow rendering with no white pixels at all and the glow reading as a uniform tube, both invisible at 1:1, and its own first filament attempt failed because at 0.40 of a 2px rim the white band was 0.8px and a pixel centre almost never landed inside it.
- **THE LAYER FACT, unchanged and still true:** combat FX are parented to `_hud_layer` (12) and **z_index cannot cross a CanvasLayer**, so the coach's scrim dims every effect that does not fall inside a punched hole. That is right for "drag this card there" and wrong for any step that asks the player to WATCH something happen. If a future step needs an effect visible, punch a hole over the FX corridor or drop the scrim for that step — do not move `_hud_layer`.
- **What was deliberately NOT built**, from the research pass: no skip-prompt before the first fight (it asks a question a first-timer cannot answer, and front-loads the decision NN/g's own study penalises); no confirmation dialog on skip (reversible actions get recall, not confirmation); no feature-locking of the shell for run 1 (Hearthstone does it and it is defensible, but it is a menu-structure change, not a tutorial one). The 7-second tip hold is a known tension with WCAG 2.2.1 — it is a shared channel that must be released — and the Field Manual is the mitigation.

## Gotchas

- Combat.gd builds all HUD in code, not in the scene editor
- Spell targeting uses `_input()` override, not the card drag system
- `KeywordEffects` accesses combat state via the ctx (Combat instance) directly — Combat is always the ctx
- Enemy deck is `Array[Dictionary]` (card data dicts from EncounterDB), not card IDs. Legacy fallback builds random dicts from CardDB
- Token creatures have synthetic card_data created in `summon_token()`, not from CardDB
- MapView, Shop, Rest, Event, and the starting-relic-pick screen all build UI programmatically; their `.tscn` files only have Background + script (map.tscn has no Background at all — the MapTerrain plate is the background)
- `current_atk + temp_atk_buff` should never be read directly — always go through `card.effective_atk()` so `persistent_atk_buff` (Butcher's Cleaver) is included
- Reactive `double_on_death` re-runs the dying enemy's on_death effect directly via `KeywordEffects._run_on_death(...)` to avoid recursion through `dispatch_on_death → _dispatch_reactive`
- `_short_pause(duration)` is a real timer-based pause (uses `create_timer().timeout`) — the parameter is honored, not ignored
- **Combat beat constants live on the shared Motion clock** (`scripts/ui/Motion.gd`, 2026-07-16): Combat's `LUNGE_APEX`/`POST_HIT_BEAT`/`HITSTOP_BEAT` alias `Motion.*`, and Card2D's lunge/recoil/death tweens build from the same constants via `Motion.time()` (anim-speed scaling). New combat-visible tween durations should be wrapped in `Motion.time()`; shell/kit animations stay unscaled by policy. `LUNGE_APEX` is DERIVED (anticipation + strike) — never hardcode an impact delay. ### Card text positioning (v3 layout — superseded)

Text on cards (cost, name, type, description, ATK, HP, FLOOP) is positioned by **pixel-measured POINT_* constants** in [scripts/Card2D.gd](scripts/Card2D.gd), each pointing at the center of a painted region in the 300×400 source frame texture.

**To tune or re-derive these positions, run:**

```
python tools/measure_frame.py
```

It scans `assets/frames/frame_creature_common.png` pixel-by-pixel — looking for the red orb's bright-red core, the banner's dark-gray interior, the gold divider scroll, the tan parchment well, etc. — and prints a copy-pasteable block of `POINT_* := Vector2(...)` constants with the bbox center of each region. Replace the matching constants in `Card2D._build_full_layout_v3`'s header.

**Eyeballing positions does not work.** Earlier attempts had `POINT_NAME` 20px above the actual painted banner because the banner's gold trim above the dark interior visually fooled the measurement. The script reads pixel values directly, so it can't be fooled the same way.

**Layout uses point-anchored centering, not anchor rects.** The helper `_center_at_point(label, point, size)` anchors a label to a single point with symmetric `offset_left/right/top/bottom = ±size/2`. This avoids two Godot quirks: (1) `Label.vertical_alignment = CENTER` misaligns when the rect is smaller than the font's line box; (2) asymmetric anchor rects make `horizontal_alignment = CENTER` compute the visual midpoint inconsistently. POINT_* is "where the center goes," SIZE_* is "how much room the label gets" — keep SIZE_* generous (≥36px tall) so Godot's centering works.

**Font setup** lives in [scripts/GameTheme.gd](scripts/GameTheme.gd) `_load_assets()`. Three fonts:
- `font_display` — Cinzel Variable wrapped in FontVariation with `wght: 600` (SemiBold) for names, type, FLOOP
- `font_stat` — same Cinzel but `wght: 800` (Black) for cost / ATK / HP numerals — matches AAA card-game stat-orb conventions (Hearthstone, MtG Arena)
- `font_body` — Nunito Regular for descriptions

Both Cinzel variations set `spacing_bottom = -3` to optically center caps-only text (caps don't use descender space, so geometric center renders ~1.5px high). If text still looks high, increase the negative value; if low, push toward 0.
