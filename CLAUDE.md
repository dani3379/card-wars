This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

"Burning Meadow" — a lane combat roguelike deckbuilder built in Godot 4.6 (gl_compatibility renderer, 2D). Inspired by Card Wars (combat) and Slay the Spire (roguelike structure). 4 lanes × 2 rows per side (front/back), simultaneous combat with Swift pre-phase, floop, spells. 3 acts with branching maps, shop/rest/event nodes, premade encounter lineups with fight passives.

## Running the project

Open in Godot 4.6+ and press F5. Main scene is `scenes/main_menu.tscn`. There is no build step or formal unit-test suite; `tools/_probe_*.gd` scripts are the headless regression harness.

**Compile gate — finish every script edit with this one command:**

```
Godot_v4.6.x-stable_win64_console.exe --headless --path "D:\Godot" res://tools/_probe_parsecheck.tscn
```

`_probe_parsecheck` runs as a SCENE (so autoload names resolve) and does a real `ResourceLoader.load()` + `GDScript.reload(true)` over every script under `scripts/` (~113). A script that does not compile takes the WHOLE GAME down, so nothing less is worth trusting. It is one of the three probes in `tools/run_safe_probes.ps1` (with `copy_lint` and `event_art`) — the CI-safe set to run before any commit.

**THE UI / FEEL GATES — `tools/run_ui_gates.ps1` (2026-09-02).** A second, SLOWER runner holding the ten pixel-and-layout gates, kept out of `run_safe_probes` for two reasons: they run for minutes (that set is the seconds-long pre-commit loop), and **three of them measure PIXELS and cannot run `--headless`** — a "CI-safe" set that silently needs a display is not CI-safe. Pass `-SkipWindowed` to drop exactly those three on a headless box. Contents: `occlusion` · `cfg_diff` · `input_reach` · `alignment` · `uiscale` · `popup_layering` · `spring` (headless) and `boil` · `smear` · `modal_scrim` (windowed). It tolerates a short, named list of Godot's exit-time noise (`resources still in use at exit`, `ObjectDB instances leaked at exit`) because every gate here builds scenes and would otherwise fail for something none of them did — anything not on that list still fails the run. **Run it after any change to Card2D, Combat's HUD/modals, Event's layout, or `scripts/ui/`.**

**THE PILOT — `tools/_probe_pilot.tscn` + `tools/run_pilot.ps1` (2026-09-15), the only thing here that HOLDS THE MOUSE.** Every other probe calls the game's functions: `_probe_autorun` soaks combat through `_on_card_played`, `_probe_card_play` asserts that gesture's bookkeeping the same way, `_probe_campaign_walk` walks the map through `visit_node`. All correct, and all blind to the same thing — **none of them touches the input pipeline**, so a card that cannot be picked up, a slot that cannot be dropped on, a scrim parked over a button, or a release one pixel under `PLAY_THRESHOLD_Y` ships green through the entire suite. The pilot moves a synthetic cursor, presses, drags and releases, and lets GODOT decide what receives each event; it knows nothing about which node *should* get the click, it asks `Viewport.gui_get_hovered_control()` — which makes it the LIVE counterpart to `_probe_input_reach` (C29), that re-implements the picking rule statically over a settled screen. It is a BUG FINDER, not a gate: **read the COVERAGE block before believing an empty finding list**, because a pilot that never reached act 2 has said nothing about act 2. **THREE MECHANICS, each measured against a button the harness owned so nothing about the game could explain a miss:** (1) **`Input.parse_input_event` is a NO-OP under `--headless`** — it hands the event to a dispatch hook only a real DisplayServer installs, so the event is accepted and silently dropped and a pilot built on it reports a clean run having pressed nothing; (2) **the coordinates must be canvas-LOCAL, `push_input(ev, true)`** — the headless root window boots **64×64 and REJECTS `root.size =`** while `get_visible_rect()` reports 1600×900, and `push_input(ev, false)` runs the event through `get_final_transform().affine_inverse()` (measured: a 0.04 scale) which throws every click off the world; (3) **`Button.text` is EMPTY on every MainMenu button** (`_make_menu_button` puts the word in a descendant Label; the road screens' `make_primary_button` does set it), so a text-only finder reports a broken title screen. **RUN IT BOTH WAYS — headless and windowed are different games for a driver.** The veterancy rung modals **auto-pick the first option headless** so probes never stall, so a headless pilot never meets one; windowed, a rung opens at the top of a player phase with `phase == PLAYER_TURN` and the hand dealt and stable — every readiness test saying "your move" while a layer-100 overlay refuses every drag. **THE HAND IS HUMAN, and that is COVERAGE rather than decoration (2026-09-15).** A cursor that teleports never crosses anything on the way (so it raises no hover, opens no tooltip, fires no `mouse_exited`), lands dead centre every time (so it never tests the edge of a hit region), and arrives on the same frame every time (so a race needing a slower approach is unreachable). Two off-the-shelf models: **WindMouse** decides WHERE — a point mass under gravity-toward-target plus a wind random-walk that is DAMPED inside `D_0`, which is what makes the path wander on the way out and settle straight on the way in (the corrective sub-movement every human pointing motion ends with), with velocity clipped to a RANDOM fraction of `M_0` so the speed never flat-tops back into a constant; published defaults `G_0=9 W_0=3 M_0=15 D_0=12`. **Fitts's law** decides HOW LONG — `MT = a + b·log2(D/W + 1)`, so target SIZE is half the model and a small far button costs materially more than a big near one. Clicks land on a Gaussian (σ ≈ W/6) near the middle, **never on it**, backed by a CENTRE RETRY: centre-lands-but-off-centre-misses is `PARTLY_COVERED` (a real, distinct finding), both-miss is genuinely blocked — without that split, off-centre aiming manufactures false occlusion reports on any control with a child over one corner. **ONE SCORER, TWO SIDES — `scripts/combat/BoardEval.gd` (2026-09-15).** "What is this play worth, right now, on this board?" is asked by exactly two things: `SkirmishBot` (the practice opponent) and `tools/_probe_pilot.gd` (the input pilot). **THE BOT LEARNS FROM THE GAME IT JUST PLAYED — `scripts/combat/BotBrain.gd` + `scripts/combat/BoardSim.gd` (2026-09-15).** `BoardEval` is a ONE-PLY judgement with hand-picked weights, which is where every hand-tuned scorer is weakest: it cannot see that the 4/1 it valued for its ATK dies to the first blow, or that the wall it undervalued denies a column for three rounds. `BotBrain` closes the loop. During a practice match `SkirmishBot` reports EVERY decision — the board, the whole slate of plays that were legal, and the one taken — and at the verdict `CombatNet._net_show_result` calls `on_match_over`, which re-examines each decision with a deeper look and moves the weights toward it. **Four published ideas, each doing a job the others cannot.** (1) **SEARCH BOOTSTRAPPING** (Veness et al., NeurIPS 2009, *Bootstrapping from Game Tree Search* — RootStrap/TreeStrap, via Samuel 1959 and Baxter's TDLeaf): the training signal is not the game result, it is what a DEEPER SEARCH said about the position — dense (every decision teaches) where win/loss is one bit per game. (2) **COUNTERFACTUAL REGRET** (the CFR family): regret = `rollout(best alternative) − rollout(chosen)`, in stat points, and it SCALES the correction so the learner spends its budget on blunders rather than on every routine play. (3) **OUTCOME WEIGHTING** (Texel's tuning): the rollout can be wrong, the scoreboard cannot, so a lost game teaches harder. (4) **SELF-PLAY HILL CLIMBING WITH AN ACCEPTANCE TEST** — the safety property, and not optional: learning never touches the weights the bot plays with, it accumulates into a CHALLENGER that must beat the CHAMPION in simulated games before it is adopted. **`user://bot_brain.json` holds both plus a ledger; with no file on disk the weights ARE the shipped constants, so a fresh profile behaves byte-identically to the build before any of this existed.**

**`BoardSim` is a SECOND implementation of the clash and the honest name for that is an APPROXIMATION.** `Combat._clash_lane_pass` is the authority and is unusable as a search primitive — it awaits animation beats, mutates Card2D nodes, fires audio and ships net events, where a rollout must resolve a board thousands of times a second with no scene at all. It models what decides ordinary trades (both rows strike, front first; target = opposing front, else back, else face; the MUSTER DELAY and Swift's exemption incl. the Rush no-face rule; OVERKILL spilling behind and STOPPING while only Piercing reads on to the face; Armored/Thorns/Last Stand/Regenerate/Wither/Lifelink/Sniper; deferred deaths so a mutual trade is mutual) and explicitly NOT triggers, relics, encounter passives, or any card played after this instant — which is why the horizon is 3 rounds, the window where "nobody plays another card" is least wrong. Its `SimCtx`/`SimBody` are duck-typed so **`BoardEval` scores a snapshot with no special case**, which is what lets a decision be re-scored offline months after the Combat scene that produced it was freed. **`SimBody.can_attack()` DOES NOT READ HP, and that is the rule rather than an oversight** — `Card2D.can_attack()` does not either, and `defer_deaths` holds a corpse standing to the end of the pass; guarding on `current_hp > 0` read perfectly sensible and made every simultaneous kill resolve one-sided, which would have taught the scorer that trading up is free.

**THE THINGS THIS COST, all of them measurement rather than code.** **(a) THE ACCEPTANCE TEST WAS NOISE.** A flat 56% over 24 games is 0.6σ on a Binomial(24, ½) and clears BY CHANCE about one trial in four; the probe caught it the only way such a thing is caught — an IDENTICAL challenger, which cannot be better by construction, was promoted at 0.67. The bar is derived from the sample now (`n/2 + σ√n`), and **the DECISION RULE is a pure function (`trial_verdict`) asserted directly**, because a test that fires a random batch at a threshold is testing the random number generator. **(b) EVALUATION IS DUPLICATE-PAIRED, and this was the fix that mattered.** Independent games with alternating seats are unbiased and far too noisy here: the best reachable vector is worth a few percent and the standard error on 240 games is the same size, so a deliberately crippled brain measured 0.494 against a 0.488 baseline — invisible. Playing each seed TWICE with the brains swapped (duplicate bridge) cancels the deal: a pair the CARDS decided ties and carries no information, and only pairs where the brains diverged score at all. Same compute, and it turned an unmeasurable difference into a readable one. **Two identical brains now produce ZERO decisive pairs, which is the pairing working perfectly and read as a 0.000 wipeout until `score_rate` was taught that "no difference" is 0.5.** **(c) THE THREE BANDS ARE ASYMMETRIC ON PURPOSE** — clearly ahead promotes, clearly behind REJECTS, and no evidence at the cap ADOPTS. A gradient step here is not a random mutation; it arrives with a rollout's justification, so the trial's job is to catch it being wrong, not to re-prove it right. Demanding proof of improvement per step sounds stricter and is fatal: one step is worth ~1% and no affordable sample resolves 1%, so every step is discarded — exactly what the first build did (23 reverts, 1 promotion, 4% of travel on a weight that wanted 60%). **(d) THE GAUGE MUST NOT DRAG.** `normalise` pins `atk` at 1.0 (the scorer is invariant under a uniform rescale, so one weight has to be fixed or the learner wanders that direction forever) — but the first version DIVIDED the whole vector by whatever `atk` had drifted to, which pushed weights the learner had never touched into the clamp ceiling: a 250-game run ended with `card` and `command` at 6.69 having never once changed a decision, reading like a discovery about drawing cards. Pin `atk`, rescale nothing.

**A SENSITIVITY SWEEP IS WORTH MORE THAN A GUESS, and it named a sanity check that could not fail.** The first "crippled brain" put `face` and `kill` at the floor — "a bot that will not close a game" — and scored EXACTLY 0.500, because those two barely enter a creature placement at all (`kill` needs a Swift body that can kill or a plain `damage` spell; `face` only reaches the open-lane term). Pushing each weight to its band edge over the real 152-card pool showed **FOUR of the thirteen — `card`, `command`, `kill`, `back_exposed` — never change a single decision in skirmish**, while `hp` and `block` move the win rate several points each. It was crippling a leg the bot does not walk on. **The same sweep predicted the learner's answer**: shipped HP at 0.75 is too high, and training independently drove it to ~0.25.

**Gates.** **`tools/_probe_bot_brain.gd`** (47 checks, `--script`, 2.4 s — it stays out of `run_safe_probes` for the same reason `_probe_board_eval` does: being `--script` is what makes it the standing check that neither new file names an autoload). Phase A pins the forward model to the engine's own rules; B requires the rollout to actually DISAGREE with the one-ply score (a learner whose deep look always agrees is an expensive no-op that still prints a rising generation count); C requires a blunder to be named AND a good decision to teach nothing; D requires the margin to grow; E pins the gauge and proves a weight the decision cannot involve is not moved by learning from it; F asserts the three-band rule and that a trial FREEZES its hypothesis; G round-trips the save and refuses a NaN (every comparison against NaN is false, so the bot would simply stop finding a best play and stop playing cards, with no error anywhere); H is the safety property — a fresh brain IS the shipped vector. **`tools/_probe_bot_train.tscn`** is the other question and runs as a SCENE because it trains on the real pool: baseline, a guardrail that must REJECT a losing challenger, a positive control that must ACCEPT a winning one, then the headline. **It gates only "learning did not make the bot worse"** — whether a seed finds an improvement is data, and asserting it would fail on an unlucky seed and teach everyone to re-run until green. **`uiscale` is CLASS C32 (2026-09-03), and it is the only gate that changes the VIEWPORT.** Every other gate runs at the 1600×900 project canvas — but `SettingsOverlay._add_ui_scale_row` offers the player **UI Scale 60–100%**, which sets `Window.content_scale_factor`, and under `canvas_items` stretch that DIVIDES the logical canvas: at 60% the UI lays itself out on **2667×1500**. **`alignment` is CLASS C30 (2026-09-03), and it is the only gate here that judges a control against the ones laid out BESIDE it.** Every other layout gate judges a control against ITSELF — does the text fit its box, is anything painted over it, can the click reach it — and a control can pass all of them and still be the thing a player points at and calls wrong: it fits, it is uncovered, it clicks, and it sits four pixels left of the column it belongs to. "Off centre" is a matter of taste judged one rect at a time, so the pass judges RELATIONALLY: the odd one out of a peer group, a near miss in the 1–8px band (alignment is binary — zero is intent and forty is intent, three is a slip), a contradicted `CenterContainer`, a one-sided invisible gutter, and worded controls compared **by their INK across the Button/Label divide** (`Button.flat = true` stops the box being DRAWN, not its margins being SPENT). **THE RULE THAT MAKES IT CORRECT: a group declares its own alignment, and only that declaration is judged** — judging CENTRE in a left-flush column reported a deliberately short chip row as 102px off, and judging EDGES in a centred row reported the map HUD's purse coin (50px, deliberately sharing the 40px row's mid-line) as a 5px near-miss top AND bottom, those two deviations being equal, opposite, and the signature of a correctly centred object. **THE SYSTEMATIC SWEEP (2026-08-29) — [`docs/BUG_SWEEP_METHOD_20260829.md`](docs/BUG_SWEEP_METHOD_20260829.md).** Ad-hoc hunting in skirmish found 13 bugs, then 1, then 0 — that curve is why the hunt was replaced by a method: nine classes organised by HOW A BUG HIDES, since that decides the technique that finds it, each with an inventory and a stopping condition. Two more followed: **`tools/_probe_persistence.gd`** (C8 — every `CreatureInstance` field enumerated from `get_property_list()` and round-tripped through both snapshot formats, so the next `effect_immune` fails a gate instead of needing a human; plus same-seed run reproduction) and **`tools/_probe_upgrade_merge.gd`** (C2/C9 — every `CardDB.UPGRADES` key diffed against the key set `_apply_plus_upgrade` actually consumes, extracted from that function's own source; an unmerged key is the Counterorders bug, where the "+" advertised 9 damage and dealt 6). Both orphan gates carry WAIVER dictionaries: an entry there is visible debt, not absolution. Two further classes came from the published test-design literature rather than from generalising found bugs, and both cover ground the first nine did not. **`tools/_probe_metamorphic.gd`** (C10) answers the ORACLE PROBLEM that stopped the text-vs-data pass dead: instead of comparing a clash to a known-correct output — which would need an oracle the engine itself is — it asserts RELATIONS between two related runs. A board and its MIRROR must resolve identically (any side-biased branch breaks it), one snapshot applied twice must equal applied once, and damage must be non-decreasing in attack. Each mirror fixture carries a vacuity check, because a symmetry test passes trivially if the transform was a no-op. **`tools/_probe_interruption.gd`** (C11) is Lewis et al.'s TEMPORAL class — invalid state / interrupted event / action not performed — which is where this codebase actually breaks: three bugs this session were one shape each, and the 2026-08-07 audit's "await-during-live-button" class was a fourth. It interrupts on purpose: the same action fired twice in one frame (the double-click that produced four latch bugs across MainMenu/Collection/Credits/MapView), the scene freed while a coroutine is parked mid-clash, and peer-loss delivered at three phases. Two more test the things the others cannot. **`tools/run_mutation_check.sh`** (C12) tests the TESTS: nine faults, each re-creating a bug actually fixed, are injected into production code and the gate that should notice is required to FAIL (files byte-copied, restore checksum-verified). It found TWO FAKE GATES on its first run — the soak stayed green with `_is_sealed()` forced false, because it was proving "cards can be played" rather than "Sealed Orders ran", and the boundary probe could not see its own founding defect since scroll content is exempt from the off-canvas rule. Both fixed; score 9/9. **`tools/_probe_fuzz_wire.gd`** (C13) is the only pass that feeds the game input it did not write itself, and it found a REMOTE ABORT VECTOR: every intent handler read peer fields with a bare `int(...)`, which THROWS on a Dictionary or Array and aborts the function where it stands, so `{"t":"play_creature","lane":{}}` stopped a host handler half-finished. `NetProtocol` cannot catch that — the envelope contract is about SHAPE and that payload is well-shaped — so the coercion was made total (`_wire_int`/`_wire_str`, all 44 peer-supplied reads, host and client). **`tools/_probe_invariants.gd`** (C14) is the only pass that watches the game WHILE IT MOVES — every other one inspects a settled state, and plenty of defects exist only in transit. It asserts always-true properties on EVERY FRAME of a driven match (one body per slot, no dead body standing outside the deferred-death window, no freed node in the entity registry, Command never negative, no duplicate uid in hand), and it found one immediately: **`Combat.gd` never called `unregister_entity` anywhere**, so every creature that died on the host stayed in `NetMatch.entities` pointing at a freed node — stale on 26,033 frames of one match, and invisible to every end-state check because the registry is cleared wholesale at `_enter_combat_local`. Its own first run was a FALSE PASS worth remembering: naming `Card2D` at parse time in a `--script` probe drags Card2D.gd into the pre-autoload compile, so `card_2d.tscn` instantiates as a bare `PanelContainer` and the whole match runs scriptless while the audit reports green — load such classes at RUNTIME. **`tools/_probe_pairwise.gd`** (C16) is the first pass to test the SPACE rather than the axes: every gate before it varies one parameter with the rest held still, so a defect living only where two features MEET is invisible. It builds an ALL-PAIRS covering array over {style, first, best_of, relic, potion} — 35 combinations covering all 119 pairs out of a 280-match cross product, with the coverage VERIFIED before the matches run — then adds the part with teeth: a (relic × style) CELL MATRIX requiring each relic's delta from the no-relic baseline (max Command, opening hand) to be IDENTICAL in both battle styles. Nothing about what a relic ought to do is hardcoded, so it survives any retune; a vacuity guard requires the matrix to observe a real effect first (4 relics move the opening today). **`tools/run_two_process_match.sh`** (C17) CLOSES THE ONE INFRASTRUCTURE GAP the method doc has listed since it was written: two real Godot processes playing a match over a real ENet socket, each writing a digest the driver DIFFS. Everything else runs host and client in one process, where the wire is a function call and a payload handed across is THE SAME OBJECT — so serialisation, real delivery ordering, and the earned three-term handshake are reachable nowhere else. Its own build produced three traps worth keeping: **the driving node must not be `current_scene`** (the match path ends in `change_scene_to_file`, which frees it — and reparenting is a no-op because the main scene is already on root, so hand the work to a second node beside `current_scene`); **both peers must stop on a SHARED clock** (stopping on local turn counts made whichever finished first tear the socket down, freezing the other mid-match and reading as a board desync that was two snapshots of different instants); and **a sealed stand-in is not a desync** — `_sealed_pending` holds local previews at `entity_id == -1` until the reveal, so the digest distinguishes a TRACKED stand-in from an ORPHANED one (an untracked `-1` body IS a real defect, since the host addresses every net beat by entity id and could never reach it). Verified by mutant: `MAX_ARRAY_ITEMS` 256→4 overruns the clash-reel envelope and the gate catches it while every other net gate stays green. **`tools/_probe_silent_refusal.gd`** (C18) is the only pass aimed at code that is CORRECT and a bug anyway: a control that declines and says nothing — no message, no sound, no recoil — is a dead button to the player, has no state to assert against, and was the shape of the two worst skirmish bugs in this sweep. It reads FEEDBACK ASYMMETRY (only functions that already speak on some refusal; a silent sibling there is the finding) and ignores any branch that CALLS something, since a dispatch or a visible snap-back is the opposite of the defect. It found the discard-mark right-click refusing in silence under the exact rules the left-drag explains, and a potion belt that is never disabled (so a mid-clash click was a dead button). Waivers are keyed `function::guard-needle`; one of them is a STANDING TRAP — the combat belt draws whatever the slot holds without filtering `usable_in`, so the first map-only potion added to PotionDB renders a lit, clickable, completely dead slot. **`tools/_probe_await_audit.gd`** (C19) is the exhaustive static complement to C11: `await` suspends a function and lets the game run, so a node it holds may be FREED on resume — and a freed-object write silently ABORTS the function, so the symptom is an animation that stops halfway with NO error printed. 594 awaits is not an eyeball pass. Two probe rules earn their keep, both language facts: a MULTI-LINE await is one statement (its args evaluate BEFORE the suspension, so a continuation-line mention is a pre-await use — missing this flagged the correctly-guarded `_ordered_strike`), and an await nested in a branch does NOT dominate code at a shallower indent (`_sniper_fire`'s sits in an `if` that returns). It found the COIN TOSS on both peers: `layer` is a child of the combat scene, peer-loss arms a scene change 2s out, so a drop mid-toss frees it and leaves the winner with a coin and no choice buttons. Waivers are keyed `function::variable`; the recurring reason is GUARD-BY-OWNER (validating the container, not the leaf), which is sound and not safely automatable. **`tools/_probe_content_census.gd`** (C20) asks the question C1 cannot: C1 is STATIC (is this id dispatched), this is EMPIRICAL — content can be perfectly wired and still never appear because an act, a rarity band, a deck predicate or a pool filter never lets the roll through. It rolls the SHIPPED generators 12,000× per context and tallies what falls out (cards 193/193, relics 70/70+9/9+6/6, encounters 48/48). ITS OWN THREE BUGS ARE THE LESSON, each having produced a confident wrong report: the card/relic rolls return an Array SLATE not one id (read as a string, it announced 193 unreachable cards — so it now refuses to print a "never appeared" list when its generator produced ZERO); encounter types are `combat`/`elite`/`boss` and a draft querying `"normal"` built its ELIGIBLE set from the SAME wrong query, so it agreed with itself and PASSED at 18-of-18 against 55 authored lineups; and rolling relics with an empty `hero_id` made `filter_pool_for_run` drop every `restricted_to` relic and call 32 reachable ones dead (it now rolls per hero and unions, and excludes `retired`). Finally, A GATE IS ONLY CORRECT IF IT CAN OPEN — "deck-gated" and "dead content" are the same observation, so the pass builds the deck each potion gate asks for and PROVES it becomes rollable. **`tools/run_chaos_save.sh`** (C21) injects faults into the ENVIRONMENT rather than the code: 14 corruptions (truncated mid-write, numbers-as-strings, empty object, NUL bytes, trailing garbage) across run/meta/settings saves, plus backup recovery. This is the class a player calls "my run is gone" and nothing else here pointed at it — C8 round-trips WELL-FORMED saves and never asks what happens when the file is wrong. The save system passes all 42: the `.bak` fallback recovers the REAL save and, with both copies wrecked, `load_run()` reports failure instead of proceeding on an empty run. It writes garbage into `user://`, so the driver moves APPDATA to a temp dir (GODOT_USER_HOME is a no-op on Windows) and the probe REFUSES to run without that isolation. Its own three harness bugs all produced the SAME wrong answer — 14 of 14 "unusable state" — and a uniform failure across every case is almost always a broken oracle: a predicate naming `player_hp` (the field is `hero_hp`), a typed `Array[String]` compared against `null` (an invalid operand that ABORTS the lambda rather than returning false), and multi-line lambdas written inline in an argument list, which parse unreliably — bind each to a local first. **`tools/_probe_invariant_mining.gd`** (C22) is the only pass that does not test a property a human chose: it MINES them. Phase 1 records every numeric field across seeds/styles and keeps the bounds plus pairwise `<=` relations that always held; phase 2 replays them against unseen seeds and the other battle style. A break is an OVERFIT or a real rule violated, and the report splits them because a widened RANGE is the expected cost of a finite sample while a broken RELATION was a structural claim. Survivors are ranked by INFORMATION — only relations whose two fields have OVERLAPPING ranges are interesting, since `hand_size <= player_hp` is arithmetic (2..5 vs 15..30), not a rule. It rediscovered **`bodies_foe <= entities`** unaided — every enemy body must be in the entity registry, which is exactly the invariant whose violation C14 caught when `Combat.gd` never called `unregister_entity`. **`tools/_probe_dominance.gd`** (C23) is the only pass that compares two pieces of content TO EACH OTHER (dominance by the rarity curve; every "+" forge strictly better than its base). It found ZERO defects, and its VALUE IS THE FALSE POSITIVES, which are facts about this codebase: **a forged bonus is driven from FOUR places** — a merged UPGRADES delta, an `is_upgraded` read in the resolver (`_apply_armament` grants hooked_pike +1 ATK, tower_shield +2 HP, grave_bell/witchbrand +1/+1, forked_spear +2 ATK, repeating_arbalest +2 HP), a local `is_plus` in a custom-spell resolver (`long_roll` pays 7/16 forged vs 5/12 base entirely that way), and a resolver keyed on `spell.id` NOT the card id (Lock Shields resolves under "testudo", Countermarch under "baggage_train"). So a desc-only UPGRADES entry is NOT evidence of an inert "+". Also: abilities must be compared by PAYLOAD not by key (every spell carries a `spell` key and 0/0 stats, so key-comparison made the cheapest spell dominate the entire pool — 1,077 false hits); **Doom is a DOWNSIDE**, not a bonus keyword; and **tribe is not cosmetic** — a Dead 2/2 and a Beast 4/2 at one cost are not substitutes. **`tools/_probe_runaway.gd`** (C24) is the only pass that plays RANDOM decks drawn from the whole skirmish pool (145 distinct cards over 10 matches) rather than the same twenty every time — cards that never otherwise share a board get to meet, which is the only way an emergent interaction shows up. Its oracle is objective, so no balance judgement is needed: a stat driven without bound is an unbounded combo, and a match that cannot end is a softlock. Clean. TWO ORACLE LESSONS from building it: **a corpse below zero HP is legitimate mid-clash** (`Card2D.defer_deaths` holds dead bodies standing so a simultaneous trade resolves both ways — sampling inside that window reported nine healthy matches as broken), and **an "absurdly large number" ceiling is the WRONG oracle for unboundedness** — forcing Command to accumulate every round only reached 18 before matches ended, so a ceiling of 25 stayed green while the resource was genuinely unbounded; deriving the bound from the CONTRACT instead (`player_max_mana + MAX_BANKED_MANA`, what `_start_round` actually promises) catches it on the FIRST round at Command 6. **`tools/_probe_golden.gd`** (C25) is the standing regression net — approval testing for a codebase with no unit tests and one 20,000-line module: it records what a fixed set of seeded matches DOES into `tools/golden/combat_digests.json` (re-record deliberately with `-- --bless`) so any future diff is the alarm. It certifies nothing about correctness, and it proved one thing nothing else had: **a whole MATCH is deterministic** — same seed, both battle styles, identical digests within a process AND across separate processes (C8 covers run GENERATION only, so a divergence here would have meant a gameplay decision reading unseeded global RNG). ITS LESSON IS ABOUT COVERAGE and came from a mutant that ESCAPED: halving `MAX_BANKED_MANA` changed no digest, because the driver spent everything each turn and nothing ever banked — the constant was never load-bearing in any scenario, while a card-stat mutant fired instantly, proving the digest itself was sensitive. Adding a FRUGAL scenario that underspends (so Command carries to `mana=5/3`) made it fire. **A golden master pins only the behaviour its scenarios exercise, and a narrow corpus is worse than none because it reads as coverage.** **`tools/_probe_coverage.gd`** (C26) is the only pass that measures the SUITE rather than the game: which behaviours has any of it ever actually executed? That became urgent in C25, where a mutant escaped the golden corpus because no scenario banked Command — every gate is vacuous over code it never runs. GDScript has no line-coverage tool, so it measures BEHAVIOURAL coverage (for a card game the dispatch surface IS the content): 14 random-deck matches reach 114/153 skirmish cards, 39/52 spell effect types, 15/21 on-enter, 8/10 on-death, 19/22 keywords, with 29 further spell types campaign-only and outside its reach. **READ THE SCOPE** — that is ONE driver over 14 matches, not the whole suite; a card absent may simply not have been drawn, and `_probe_autorun` likely covers some campaign resolvers, so the honest claim is a FLOOR not a verdict. Its own bug was THE DENOMINATOR for the third time in the sweep: building the universe from the whole CARD_POOL counted `draftable: false` hero-retinue customs as blind spots of a SKIRMISH driver and reported 48% where the scope-matched figure is 75%. **A coverage number whose denominator does not match what the driver can reach is not a measurement.** Read the doc's "honest limits" section before assuming a class is covered — design/balance, true two-peer faults and emergent interactions are explicitly out of reach.

**parsecheck's ONE blind spot (2026-08-29): it runs as a SCENE, so autoload NAMES resolve.** That is what makes it trustworthy for everything Combat-shaped — and it means it cannot see a compile error that only happens in a `--script` context. A plain `RefCounted` that tools `preload` (e.g. `scripts/net/NetPlayerState.gd`) has its dependencies compiled BEFORE the autoloads register, so a bare `RelicDB` / `RunState` identifier inside one is a hard compile error there while parsecheck stays green — and it takes the whole depending probe down with it (`_probe_skirmish_combat` failed to load outright). **`preload()`ing the autoload's script instead is worse, not better**: it drags that script into the same early compile, where ITS own autoload reference fails, and the failure then poisons the real autoload for the entire run (every call site reporting "Nonexistent function 'get_relic' in base 'Node'"). Resolve through the tree at CALL time (`Engine.get_main_loop().root.get_node_or_null("RelicDB")`) with an explicit fallback. After touching any non-Node helper script, run one `--script` probe as well as parsecheck.

Two cheaper recipes exist and BOTH have shipped false passes; use them for a fast inner loop only, never as the final word:
- `--check-only --script res://scripts/scenes/Combat.gd` catches TOKEN/syntax errors only ("Identifier not found: <autoload>" is a false positive here — autoloads aren't loaded). **2026-07-28: it reported a clean Combat.gd that could not be `load()`ed at all** — a stray `var` left in the wrong `match` arm is a SCOPE error, resolved in a later pass than this runs. Note also that a syntax error MASKS semantic ones, so fixing a mangled token can reveal a second break further up the file.
- `--editor --quit-after 5 res://scenes/combat.tscn` force-compiles Combat.gd/Card2D.gd in the headless editor. **CAUTION (2026-07-17): it can silently pass on a broken script when the editor serves a cached compile.**

## Architecture

### Scene flow

`MainMenu → RUN SETUP (ONE screen: hero · banner · terms · START RUN) → MapView → Combat/Shop/Rest/Event/Recruit/Treasure/Wayside → Reward → MapView → ... → Combat (boss) → GameOver`

**The run opening is `MainMenu._show_muster_step(step)` and it is ONE SCREEN (redesigned 2026-09-14).** The `step` argument is now IGNORED and kept only so the probes and shot tools that pass it keep resolving. It was four steps walked in dependency order (host → banner → terms → review) from the 2026-07-31 split until the owner's verdict: "way overblown… several screens for no reason". **The SPLIT was the defect, not the content.** Four decisions do not earn a wizard — the form literature puts the break-even at seven-plus steps and calls the extra Next clicks pure overhead below that — and **Hick's law counts TOTAL options, not options-per-screen**, so spreading four choices over four pages reduced nothing while adding three clicks and a rail carrying eight strings of navigation chrome. Slay the Spire, the stated model, puts character + ascension + seed on ONE screen with the modifiers in a corner. **Two symptoms proved the split was load-bearing waste, and both are GONE rather than relocated — that is the test of whether a merge was real:** the deck strip was built THREE TIMES (step II's own comment said why: "a chip that says so while the opener is on another screen is a claim the player cannot check"), and **step IV existed only to restate steps I–III**, which is the standard tell of an over-split flow. `_build_muster_screen` lays three panes across one row — roster | THE COLUMN | banner chips — with THE TERMS full width beneath and the run controls in the footer; measured 730px inside the 780 rect, so the banner chips keep their full 270px width and every choice sits beside the thing it changes. All state still lives on the object and `start_new_run` is still called exactly ONCE, at START RUN. Gates: `tools/_probe_muster.gd` + `tools/_probe_menu.gd` + `tools/_probe_terms.tscn` + `tools/_probe_shellpass.gd` + `tools/_shot_runstart.tscn`.

**THE OPENER IS SHOWN AS PICTURES, NOT FACES (2026-09-14).** THE COLUMN used to print seven baked `Card2D` faces at `DECK_MINI_SCALE` 0.62. Card2D holds rules text at an **ABSOLUTE 18px floor** — `_fit_desc_to_box` refuses to shrink a glyph and would rather clip the card, COPY_STYLE §11 sets that floor, and `tools/_probe_text_floor.gd` fails the build below 14 — so scaling the NODE to 0.62 rendered that text at **11.2px**, and **no gate could see it, because the probe reads font-size OVERRIDES and a `Control.scale` is not one.** That blind spot is GENERAL: any scaled subtree defeats a size-literal check. The loudest ink on the screen was rules text nobody could read. `_make_opener_art_strip` now shows the WHOLE eleven-card opener as a 6-wide grid of art tiles instead of a seven-card sample — strictly more information at roughly a third of the ink — with the rules one gesture away twice over (hover floats the readable card, VIEW FULL DECK opens the inspector), which is the single level of disclosure NN/g's guidance allows before users get lost between levels. **Three rendering facts cost a render each and all three are general.** (1) `TextureRect.expand_mode` defaults to `EXPAND_KEEP_SIZE`, under which the node's minimum size is the TEXTURE's (768×512) — anchors never shrink it and `stretch_mode` does nothing, so the painting drew at 1:1 and the clip scissored a window out of its **TOP-LEFT CORNER**, which reads exactly like a broken image loader. (2) `STRETCH_KEEP_ASPECT_COVERED` does NOT crop by itself; it needs a scissor, and that scissor must be a WRAPPER node (`clip_contents` — a real scissor rect that works on gl_compatibility, unlike `CanvasItem.clip_children`) because anything else in the tile, like the ×N chip, would be clipped away with the overflow. (3) **Card art ships 3:2 LANDSCAPE** (768×512 / 1344×896 throughout `assets/creatures`), so tiles are built at that ratio: covering a 3:4 PORTRAIT tile with it crops to the middle 50% of the painting's width, and the middle of a painting is usually its background.

**Still true from the 2026-08-01 pass:** the ascension `−`/`+` pair is **not built at all below the first win** (`_build_muster_settings`), because a permanently disabled control beside live build offers is the one pattern no surveyed roguelike ships; `_update_asc_rules_text` still prints the promise and every `_asc_label` consumer null-guards. **THE ARSENAL previews the three relics it will actually offer** (`_writ_arsenal_preview`, reproducing `_pick_blessing`'s roll — `_muster_signature_relic` is the ONE writer of "which relic is already held", so the preview cannot drift from the deal). The PACT is dealt into the slot BESIDE its twin and carries no numeral. The six banner cards carry art aliases.

**PLAY AGAIN (the rematch) goes through THE MUSTER, and must.** `_start_rematch` used to call `_begin_run_with` directly, skipping the only two things `_show_hero_select` does that a run cannot start without: it rolls `_muster_random_seed` (whose declaration default is 1 and which is randomised nowhere else — so **every rematch on every profile ran seed 1**, the same act 1 map and rival deal forever) and it deals `_muster_writ_slate` (so `chosen` came back empty and the rematch **silently forfeited the whole terms step**). It now restores the picks into `_muster_setup_preset` and calls `_show_hero_select(3)`, landing on THE TERMS one click from the field. `_probe_muster` asserts `_begin_run_with` has exactly one call site.

Scene transitions use `get_tree().change_scene_to_file()`. Each scene is a `.tscn` in `scenes/` with a matching script in `scripts/scenes/`. The whole run-opening flow runs from MainMenu before the first map appears, building UI programmatically over the menu background. **THE TERMS is dealt by `scripts/data/WritDB.gd`** — one tile from each of four fixed ROLE slots (I·ROLL the deck / II·ARSENAL choose-1-of-3 relics / III·PURSE the road / IV·PACT the price), so the player is never asked "which currency is worth most?" but "which axis of my run do I want moved?". Curses, boss relics, lump sums and SKIP are all permanently banned from the opening, each for an audited reason recorded in WritDB's header. **The three FREE tiles must stand on three DIFFERENT axes** — the pact doubles one by construction, so a fourth collision makes the row unreadable; THE PURSE was quietly a second ROLL (it granted `collectors_tome` and `whetstone`, both deck power) until 2026-08-01 and is now four road verbs, one each: BUY · SELL · EARN · MEND. Every pact must buy 1.00–2.00 "forges" over its own free twin (the road already prices one forge = two potions = ~90 gold = one common relic, via `Treasure._run_arsenal` and `Shop`), because the old spread ran 0.75–3.5 for one fixed price and made the loud tile dominated on half the deals and automatic on the other half. Gate: `tools/_probe_terms.tscn` reads the four dealt descs the way a player does and audits every granted relic against **RelicDB's own desc**, so the slot label cannot be made true again by rewording a tile. The menu column itself is 7 items max (CONTINUE / NEW RUN / SKIRMISH / COLLECTION / HOW TO PLAY / SETTINGS / QUIT, + LOAD GAME only when 2+ slots are filled); daily run and custom seed live inside run setup, not the column. GameOver's PLAY AGAIN button sets `RunState.rematch_request` and MainMenu consumes it on ready, opening RUN SETUP with the same hero/banner/doctrine/ascension already restored — one screen, so a rematch is a single press of START RUN.

### Autoload singletons

- **RunState** (`scripts/state/RunState.gd`) — current run state: HP, deck, relics, gold, potions, map data, card upgrades, `phoenix_heart_consumed`. `start_new_run()` delegates deterministic topology/content creation to `scripts/campaign/CampaignMapGenerator.gd`; RunState retains persistence and `get_current_act_map()` / `get_available_nodes()` / `visit_node()` navigation. Card upgrades are tracked by `deck_uid`.
- **HeroDB** (`scripts/data/HeroDB.gd`) — 5 playable heroes (Raider/Stalwart/Acolyte/Pyromancer/Kindler). Each entry has `deck` (10-card list of CardDB ids) and `relic` (id of a `tier:"starting"` RelicDB entry). Picked at the start of every run from MainMenu — replaces the old "pick 1 of 3 starting relics" screen. **The starter contract (2026-07-06 progression pass): hero decks use ONLY starter-rarity cards** (the original 8 + the levy set Outrider/Palisade/Mourner/Spark; Kindler's plain doom commons are the sanctioned exception) — never seed a hero deck with pool commons/uncommons, that's what flattened the run's power curve. Drafted cards must always outrank the opener. Generals additionally offer a chosen "+" forge on the Reward screen (The General's Forge), and Recruit slates richen gently by act (65/30/5 → 55/38/7 → 45/42/13 c/u/r; flattened 2026-07-16 — commons stay the majority of offers every act, rares stay events; late-run power comes from c4+ pieces/tribes/forges, not rarity inflation. Same pass: 10 tribe-glue uncommons demoted to common and 6 vanilla commons added, one per tribe — see CardDB's rarity-floor block). **Cross-run muster unlocks (2026-07-04, options not stats)**: `relic_alt` (choice of signature relic, unlocked by the hero's first win) and `deck_alt` {name, tagline, deck} (alternate 10-card start, a 2-3 card swap on the default; unlocked by a win at Ascension 4+). The run-setup detail pane shows them as toggles (locked = dim hint lines); MainMenu hands the picks to `RunState.start_new_run` via `pending_signature_relic` / `pending_deck_variant` (consumed + cleared there). **THE MUSIC CROSSFADE IS EQUAL-POWER, AND IT MUST STAY THAT WAY (2026-09-14) — [`docs/MUSIC_SYSTEM_AUDIT_20260914.md`](docs/MUSIC_SYSTEM_AUDIT_20260914.md).** The fade was two parallel `tween_property(player, "volume_db", ...)` calls, which interpolate LINEARLY IN DECIBELS — so mid-fade both tracks sat at −20 dB, a tenth of amplitude each, and two tenths are not a whole. **Measured on the real assets** (map.mp3 → combat.mp3, the shipped 1.0 s, RMS per 100 ms): steady state −13.2 dBFS, mid-fade **−34.4 dBFS**. A 21 dB dropout in the middle of every transition, ~108 times a run (18 rows × 2 transitions × 3 acts), and it read as "the music sounds weird" rather than as a defect. `_crossfade_step` now runs `sin`/`cos` so `in² + out² = 1`; **the conversion order is the whole trick — the law is defined on AMPLITUDE and the player takes DECIBELS**, so the sine is computed first and converted after, and running the curve on `volume_db` directly is the bug every Godot fade tutorial teaches. `linear_to_db(0.0)` is `-inf` and a non-finite `volume_db` write silently ABORTS its function, hence the `FADE_FLOOR_DB` clamp. One tracked `_music_tween`, killed on entry, because two fades writing the same two properties leaves the loser driving a player the winner just started and its trailing `stop()` kills live music. Gate: `tools/_probe_music_fade.tscn`. Same pass put an `AudioEffectHardLimiter` on Master (`UserSettings._install_master_limiter`) — the buses were built at runtime with **no effects at all** while six library tracks are mastered above 0 dBTP and 12 SFX voices summed unwatched. **THE ROAD'S MUSIC IS A THEME, NOT A ROLL (2026-09-14, same pass).** `play_music_random` EXCLUDES the currently-playing track, so any screen re-rolling its pool on entry is GUARANTEED to change track — and MapView did, on all ~18 chart returns an act. No road theme was ever heard twice running in any run, so none was ever learned, and each forced change also paid a crossfade: **the anti-fatigue feature was the cause of the fatigue.** `AudioBank.play_music_theme(key, pool)` draws ONCE per key and holds; **key namespaces are load-bearing** — `clear_music_themes()` (called from `RunState.start_new_run`) drops only `run:*`, so road themes re-roll per march while the menu keeps one voice per session. `play_road_theme(act)` over the `ROAD_BOOKS` const is called by BOTH `MapView` and `Wayside` — a wayside is a stop ON the road, so asking for the road theme resolves to what is already playing and `play_music` no-ops, which is the entire mechanism (it used to crossfade into the EVENT book for a ~20s decision and back, ~36 needless transitions a run). MP3 is gone, which also removes the loop seam (encoder delay + padding, no standard way to record them; Vorbis trims on decode). The MP3s live at `HEAD`, so `git checkout -- assets/audio/music/` reverts the swap. **`_resolve_music_path` tries `.ogg` before `.wav` before `.mp3`, so an `.ogg` beside an `.mp3` of the same name SILENTLY WINS** — handy for auditioning, a trap if you forget the loser is on disk. **Static gain cannot fix a track that is quiet AND peaky** (the peak hits the ceiling before the average reaches target) — four were (`map_b`, `event`, `map_act3`, `map_e`) and the first pass backed their gain OFF, leaving three QUIETER than they started. They were re-done **from the originals recovered out of `HEAD`, never from the OGGs** (that would stack a second lossy generation) with a look-ahead limiter ahead of the gain: 2.2–4.2 dB of peak reduction costing at most **0.5 LU of loudness range** (three of four cost 0.1), which is the number that separates mastering from damage. A SECOND pass was then needed, and its cause is the reusable lesson: the gain-only path computed headroom from the **INPUT's** true peak and never re-measured, but **Vorbis overshoots true peak**, so seven more tracks (`combat_act1_d`, `defeat`, `event_c`, `event_wry`, `rest_b`, `rest_c`, `rest_d`) encoded ABOVE the ceiling — and six of them carried the note "gain reduced to hold −1.5 dBTP", i.e. they were the ones the arithmetic was supposedly protecting. **A prediction is not a measurement**; the limiter path was correct only because it iterates on the MEASURED output. Now every path does. **FINAL: spread 13.9 → 0.53 LU, every track between −16.50 and −15.97 LUFS, worst TP −1.50 dBTP, 6 → 0 clipping, all 17 pools inside 0.5 LU, 446 → 215 MB, mean LRA cost −0.04 LU.** The limiting is in the tool, applied only where needed; `MAX_LIMIT_DB=0` restores gain-only; >5 dB is flagged as wanting replacement not processing; `SRC_DIR=` points it at originals recovered from git. **Three traps:** `alimiter`'s `level` defaults to TRUE and auto-normalises to 0 dB, silently discarding your gain staging — must be `level=false`; it measures SAMPLE peaks, so its threshold sits at −2.0 dB for inter-sample headroom; and **crest factor is NOT an independent quality oracle** — it falls by exactly the peak reduction by construction, so judge the ABSOLUTE crest (these land 16–17.6 dB where commercial masters sit at 8–12) and use LRA for the real signal. Reproducibility is checked by **decoded PCM, never file hashes** — Ogg bitstream serial numbers are randomised per encode.

### Map system

CampaignMapGenerator (called by RunState) generates a branching map per act: 18 rows tall × up to 7 columns wide, 3 paths with a 3× merge bias (trunk road + branches). The act is a fixed **row skeleton** (Kaycee's-Mod model; lengthened 2026-07-07 from 12 rows / 5 combats — the act ended in 3-4 fights, too short for the deck/veterancy/relics to snowball): fight rows (`FIGHT_ROWS [0, 3, 15]`, elite bands at `ELITE_ROWS [6, 12]`) alternate with PAIRS of wayside rows, so every between-fight gap is exactly two non-fight stops (Inscryption cadence) dealt from event / wayside verb / recruit / shop / treasure; `MID_REST_ROW = 9`, `REST_ROW = 16`, `BOSS_ROW = 17`. **THE FIGHT COUNT IS A DECISION NOW, AND UNTIL 2026-09-19 IT WAS NOT (`tools/_probe_fight_count.tscn`).** This paragraph used to say "fight count per route is constant by construction — 7 combats" and treat that as a feature; measured, it was **min 7, max 7, span 0, in 180 of 180 acts** — 21 a run against Slay the Spire's ~16 and Monster Train's 8, with the chart carrying no choice at all about how much of the run was combat. **The cause was structural rather than tuning**: a fight row is a ROW and the player walks one column of every row, so a row that is combat in every lane is a fight nobody can decline — and the war-road fork, which the old text sold as the StS elite-hunt trade, changes WHICH fight and never HOW MANY. Two changes, both gated: the mandatory spine dropped to **three** plain rows (row 9 became the mid-act camp), and an elite band is now **one spike with road in every other lane** rather than a fight row with a General on it, so a General can be walked past. Measured after: **min 12.1 / max 17.8 / span 5.7 a run, 2% of acts forced** — a mean route of ~15, i.e. a 29% cut that brackets StS. The war road survives unchanged as the *composition* choice on a mandatory row (`_war_road_ok` still rejects lattices where the fork couldn't land, and was tightened from "ANY band is ≥2 lanes" to EVERY band, since a width-1 band is now an undeclinable General). **Gold was re-denominated in the same pass** — 50/70/65 → 65/90/85, a percentage rather than the flat adjustments above it, because what changed is the NUMBER of payouts while the shops/musters/wagons that spend them sit on wayside rows whose count did not move; leaving it would have cut buying power ~23% against an unchanged number of places to spend. **The second camp is the `docs/PLAYTEST_MEASUREMENT_20260919.md` §10 fix**: StS runs ~2.6 rests an act plus a full heal at every act boundary, we shipped the guaranteed pre-boss rest ALONE, and the measured recovery was +1.0 HP against a 6.1 HP bill a fight. Route census after: rest on route **1.00 → 2.00** per act. **Trap paid for here:** the verb pass that gives a halt its `wayside_id` walks `wayside_rows`, which does not contain the elite rows — so the first draft of the bypass dealt waysides with NO VERB, i.e. a stop the Wayside scene opens with nothing to run. `_probe_wayside`'s "every wayside halt carries a verb" caught it; the loop now walks `wayside_rows + ELITE_ROWS`. One Reliquary (R7) and one Arsenal (R13) and two musters (R4, R10) ride the longer road (the Reliquary is the fixed relic-bearing stop; the Arsenal pays Forge/potions/gold). ### Card upgrade system

Slay-the-Spire-style **"+" upgrades**: every draftable card has one hand-crafted upgraded version. Rest sites offer the "Forge +" action — the player picks a card, sees a before/after preview, and confirms. No path picking, no random rolls. Camp also offers **Hold a Wake** (2026-07-04, only when the Roll of the Fallen has names): pick one fallen soldier; its shade (folded stats while the card still marches, printed stats if mustered out) opens the NEXT fight in front-left via `next_combat_gift_creature` — a real 3-way camp fork (heal / forge / wake), and since camp sits right before the keep, the wake usually arms the boss fight.

**Veterancy ladder** (solo campaign memory, `RunState.creature_kills` per deck_uid) — **the choosing rungs moved FORWARD 2026-07-30** because the old single choice sat 10 kills away and most runs never saw it: **3 kills = epithet ("Pikeman the Grim") AND the war school** (Armored / Swift / Thorns, a `war_school` mod entry), **6 = +1/+1**, **10 = the TRIBE DOCTRINE** — a second chosen keyword drawn from the creature's own `ctype` pair in `Combat.WAR_DOCTRINES` (soldier formation/guardian · beast charge/overrun · dead last_stand/lifelink · warlock piercing/poison · bastion regenerate/guardian · stray sniper/rampage), written as a `doctrine` mod entry. Both modals fire at the top of the next player phase, both have a round-1 catch-up sweep (which doubles as the migration path for live saves), and both auto-pick the first option headless so probes/autorun never stall. **`RunState.veteran_school_kills()` is deliberately an ALIAS of `veteran_epithet_kills()`** — that one function is how the rung moved without touching thirteen call sites; `veteran_doctrine_kills()` inherited the old threshold and the drill_book shave. Every doctrine keyword is drawn from `Combat.DEFECTION_STEALABLE`, the project's already-vetted list of grantable keywords, and none repeats a war school. Verify: `tools/_probe_progression.gd`.

- Per-card upgrade deltas live in `CardDB.UPGRADES` (atk/hp/cost/value/keywords/sub-effect bumps, plus optional desc override). `CardDB.get_plus_upgrade(id)` returns the delta; `CardDB.is_upgradeable(id)` filters out curses.
- The upgrade is applied by `RunState._apply_upgrade` via the `"plus"` path → `_apply_plus_upgrade(data)` merges the delta into the card data and stamps `is_upgraded: true`.
- Custom-spell resolvers in `Combat.gd` read `dmg_bonus`, `slay_draw`, `extra_draw`, `extra_mana`, `ricochet_hits`, etc. from the merged card_data, so + versions actually hit harder / draw more / give more mana.
- A handful of creature passives (Royal Guard, Corpse Eater, Vengeance, Vampire Lord, Riteforge, Warchief) read `card_data.is_upgraded` directly and bump their tick value.
- Specialty upgrade paths — `butcher` (now granted by the War Chest's "Butcher's Kindness" opener), `mirror_twin` / `fortify_neg` (legacy — their events were cut in the 2026-07-03 pool remake; the arms stay so old saves fold) — keep their dedicated paths in `_apply_upgrade`. Events also write the wayside `grant_kw` path: the Old Drill Master (event id `the_lame_master`; renamed from "The Pensioned Master" in the 2026-07-18 prose pass) teaches a chosen creature Armored/Swift/Thorns permanently.

Mods are tracked in `RunState.card_upgrades` keyed by `deck_uid` — **each value is an ordered Array of mod entries (Inscryption stacking model)**: a card can be drilled, carry a transferred keyword, AND be forged; entries fold in the order earned. The "+" forge is the only once-per-card path — `has_upgrade_path(i, "plus")` is the forge filter; `is_card_upgraded(i)` now means "carries any mod"; the " +" name suffix marks the forged state only. `get_upgraded_card_data(uid)` returns the folded data. **Upgrades are applied at draw time in Combat** via the `deck_uid → card_data` lookup — drawing a card looks up its uid and uses the upgraded data dict. Legacy single-entry saves are shape-migrated (wrapped into arrays) on load.

The Whetstone relic upgrades the "Reforge" rest banner to forge **two** cards instead of one (once per act).

**EVERY PERMANENT CHANGE TO A DECK CARD PLAYS A BEAT (2026-08-28).** The forge had `Motion.forge_strike` (Camp, the General's Forge); four other surfaces changed a card and showed the player *nothing* — the screen simply rebuilt with different numbers on it. `Motion.writ_amend(host, card, stamp_text, accent, opts)` is forge_strike's sibling and the shared beat for them. Its five stages are the standard juice grammar, each earning its place: **anticipation** (the page dips and dims for 90ms before it is struck — the wind-up is what separates "a thing appeared" from "a thing happened"), a **specular shine** (a tilted band crossing the card, drawn by a `canvas_item` shader on a child ColorRect in `blend_add` — the Balatro-foil setup, effect on a child rect never on the card's own material; layered trig gives the iridescent fringing and a white-hot core carries the CLAUDE.md contrast rule), then **contact**: a two-frame **impact frame** (the card blown to near-white — hand-drawn action animation's trick, one ColorRect, sized to the SQUASHED rect and centred on the pivot or its own corners stick out past the writ), a **squash** snapped on with no tween (a squash you can watch travel is a wobble), **two rings** (a thin fast shock ahead of a slow heavy swell — one ring reads as a bubble), sparks and a shake; **~70ms of hitstop** that simply refuses to start the settle; then the **settle** with embers lifting off the drying ink. Wired at the **drill yard** (+1/+1 per pass), the **standard-bearer** (the pinned keyword, on the taker's own tile), the **Arsenal** (whose forge called `show_deck_picker` → `upgrade_card` → `change_scene` in one frame and is now a `forge_strike` on a shown "+" card, `Treasure._show_forged_card`), **Event's forge + `grant_kw` pickers**, and **both veterancy rung modals**. Three rules the build cost: (1) **the stamp strikes the ART, not the card's centre** — dead centre on the v9 writ is the name cartouche, so the first version printed "+1/+1" through the creature's own name and "GUARDIAN" over a cream rules box; (2) **the word is fitted to the card width**, or a long keyword lands across the two neighbouring tiles as well; (3) the stamp is INFORMATIONAL so it still lands under Reduce Motion (settled, held, faded) while the lift/sweep/sparks/thump gate off. The drill yard's recruit is now a node that **survives `_clear_ui`** (`_drill_card`, freed by `_drill_dismiss` at every exit) so each pass stamps a card the player was already watching; its tiles carry a `_drill_busy` latch, because the beat is awaited with both tiles still live (Event's pickers got the same, `_picker_busy`, cleared in `_make_card_picker_grid`).

**A PICKER GRID IS BUILT BEFORE THE MUTATION**, so the clicked tile still prints the OLD numbers when the stamp lands on it — `Event._refresh_pick_tile(idx)` re-bakes that one writ from post-mutation data first (keeping the click catcher, which carries the hover lift), or "+2 HP" strikes a card the player can see says 4. Wayside's drill yard solves the same problem by swapping the writ inside the persistent wrapper. **Both veterancy rung modals now stand the veteran's own card in the overlay** (`_rung_overlay_writ` / `_rung_overlay_writ_strike`): they used to name the veteran in a title and show nothing but two keyword tiles, and the overlay no longer frees itself on the click — the lesson is struck onto the writ first, then the screen closes (one-shot `acted` latch on the tiles). Both modals also **moved onto their own CanvasLayer at 100** (the pile-viewer/glossary convention): parented to `self` they sat on the base canvas at layer 0, so the HUD (12) and the hand (20) drew straight over a modal that was blocking input — **`z_index` cannot reach across a CanvasLayer**. Eyes: `tools/_shot_writ_amend.tscn` (18 frames across all five surfaces + a same-instance assertion across two drill passes).

**THE IMPACT KIT — `Motion.impact_frame` / `shock_rings` / `foil_sweep`** were extracted out of `writ_amend` so every card moment speaks one language, and **`forge_strike` was rebuilt on them** (it had the flash and the anvil sparks but no wind-up, no squash and no hitstop, so the loudest card moment in the game was landing softer than its quieter sibling; it stays the BIGGER of the two — heavier squash, wider rings, full-weight shake, ~0.72s). **`rarity_reveal` gives a RARE the foil sweep** across the card itself — the halo says "the slate rolled well" from outside, the foil says it about the card; uncommons deliberately don't get it, because two tiers of shine is one tier of noise. All three primitives gate headless themselves; Reduce Motion stays the caller's branch. A `foil_sweep` on a target whose scale is mid-tween photographs as nothing — the settle is BACK-out and ~85% home within 0.16s, so shoot the hitstop, not after it.

### Card2D (`scripts/Card2D.gd`)

PanelContainer-based card (~4,600 lines after retiring alternate renderers). `CreatureInstance` owns typed gameplay state and versioned save/network snapshots; Card2D is its input/render adapter. **The writ-kit painter classes (WritLeaf, InkCartouche, WaxSeal, StatCaret, ParchmentPlate, TallyMarks, EmptyPlateSigil, WritDetailDiamond, PolyBadge, StatGem) live in `scripts/ui/painters/`** (extracted 2026-07-14), preloaded as same-name consts so `Card2D.WaxSeal`-style references still work; new diegetic painters belong there, not inline. Supports creatures (ATK/HP display) and spells (SPELL label, no stats). Drag from hand above play threshold to play. Battlefield creatures show floop indicator. `take_damage()` handles Armored and Last Stand. `temp_atk_buff` for this-turn buffs; `persistent_atk_buff` + `persistent_atk_buff_rounds` for multi-round buffs (Butcher's Cleaver). `effective_atk()` is the canonical "what's my real ATK right now" — always prefer it over raw `current_atk + temp_atk_buff` reads.

### Card data schema

Creatures: `id, name, type:"creature", cost, atk, hp, rarity, keywords[], desc`. Optional: `on_enter{}, on_death{}, floop{}, adj_buff{atk,hp}, wither:int, passive:String, extra_damage:int`. **Every draftable creature carries a `ctype`** (2026-07-10; system remade 2026-07-15 — see [`docs/TYPE_SYSTEM_DESIGN.md`](docs/TYPE_SYSTEM_DESIGN.md)): **SIX tribes** (expanded 2026-07-15), each with a payoff keystone: `soldier` (ENDURE — line/formation; keystone Warden-Sergeant `warden_line` → full front row grants Soldiers Armored+Thorns, in `_apply_start_round_passives`), `beast` (ARRIVE — on-enter reach/aggro; Bloodmoon Alpha `beast_encore` → a Beast's on-enter fires twice, via `_maybe_beast_encore` at every on-enter dispatch site), `dead` (DIE — the death spine; Gravepact `reap_on_ally_death` → a Wight per friendly death, in `_apply_ally_death_passives`), `warlock` (SPELLCRAFT — casters; Coven Mother `coven_spell` → Warlocks +1 ATK/fight per spell, in `_record_spell_cast_board_payoffs` + its CombatNet mirror), `bastion` (SIEGEWORKS — walls + siege; Siegewright `bastion_ramp` → Bastions +1 ATK/round, in `_apply_start_round_passives`), `stray` (the MASTERLESS — rogues/mercs/shapeshifters; MOBILITY + LARCENY since the 2026-07-24 rework that retired the old gold spine — keystone Free Company Captain, id `kingpin`, carries `defection`: on killing an enemy creature it loots one of that corpse's keywords as a persistent grant (`DEFECTION_STEALABLE`) or free-redeploys when there's nothing worth taking, and while it stands every other friendly Stray free-redeploys on a kill — `_stray_defection_active` / `_resolve_defection`, hung off `_apply_combat_strike_riders` host-side with NO `_is_net` guard, so larceny is skirmish-safe. No pool card carries `per_gold` any more). Effectively no untyped creatures remain. The old `engine`/`zealot` tags are GONE. The tag prints as the letterpress footer and is read by `type_buff {ctype, atk}` (Warchief — state-derived aura in `Combat._get_type_buff_atk`, rides `adj_atk_buff` + the net snapshot) and the `buff_ctype_keyword` on-enter (Siege Golem — retyped Bastion 2026-07-15 — grants its fellow **Bastions Thorns**). **The 2026-07-15 interest slate** (18 boring cards replaced, ids kept — verify `tools/_probe_interest_slate.gd`) added per-tribe texture: `buff_per_ctype` / `per_ctype` breath (Beast arrive-scaling), `buff_ctype_hp` (Warding Stone fortifies Bastions), the c1 wall cycle (Iron Rampart `reflect_strike` — reflects ACTUAL HP lost even on death, via `_apply_struck_passives`; Bramble Stockade `anvil_spawn`), the voltron pair (Oathbound Squire `bodyguard` + Honor Guard `column_ward` — both state-derived column wards refreshed in `_refresh_adjacency_buffs`, read in `Card2D.take_damage`; kill-convention 99+ damage bypasses both), Tallow Doll's `betray_opposing` (the opposing enemy strikes its own nearest ally, or its own face when alone — `_resolve_tallow_betrayal`), and spellcraft/potion payoffs (`spark_on_spell`, `shield_on_spell`, `tonic_vigor`). **Doom** stays a keyword sub-engine feeding Dead. Verify `tools/_probe_type_audit.gd` + `tools/_probe_type_keystones.gd`. Discover finds enter the hand costing 1 less (never free — floored at 1) (`_add_discovered_card_to_hand`, ephemeral). Unholy Bargain's end-of-turn bill = `_bargain_bill`, paid at the solo commit (card is skirmish-denylisted).

Spells: `id, name, type:"spell", cost, rarity, keywords[], desc, spell{type,value,...}, targeting:String`. Targeting: "enemy_creature", "friendly_creature", "any_creature", "any", "none". Untargeted board spells may carry an optional `scope` string ("ALL ENEMIES", "ALL CREATURES", "ENEMY FACE") — it prints as the contract on the card face's one-line footer (`Card2D._spell_footer_text`: "{contract} · {EXHAUST|RETAIN}"; the type word "SPELL" prints only as the fallback when there's nothing to declare — a grid of spells repeating the prefix was noise). Keyword words in rules text are gilded + carry the `[hint]` hover glossary (`KeywordEffects.decorate_keywords`); its inline device stamps exist but are OFF behind `KeywordEffects.INLINE_KEYWORD_STAMPS` until an icon set legible at 13px lands (flat bold silhouettes — painted icons mush below ~20px). The old bottom-margin roundel row is retired on hand cards (2026-07-10). Creatures have NO footer by design — the footer is a casting contract; add a creature type line only when a mechanic reads it (faction tags would live there).

### Adding content

- **New card**: add to `CardDB.CARD_POOL` (include all fields per schema above) AND add a `CardDB.UPGRADES` entry for its "+" version. **It also needs ART** — a file at `assets/creatures/<id>.png` (or `spells/`) or an entry in `CardArtAliases.ALIASES` / `SPELL_ALIASES`, or it renders the line-art stand-in: a blank writ with a thin gold glyph, which in a shop row beside four paintings reads as unfinished. `tools/_probe_card_art.tscn` (headless) lists every playable card that resolves to it — it was 16 on 2026-08-28 and is 0 now. **Armaments take the SPELL loader**, because `Card2D._find_card_art` gates on `is_spell() or is_armament()`; a probe that checks only `type == "spell"` reports six well-aliased weapons as artless, and re-adding them is a duplicate dict key, i.e. a parse error. Missing UPGRADES entries get a default fallback (+1/+1 creature or -1 cost spell) so they still upgrade cleanly, but hand-crafted entries feel better. ## THE COACHING SYSTEM (2026-09-10) — the tutorial, its skip, and its replay

**Reasoning, sources and the rejected options: [`docs/ONBOARDING_20260910.md`](docs/ONBOARDING_20260910.md).** This section is the operational summary.

`scripts/ui/TutorialCoach.gd` is the LAYER (spotlight scrim with punched holes, breathing rims, pointing arrows, the drag arc, the step panel — layer 30, above the hand at 20 and the HUD at 12). `scripts/data/TutorialDB.gd` is the REGISTRY: **22 lessons, one dictionary entry each, and everything else derived from it.** Before the registry the teaching was six hand-rolled `_maybe_show_*` functions inside Combat.gd, and that shape had three faults the player paid for: the copy was unlistable and unshowable ("how do I see that again?" had no answer but a new profile), a flag was spent once ever with no way to un-spend one, and **nothing could count them** — so six lessons covered the first fight and nothing else in the game, and the omission was invisible because there was no list to compare against.

- **THE SKIP IS `UserSettings.coaching_mode`** (Settings › Coaching): **FULL** / **TIPS ONLY** / **OFF**. Three settings, not a checkbox, because the commonest returning-player state is "I know deckbuilders, I don't know THIS one" — TIPS ONLY drops the guided walkthrough and keeps the one-line rules that are peculiar to Burning Meadow (the muster, banking, overkill), which are exactly the rules a genre veteran otherwise mistakes for bugs. **`TutorialCoach.should_teach(id)` is the ONE definition of "off"** and every teaching site asks it; a `KIND_STEP` additionally requires FULL. The walkthrough also carries an in-panel `SKIP TUTORIAL` (named, not an X — NN/g), answers **Esc** (narrowly: only while a panel with a visible skip is up, so the pause menu keeps Esc everywhere else), and both endings state where the coaching went — a note on step 1 before the decision and an info line after it. **A skip whose content is unrecoverable is a trapdoor, not a skip.**
- **THE REPLAY IS PER-LESSON.** HOW TO PLAY grew a **COACHING** tab beside the primer: every lesson printed in full, ticked SEEN / NOT YET SEEN (a word, not a colour), each with SHOW AGAIN. **`make_how_to_play_overlay(open_tab)` takes 1 to land on that page directly**, and Combat's `?` panel has a **LESSONS** button that does exactly that — the list was reachable only from the main menu and the map, i.e. never at the moment a player is actually confused. That button forced the FIELD CARD's action row into **two rows**: four 124px buttons need 520px inside a 414px panel. `UserSettings.replay_lesson(id)` un-spends one; Settings' REPLAY ALL un-spends everything. **The replay button is offered once per distinct underlying flag**, keyed off `legacy` rather than a hand-listed set — which is why the three walkthrough steps share one button (a walkthrough is one thing; you cannot have seen step 3 and not step 1).
- **SAVE COMPATIBILITY IS THE `legacy` KEY.** The nine pre-registry lessons keep their own named `UserSettings` properties and are reached through it; everything since lives in the `lessons_seen` dictionary. A lesson that forgets its mapping would re-teach a rule the player was taught weeks ago. `_probe_tutorial` asserts every `legacy` name is a real property, because `get()` on a name that does not exist returns null — which reads as false forever AND can never be set.
- **COVERAGE went from 6 lessons to 22.** New in combat: `back_row` · `keywords` · `spells` · `relics` · `potions` · `overkill` · `hero_hp`. **`back_row` is a design-rule repair, not just coverage**: the walkthrough's own lane step used to say the back row "waits behind" the front, which teaches that four of your eight slots are a bench — the house rule is that the back row is play space and BOTH rows strike every round. The step was rewritten and `back_row` now fires at the decision point (the first time the front row fills, or the first body placed back there). New outside it, one per screen: `map_road` · `map_gate` (MapView) · `recruit_card` (Recruit — **not** the post-fight spoils screen; Recruit is the only place a card enters the deck) · `shop_trade` · `camp_choice` · `event_choice`. **Every one fires the first time its subject is ON SCREEN, not on a fixed round** — a tip that points at nothing is worse than no tip, because it is stamped seen the moment it fires. The two clash-shaped lessons latch instead (`_arm_overkill_lesson` / `_arm_hero_hit_lesson` set a bool inside the clash; the round ladder cashes it in on the next player turn, with the board that produced it still standing).
- **THREE GATES.** `tools/_probe_coach_a11y.tscn` (660 checks) is the newest and the only one that judges the LAYER rather than the lessons: reduce-motion must HOLD not remove, no colour-only signal, the panel must stay on-canvas and cover the full canvas at UI Scale 1.0 / 0.85 / 0.6 (the C32 class), the panel must never sit on its own spotlight, and focus/Esc must behave. **It found a defect the placement code's own header claimed to have fixed:** `_place_panel`'s four candidates are all-or-nothing at the panel's preferred width and the fallback was accepted UNCONDITIONALLY when they all failed — so a TALL spotlight (the lane column is ~632px of a 900px canvas, leaving no room above or below and side gutters narrower than an 820px panel) parked the copy squarely on the two creatures the sentence compares. The header had fixed the candidate ORDERING and never the "nothing fits at all" case. Fix: narrow into the roomier gutter down to `MIN_PANEL_W` (420), re-measuring height because the body rewraps — a narrow panel beside the thing beats a wide panel on top of it. **`_probe_occlusion` (C28) then caught the other half of the same rule**: the keep-out was only ever the SPOTLIGHT, so on any screen with prose OUTSIDE it the panel was free to bury that prose — it sat on Recruit's season subtitle at 63% and its GOT IT button at 67%. `_place_panel` now also scores `_host_text_rects()` (walked LIVE off the host, skipping `self` and nested CanvasLayers) via `_buried_area()`, and — the part that actually fixed it — offers a **LADDER of fallback heights** (0.06/0.18/0.44/0.58/0.70 of canvas). Two earlier attempts failed with BYTE-IDENTICAL overlap percentages, which is the tell that a decision procedure is being handed exactly one option: Recruit's spotlight is the card row in the MIDDLE, so all four side candidates were rejected and "least-worst" had nothing to choose between.
- `tools/_probe_tutorial.tscn` (in `run_safe_probes`) is STATIC — C1 reachability both directions, the copy contract, unresolved `{tokens}`, the legacy mapping, the seen/replay round trip, and that OFF silences everything. `tools/_probe_tutorial_live.tscn` (71 checks) is EMPIRICAL and answers what the static one cannot: it boots a real fight AND all five road screens, and requires each lesson to actually LAND, because a lesson gated on `_relic_chip_by_id` or `_potion_bar_root` can be perfectly wired and still never open — the C20 content-census lesson. **`lesson_seen` is NOT a sufficient oracle and the probe no longer treats it as one**: `teach()` stamps a lesson seen even when every target it was handed resolved to nothing, so each screen must now report what it actually LIT (the camp's banners are found by SHAPE, never by the name the lesson looks them up under — an oracle repeating the lookup it tests only agrees with itself). It carries a `_MUTANT` harness that sabotages one screen on demand; it ships disarmed and prints a banner when armed, and two mutants ESCAPED on their first run because Recruit and MapView build ASYNC — a mutation applied at `add_child` time is overwritten by the build that follows, so it re-applies every poll frame. **A mutant that does not mutate is the same false green as a probe that does not probe.** Eyes: `tools/_shot_tutorial_manual.tscn` (the manual + the settings row), `tools/_shot_tutorial_tips.tscn` (the guided fight), and **`tools/_shot_coach_devices.tscn`** — 22 frames of the DEVICES themselves, including **nearest-neighbour ZOOMS**, because a 2px rim and an 8px seam are not decidable at 1600×900. It settles on the coach's panel-rect + hole signature rather than a whole-screen fingerprint (the board's idle bob is ±3px forever, so a full-screen hash never holds) and prints each arrow's tip, direction and measured standoff from the target's ROTATED edge. **Judge the shine by these, never by the 1600×900 frame** — the craft pass that produced them found the arrow rendering with no white pixels at all and the glow reading as a uniform tube, both invisible at 1:1, and its own first filament attempt failed because at 0.40 of a 2px rim the white band was 0.8px and a pixel centre almost never landed inside it.
- **THE LAYER FACT, unchanged and still true:** combat FX are parented to `_hud_layer` (12) and **z_index cannot cross a CanvasLayer**, so the coach's scrim dims every effect that does not fall inside a punched hole. That is right for "drag this card there" and wrong for any step that asks the player to WATCH something happen. If a future step needs an effect visible, punch a hole over the FX corridor or drop the scrim for that step — do not move `_hud_layer`.
- **What was deliberately NOT built**, from the research pass: no skip-prompt before the first fight (it asks a question a first-timer cannot answer, and front-loads the decision NN/g's own study penalises); no confirmation dialog on skip (reversible actions get recall, not confirmation); no feature-locking of the shell for run 1 (Hearthstone does it and it is defensible, but it is a menu-structure change, not a tutorial one). The 7-second tip hold is a known tension with WCAG 2.2.1 — it is a shared channel that must be released — and the Field Manual is the mitigation.

- **THE HAND: ONE CIRCLE, AND A CUE MADE OF LIGHT (2026-09-17)** — `Combat._layout_hand` + `Card2D`, eyes `tools/_shot_hand_fan.tscn`. Two defects, one root. **(1) THE PLAYABLE CUE WAS DISPLACEMENT AND IS NOW LIGHT.** Affordability shipped 2026-09-16 as a 16px lift + 1.06 grow ("a card you can pay for stands proud of the fan"); the intent was right and the CHANNEL was wrong, and the numbers say so without appeal to taste — **the fan's entire edge-to-centre sag was 12.8px at five cards, so the affordance was an informational offset LARGER THAN THE STRUCTURE IT PERTURBED, on the same axis.** The smooth arc a hand is read by became a cost-keyed SAWTOOTH, and the grow made neighbours different sizes on top of it: the cue was destroying the shape it existed to be read against. **The rule, not the number — an informational offset must be small relative to the structure it rides, or must use a channel that structure has no claim on.** The layout is untouched now; affordability takes light. **WHICH light took three tries, and only the third came from LOOKING AT THE REFERENCE FRAMES instead of recalling them** (`tools/screenshot/` + the Slay the Spire and Hearthstone captures the pass was judged against). (1) A warm bloom along each card's TOP edge: six lit cards fused it into ONE continuous arc lying across the whole hand, belonging to no card and reading as a light leak. (2) An additive halo on the cost gem — which failed on a Godot fact worth keeping: **a `StyleBoxFlat` `shadow` is a FILLED blurred silhouette, not a ring**, so a transparent body shows the whole blob; it swallowed the numeral and stuck a fuzzy blue ball on every card. The top-edge version had only *looked* like a rim because the opaque paper hid the middle — the primitive was never making a ring. (3) **THE GILT EDGE, which is what both references actually do**: StS rings every playable card in a cyan OUTLINE tracing that card's own border, Hearthstone rings each actionable minion in green. `border_width`, not `shadow`. **The principle: A BLOOM HAS NO EDGE, SO OVERLAPPING CARDS SUM THEIR BLOOMS; A BOUNDED CUE CANNOT MERGE, BECAUSE ITS SHAPE ENDS.** Overlap does not break it — each card's own paper hides the part of its neighbour's edge it covers, so a crowded hand renders as nested arcs, one per card, still countable. **MEASURED, and this is the check that separates the two designs rather than my eye**: `_shot_hand_fan`'s pixel probe reads every lit card at **0.89 and every unlit at 0.29 at any hand size**, where the bloom ran 0.01–0.69 lit against 0.00–0.25 unlit — overlapping ranges, i.e. a cue whose strength depended on how many neighbours shared it. Gilt rather than neon because gilded page edges are already this card's material language. - Combat.gd builds all HUD in code, not in the scene editor
- Spell targeting uses `_input()` override, not the card drag system
- `KeywordEffects` accesses combat state via the ctx (Combat instance) directly — Combat is always the ctx
- Enemy deck is `Array[Dictionary]` (card data dicts from EncounterDB), not card IDs. Legacy fallback builds random dicts from CardDB
- Token creatures have synthetic card_data created in `summon_token()`, not from CardDB
- MapView, Shop, Rest, Event, and the starting-relic-pick screen all build UI programmatically; their `.tscn` files only have Background + script (map.tscn has no Background at all — the MapTerrain plate is the background)

- Reactive `double_on_death` re-runs the dying enemy's on_death effect directly via `KeywordEffects._run_on_death(...)` to avoid recursion through `dispatch_on_death → _dispatch_reactive`
- `_short_pause(duration)` is a real timer-based pause (uses `create_timer().timeout`) — the parameter is honored, not ignored
- **Combat beat constants live on the shared Motion clock** (`scripts/ui/Motion.gd`, 2026-07-16): Combat's `LUNGE_APEX`/`POST_HIT_BEAT`/`HITSTOP_BEAT` alias `Motion.*`, and Card2D's lunge/recoil/death tweens build from the same constants via `Motion.time()` (anim-speed scaling). Screen shake is GameTheme's trauma service (`set_shake_target`/`add_trauma`; `Combat.screen_shake` delegates, mapping legacy 4–28 px magnitudes) — impulses compound; don't re-add per-call jitter tweens. Verify: `tools/_probe_anim_clock.gd`. Audit + remaining plan: `docs/ANIMATION_AUDIT_20260716.md`.
- **Motion grammar + Reduce Motion contract** (2026-07-16): `Motion.ANTICIPATE/PUNCH/SETTLE/SETTLE_SLOW/EXIT/EXIT_SLOW/LOOP` are the named beat tokens (SINE-out / QUAD-out / BACK-out / EASE_IN / SINE loop respectively); prefer a kit verb — `deal_in`, `hover_lift` (opt. `target`/`raise_z`), `punch` (the juice_up impact, keyed kill-before-restart), `claim_pop`, `fade_exit`, `pocket_away`, `tick_number`, `write_on` (typewriter), `ken_burns`, `card_reveal` (the shared slate entrance, rarity shine + companion button included), `ring_pulse`, `rarity_reveal`, `forge_strike`, `writ_amend`, `reroll_sweep`, `pulse_label` — over hand-rolling a tween. **The verbs live as statics in `scripts/ui/Motion.gd` (extracted 2026-07-16, R6); GameTheme keeps same-name delegators** so `GameTheme.deal_in(...)` call sites still work — new verbs go in Motion.gd (+ a GameTheme delegator only if shell code will call it). Every animation is either **informational** (carries game state: lunge/recoil, mortal slump, floating numbers, threat/danger overlays, log chips — always plays; persistent overlays hold steady instead of pulsing under Reduce Motion) or **decorative** (idle bob, ambient FX, entrances, bursts, reveals, hover lifts, Ken Burns — gated OFF; the kit verbs gate themselves, incl. snapping to end-state where content must still land). - **EVERY BUTTON ANSWERS THE PRESS, AND IT ANSWERS ON `button_down` (2026-09-17).** Measured before the pass: **214 `pressed.connect` sites, TWO `button_down` connections in the whole repo, 24 buttons with a press cue, and `Motion.press` called exactly once** (on a HUD instrument, not a button). Pressing almost anything changed a StyleBox and nothing else. **`pressed` FIRES ON RELEASE** — so every reaction in the shell was waiting out the player's own finger (60-120 ms on a brisk click, unbounded on a deliberate one) against NN/g's 0.1 s limit for a system to feel like it is reacting instantaneously; Material specifies its ripple the same way (appears on pointerdown, holds to pointerup) for the same reason. **The acknowledgement moved to `button_down`; the COMMIT stays on `pressed`**, which is what keeps press-then-drag-off a cancel. **THE HOLD IS FREE AND IS DOING REAL WORK** — the 2022 impact-feel study (arXiv:2208.06155) ranked HIT STOP first of the three features whose absence "may ruin players' impact feel", and a held button is a hit stop the player performs themselves. **`Motion.arm_press` is the verb**; `GameTheme._install_press_feedback` hooks `SceneTree.node_added` and arms every `BaseButton` in the game. **That is a tree hook rather than four factory calls because the factories cover ~87 call sites against 92 bare `Button.new()`s** — half the game's buttons are hand-rolled, so a factory-side arm delivers exactly the half-covered surface the pass exists to end, invisibly (a button that does not react looks like a button). Opt out with a `no_press_feel` meta. **FOUR RULES THE BUILD RESTS ON.** (1) **THE DIP IS DENOMINATED IN PIXELS, NOT IN A RATIO** (`press_squash_for`) — a flat scale gave the 44px close button **0.40px** of edge travel and the 220px plate **1.98px**, i.e. below threshold on one and "the wide button was pressed harder" on the other; one thumb pushed both, so it is 2.6px on y / 1.3px on x at every size. It SQUASHES (y harder than x), because a uniform shrink reads as receding rather than as pushed in. (2) **THE REST POSE IS DERIVED, NEVER SAMPLED** — reading `scale` at press time samples `hover_lift` mid-tween, springs back to 1.01, and leaves the control permanently 1% large with no error anywhere; it is computed from the hover state off `_motion_hover_lift`. (3) **THE TARGET IS RESOLVED AT PRESS TIME** — every offer tile (Recruit's slate, the Shop's shelf, Reward's cards) is a painted wrapper under an invisible catcher, and `hover_lift(btn, lift, wrapper)` runs AFTER the funnel armed the button, so a target captured at arm time dips an invisible rect forever. `hover_lift` publishes `_motion_feel_target`. (4) **BOTH ARMS ARE IDEMPOTENT** — releasing on `mouse_exited` is required (a release after dragging off arrives over another control), but `mouse_exited` is also hover's trigger, so an unguarded release puts a second tween on `scale` for every ordinary un-hover. **AUDIO: one press is one sound.** The funnel's default cue is connected **DEFERRED** so a screen's own explicit cue runs first, and `AudioBank.play_ui` **drops a repeat in the same frame** (the frame, not a time window — a window has to be guessed against how long a player holds a button, and every pair being collapsed comes off one `pressed` signal). `arm_ui_press` is no longer how a button gets a voice — every button has one — it is how a button gets a DIFFERENT one. **`Motion.press_mark` is the at-cursor bloom and it is NOT on every button** (Material needs a ripple everywhere because a flat surface has no other press channel; here the plaque darkens AND the control dips), only on `press_weight` — `make_primary_button` and any "commit". **It is a filled BLOOM, not a ring**: run through `Motion.ring` it photographed as a thin hairline "O", which is the ring rebuild's own verdict on the Line2D circles it replaced, and at 40px there is no band width available to read as anything else. Its peaks are held at 0.50/0.52 because **a button is mostly its label and the press point is usually ON the text** — at 0.80/0.95 it washed the "E" out of TAKE THE FIELD, and there is no z-order fix (a Button draws its own text, so a child sprite is always above it and `show_behind_parent` hides the mark behind the plaque). `press_point_on` falls back to the control's CENTRE when the cursor is not inside it, because a KEYBOARD press reports wherever the pointer is parked — the first shot caught the bloom 500px off the button in open space. Gates: **`tools/_probe_press_feedback.tscn`** (35 checks — and the flag is deliberately NOT the oracle: every behavioural case drives the real signal and then MEASURES `scale`, because `arm_press` stamps `_motion_press_armed` on entry and cannot be asked whether it worked) and **`tools/_shot_press_feel.tscn`** (windowed; prints measured edge travel per button kind and 4× zooms the bloom). **Its phase C had to learn the house settle lesson twice**: 18 process frames reported "map: all 0 buttons armed" and PASSED (MapView builds behind `await build_map()`), and a bare stability test settled instantly because "0, 0, 0" is perfectly stable — it must poll on REAL TIME with a floor, since headless runs the main loop as fast as it can.
- **Card2D `rotation` has ONE writer; stat feedback has ONE funnel** (2026-07-16, C1/C2): `Card2D._process` is the card-LEAN driver and nothing else — armed only while a hand card is dragged (leans into cursor velocity, ±0.35 rad) or hovered (tilts toward the cursor, ±0.10 rad; this REPLACED the old straighten-to-0 hover tween), `set_process(false)` at `_ready`, self-disarming. - **A BOARD TOKEN'S REST POSE AND RESTING TINT ARE DERIVED, NEVER SAMPLED (2026-09-17)** — `scripts/Card2D.gd`, gate `tools/_probe_card_pose.tscn` (in `run_ui_gates.ps1`). ONE defect class, four spellings, all found by one oracle: **does the card come back to rest when two beats overlap?** Every other feel gate judges a settled screen or one beat alone, so a beat that SAMPLES a property another beat is mid-way through writing — and then restores to what it sampled — was invisible to all of them. `play_defend_brace`'s own header already named the rule ("a tween that captures a mid-move point as 'rest' walks the card out of its slot and compounds over every trade") and it had been applied to the brace and the arc only; **the two functions that header NAMES still read their own previous tween's mid-flight value**, three lines above their own kills. **IT SURVIVED BECAUSE THE TWO AXES FAIL DIFFERENTLY: `position.y` SELF-HEALS** (the 30 Hz idle bob rewrites it from `_bob_base_y` within 33 ms, so no shot ever caught one) **and `scale` does not** — nothing else writes a battlefield token's scale, so the error is kept and COMPOUNDS multiplicatively. MEASURED at the conductor's own cadence (Combat awaits `LUNGE_APEX` 0.18 s while the lunge runs 0.36 s, so **the back half of every lunge is unawaited BY DESIGN** and a repeat lands inside it): four lunges → scale **0.903 × 1.186** and **12.6 px out of the slot**; four recoils → **1.405 × 0.729**, i.e. a body struck four times in one clash ended 40% wider and 27% shorter, kept for the rest of the fight. Repeat strikers are ordinary content (`attacks_twice`, the `battle_order_second_strike` rider, a Sniper chaining on kills, `charges_this_turn` sweeping four lanes) and a defender is struck twice in any column where the hold keeps both rows. **`Tween.kill()` IS NOT ENOUGH ON ITS OWN and that is the transferable half** — kill leaves the property wherever it stopped, so a read after the kill is still a read of a mid-flight value; `_sync_rest_pose()` instead lets the FIRST beat capture the true rest and every beat starting inside it INHERIT (`_pose_beat_running()`), taking y from `_bob_base_y` rather than the sine offset showing that frame. Same pass, same shape on `modulate`: **the resting tint of a BATTLEFIELD token now has one writer**, the exact twin of `_apply_hand_tint`'s 2026-08-04 rule which was written for the HAND and never extended to the BOARD. SEVEN beats washed a board token's tint (doom tick / heal / `_flash_hit`'s fallback / mortal slump / its rescue / Last Stand flare / floop pulse), every one "capture `base := modulate`, wash, restore to `base`", none aware of the others — so two overlapping beats left the body permanently tinted with nothing to correct it (measured: a doom tick landing 0.10 s into a floop pulse left it gold at `(1.00 1.00 0.56)`). **`_mark_mortally_struck` was the worst of the seven because it stored its poisoned sample in a FIELD** (`_mortal_slump_base`) that a rescue restores FROM, so the error outlived every tween involved — a body struck mid-tick and then rescued came back **bright red `(1.89 0.41 0.36)`** for the rest of the fight. `_body_wash()` is the one funnel now and the slump CHANGES `_tint_rest` rather than fighting it (it is a state, not a transient). Fourth: **`_combat_tween_active()`, the bob's yield rule, named the lunge and the recoil only** — its reasoning ("scale-only tweens are excluded, the bob writes position.y") was sound and its LIST was wrong, because `play_defend_brace` is not scale-only: it tweens `position`, and its displacement is PURELY VERTICAL, the one axis the bob rewrites every tick. The defender's brace — whose header calls it "the cheapest fix in the whole design" — was being stomped four times over its 0.14 s life and did not visibly happen at all on a bobbing body. ### Card text positioning (v3 layout — superseded)

Text on cards (cost, name, type, description, ATK, HP, FLOOP) is positioned by **pixel-measured POINT_* constants** in [scripts/Card2D.gd](scripts/Card2D.gd), each pointing at the center of a painted region in the 300×400 source frame texture.

**To tune or re-derive these positions, run:**

```
python tools/measure_frame.py
```

It scans `assets/frames/frame_creature_common.png` pixel-by-pixel — looking for the red orb's bright-red core, the banner's dark-gray interior, the gold divider scroll, the tan parchment well, etc. — and prints a copy-pasteable block of `POINT_* := Vector2(...)` constants with the bbox center of each region. Replace the matching constants in `Card2D._build_full_layout_v3`'s header.

**Eyeballing positions does not work.** Earlier attempts had `POINT_NAME` 20px above the actual painted banner because the banner's gold trim above the dark interior visually fooled the measurement. The script reads pixel values directly, so it can't be fooled the same way.

**Layout uses point-anchored centering, not anchor rects.** The helper `_center_at_point(label, point, size)` anchors a label to a single point with symmetric `offset_left/right/top/bottom = ±size/2`. This avoids two Godot quirks: (1) `Label.vertical_alignment = CENTER` misaligns when the rect is smaller than the font's line box; (2) asymmetric anchor rects make `horizontal_alignment = CENTER` compute the visual midpoint inconsistently. POINT_* is "where the center goes," SIZE_* is "how much room the label gets" — keep SIZE_* generous (≥36px tall) so Godot's centering works.

**Font setup** lives in [scripts/GameTheme.gd](scripts/GameTheme.gd) `_load_assets()`. Three fonts:
- `font_display` — Cinzel Variable wrapped in FontVariation with `wght: 600` (SemiBold) for names, type, FLOOP
- `font_stat` — same Cinzel but `wght: 800` (Black) for cost / ATK / HP numerals — matches AAA card-game stat-orb conventions (Hearthstone, MtG Arena)
- `font_body` — Nunito Regular for descriptions

Both Cinzel variations set `spacing_bottom = -3` to optically center caps-only text (caps don't use descender space, so geometric center renders ~1.5px high). If text still looks high, increase the negative value; if low, push toward 0.
