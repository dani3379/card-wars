## Project overview

"Burning Meadow" — a lane combat roguelike deckbuilder built in Godot 4.6 (gl_compatibility renderer, 2D). Inspired by Card Wars (combat) and Slay the Spire (roguelike structure). 4 lanes × 2 rows per side (front/back), simultaneous combat with Swift pre-phase, floop, spells. 3 acts with branching maps, shop/rest/event nodes, premade encounter lineups with fight passives.

## Running the project

Open in Godot 4.6+ and press F5. Main scene is `scenes/main_menu.tscn`. No build step, no tests, no CLI tooling.

For headless parse-checks during development: `Godot_v4.6.x-stable_win64_console.exe --headless --path "D:\Godot" --editor --quit-after 5 res://scenes/combat.tscn` — opens combat.tscn in the headless editor, which force-compiles Combat.gd and Card2D.gd. Any parse errors print to stderr.

## Architecture

### Scene flow

`MainMenu → run setup (hero + ascension + daily/seed, one screen) → war-chest blessing → MapView → Combat/Shop/Rest/Event/Recruit/Treasure/Wayside → Reward → MapView → ... → Combat (boss) → GameOver`

Scene transitions use `get_tree().change_scene_to_file()`. Each scene is a `.tscn` in `scenes/` with a matching script in `scripts/scenes/`. The whole run-opening flow (setup screen, then the blessing pick) runs from MainMenu before the first map appears, building UI programmatically over the menu background. The war chest (remade 2026-07-03) rolls 3 honest + 1 priced opener from run-shaping pools (advance gold / sharpen / transform 2 / pick-1-of-3 uncommons / +7 max HP / 2 potions / relic — vs black ledger / widow's coin / butcher's kindness / hollow levy); every entry is alive at run start (the old Heal-12 and full-heal tiles were dead — the march begins at full HP). The menu column itself is 7 items max (CONTINUE / NEW MARCH / SKIRMISH / COLLECTION / HOW TO PLAY / SETTINGS / QUIT, + LOAD GAME only when 2+ slots are filled); daily run and custom seed live inside run setup, not the column. GameOver's MARCH AGAIN sets `RunState.rematch_request` and MainMenu consumes it on ready, jumping straight to the war chest with the same hero/ascension.

### Autoload singletons

- **RunState** (`scripts/state/RunState.gd`) — current run state: HP, deck, relics, gold, potions, map data, card upgrades, `phoenix_heart_consumed`. `get_act()` returns 1-3. `start_new_run(hero_id := "")` resets, builds the deck from `HeroDB`, adds the hero's signature relic, and generates the map. `get_current_act_map()` / `get_available_nodes()` / `visit_node()` for map navigation. Card upgrades tracked per deck index via `deck_uid`: `upgrade_card(uid, path, keyword)`, `get_upgraded_card_data(uid)`.
- **HeroDB** (`scripts/data/HeroDB.gd`) — 5 playable heroes (Raider/Stalwart/Acolyte/Pyromancer/Kindler). Each entry has `deck` (10-card list of CardDB ids) and `relic` (id of a `tier:"starting"` RelicDB entry). Picked at the start of every run from MainMenu — replaces the old "pick 1 of 3 starting relics" screen. **The starter contract (2026-07-06 progression pass): hero decks use ONLY starter-rarity cards** (the original 8 + the levy set Outrider/Palisade/Mourner/Spark; Kindler's plain doom commons are the sanctioned exception) — never seed a hero deck with pool commons/uncommons, that's what flattened the run's power curve. Drafted cards must always outrank the opener. Generals additionally offer a chosen "+" forge on the Reward screen (The General's Forge), and Recruit slates lean uncommon/rare by act 3 (30/50/20). **Cross-run muster unlocks (2026-07-04, options not stats)**: `relic_alt` (choice of signature relic, unlocked by the hero's first win) and `deck_alt` {name, tagline, deck} (alternate 10-card start, a 2-3 card swap on the default; unlocked by a win at Ascension 4+). The run-setup detail pane shows them as toggles (locked = dim hint lines); MainMenu hands the picks to `RunState.start_new_run` via `pending_signature_relic` / `pending_deck_variant` (consumed + cleared there). MARCH AGAIN rematches use defaults.
- **MetaState** (`scripts/state/MetaState.gd`) — cross-run persistence: win/loss counts, `unlocked_ascension`, per-hero `hero_stats` ledger (wins/losses/best_asc, shown on the run-setup detail pane), and the `daily_record` (today's Daily March: date/hero/result). Transient `last_victory_unlocked_tier` / `last_victory_was_fastest` flags let GameOver announce what a win just changed. Saved as JSON to `user://meta.save`.
- **CardDB** (`scripts/data/CardDB.gd`) — 174 total card entries: ~112 draftable (starter + common + uncommon + rare, incl. the 2026-07-07 fun slate: Rat Piper / Slow Match / The Petard / The Volunteer / Trebuchet / Muster the Fallen) + 18 enemy-only + tokens/curses. **Curses are a 6-card branded pack** (curse, wound, craven, deserters_mark, grave_debt, war_debt): `curse_playable: true` marks the one playable-at-a-price curse (Cowardice — costs 2, does nothing, Exhausts); `curse_on_draw: {type, value}` fires a draw sting in Combat (`lose_command` / `hero_damage` / `lose_gold`). Unplayability is ENFORCED by a gate in `Combat._on_card_played` (before 2026-07-03 curses silently resolved as free no-op spells). `random_curse_id()` rolls weighted (plain Curse commonest, Wound rarest); events can hand a specific mark via the `add_curse_id` effect. Card types: "creature" (ATK/HP/keywords) and "spell" (spell effect + targeting). `roll_card_reward(act, is_elite, is_boss)` for rarity-weighted picks.
- **RelicDB** (`scripts/data/RelicDB.gd`) — ~135 relics across tiers (starting, combat, utility, including 4x4-specific relics like Vanguard Banner / Rear Guard Charm). Each has hooks, effect ID, and value.
- **KeywordEffects** (`scripts/data/KeywordEffects.gd`) — 26 keywords. Dispatchers: `dispatch_on_enter`, `dispatch_on_death`, `dispatch_start_of_round`. On-enter types include: damage_opposing, damage_random_player, damage_all_enemies, draw, gain_gold, damage_face, debuff_opposing_atk, discard_random, copy_friendly, copy_opposing_keywords, copy_last_dead, look_top, cast_random_spell. On-death types: damage_opposing_lane, damage_all_enemies, summon, bonus_mana, damage_face, debuff_all_player_atk, damage_adjacent.
- **EncounterDB** (`scripts/data/EncounterDB.gd`) — 55 premade fight lineups across 3 acts (incl. the 5 rival-lord kits + 5 amalgam finales). Each encounter has ordered creature deck, reinforcement, HP, and optional fight passive. `REACTIVE_PASSIVES` dictionary defines per-encounter reactive triggers (e.g. `necromancer_tower` doubles enemy on_death via `_dispatch_reactive("ON_CREATURE_DEATH", ...)`). `build_enemy_deck(id)` returns Array[Dictionary] of card data. `get_reinforcement(id)` for infinite backup creature.
- **AudioBank** (`scripts/AudioBank.gd`) — central SFX/music dispatcher: `play_sfx(name, jitter, volume_db, pitch_base)` (`pitch_base < 1.0` deepens a cue — the low-HP heartbeat, boss horn, and doom tick are repitched stand-ins; those call sites check `has_own_sfx` so a real clip plays straight once it lands), `play_music(name)` (remembers each track's playback position and resumes there when it re-enters rotation — intros don't wear out), and `duck_music(depth_db, hold)` (dips the Music bus under victory/defeat/boss-entrance stingers as a relative offset, then restores the user's slider level). Every screen picks music from a pool via `play_music_random` (35-track library, see `assets/audio/music/MUSIC_CREDITS.md`); `tools/_probe_music_wiring.gd` (headless) fails if any pooled name lacks a file. A cue whose `assets/audio/sfx/<name>/` dir is missing/empty plays its `SFX_FALLBACKS` stand-in (real clips in the primary dir auto-win); `tools/_probe_audio_cues.gd` (headless) fails if any `play_sfx` call site resolves to silence. Clash audio ownership: struck survivors sound via `Card2D._flash_hit` ("hit_creature"), kills sound ONCE at the impact beat via Combat ("creature_death" + `death_cue_played` flag that `_die()` respects) — don't add a second cue on either path.
- **CardTextureCache** (`scripts/state/CardTextureCache.gd`) — preloads card frames/art textures to avoid per-card disk reads.
- **ScenePreload** (`scripts/state/ScenePreload.gd`, 2026-07-06) — warms and PINS every screen's PackedScene + the script-loaded big backgrounds (per-act arenas/campfires, map paper fiber) on ResourceLoader worker threads right after boot, so `change_scene_to_file()` hits the resource cache instead of re-parsing .tscn + re-decoding ~2MB backgrounds on the main thread per transition. After the queue drains it bakes one creature + one spell via CardTextureCache (windowed only) to pull the card-font glyph atlases and bake pipeline warm behind the menu. Music has the matching treatment inside AudioBank: `play_music` threaded-loads each track once per session into `_music_streams` (files run up to 18MB — the old sync `load()` was a per-transition hitch); `_pending_music_track` arbitrates races, `stop_music` cancels in-flight plays. Verify both: `tools/_probe_perf_pass.gd` (headless).
- **GameTheme** (`scripts/GameTheme.gd`) — fonts, colors, panel styles, and the enemy-name→art-alias map (now `scripts/data/CardArtAliases.gd`).

### Combat scene (`scripts/scenes/Combat.gd`)

Largest file (~14,400 lines). Core systems:
- **Round flow**: draw 4 → player plays creatures/spells, toggles floop, banks ≤2 mana → resolve floops → Swift phase → simultaneous combat (both rows attack each turn; front attacks first and is attacked first — back row is queue space, not a separate combat tier) → deaths/on-death → discard hand → enemy places creatures (escalates at `ESCALATION_REINFORCE_ROUND`) → passives → new round. Combat runs EVERY round — there is no setup-only turn; ending round 1 clashes with whatever both sides fielded (player copy must never imply round 1 is consequence-free — see the `_update_hud` round-label comment).
- **Board (4×4)**: `_player_field[4]` and `_player_back[4]`, mirrored `_enemy_field[4]` / `_enemy_back[4]`. `_row_array(is_enemy, row)` is the canonical accessor; `ROW_FRONT = 0`, `ROW_BACK = 1`. `_all_creatures_both_sides()` iterates everything.
- **Enemy deck**: `Array[Dictionary]` of card data, loaded from EncounterDB or built from legacy random pool. `_place_enemy_card(data, lane)` creates Card2D from card data dict directly.
- **Spells**: targeted spells enter `_targeting_spell` mode (click to resolve). Non-targeted resolve immediately. Exhaust pile separate from discard. `_last_spell_played_this_turn` enables Echo. `_auto_target_for(card_data)` picks a sensible target for self-resolving spells (used by Chaos Imp / Echo / Reposition fallback).
- **Sacrifice**: NOT a free player action. The player cannot kill their own creatures on command. Sacrifice only happens via specific card effects: the `blood_sacrifice` floop ability, the Offering / Fuel the Pyre spells (target-friendly sacrifice via 999 damage), and any future card with the "sacrifice" keyword as its play cost. All three paths route through `_trigger_player_sacrifice(victim)` so Bone Pile, Butcher's Cleaver, Reaper's Scythe, and the `ON_PLAYER_SACRIFICE` reactive fire uniformly. Same model as Slay the Spire.
- **Floop**: creatures with floop can toggle `will_floop`. Types include damage_any, summon_random, kill_adjacent_summon, steal_atk, heal_all_friendly, summon_token, redirect_adjacent, copy_opposing_floop, swap_atk, become_copy, drain, blood_sacrifice, etc.
- **Keywords**: Armored (-1 dmg), Swift (pre-phase), Thorns (1 back), Piercing (excess → face), Last Stand (survive once at 1 HP), Ranged (random target, prefers back row), Regenerate/Wither (start of round). Royal Guard passive grants adjacent-friendly -1 dmg and gains +1 ATK when hit (in addition to its redirect floop).
- **Encounter passives**: `_dispatch_passive_start_of_round()`, `_dispatch_passive_end_of_round()`, `_dispatch_encounter_on_enemy_death()`, `_dispatch_encounter_on_player_death()`, `_dispatch_encounter_on_enter()`. `_has_encounter_passive_keyword(card, kw)` grants piercing/thorns/armored to enemy creatures based on encounter passive ID.
- **Reactive passives**: `_dispatch_reactive(trigger, source_card, lane_idx)` fires per encounter's `REACTIVE_PASSIVES` entry. Triggers: ON_PLAYER_SPELL, ON_PLAYER_SACRIFICE, ON_PLAYER_FLOOP, ON_PLAYER_SUMMON, ON_CREATURE_DEATH, ON_PLAYER_DRAW.
- **Relic effects**: checked inline via `_has_relic()`. Major hooks: combat_start, turn_start, creature_played, hero_damaged, creature_death, sacrifice, bonus_draw, combat_end.
- **HUD**: built programmatically. Shows encounter name and passive description. Parchment-styled panels, screen shake via CanvasLayer offset. **Battle log** (2026-07-08): the top-left LOG tab opens a chronicle drawer; every beat routes through `_log_event(bb, data, side, icon_override, icon_tint)` / `log_status(card, text)` — new mechanics should log through those funnels, and paths that already feed them (keyword chips, `spawn_keyword_callout_kw`, strike/death/face-damage/potion/spell hooks) must not add a second call. Each row is illustrated (Hearthstone-style): actor call sites pass `_log_data(card)` + `_log_side(card)` so the entry shows a 34px card-art thumbnail with a side-tinted rim (gilt=you / ember=foe), and hovering a card-bearing row floats the full live-baked Card2D beside the drawer (`_show_log_preview`). Battlefield tokens carry a LIVE status rail (Card2D `_refresh_status_rail`, signature-polled) — transient statuses (Shield/Frozen/Stunned, temp Armored/Thorns) render tinted ahead of the gilt printed keywords; verify all three with `tools/_shot_battle_log.tscn` (shoots status/log/hover).

### Map system

RunState generates a branching map per act: 18 rows tall × up to 7 columns wide, 3 paths with a 3× merge bias (trunk road + branches). The act is a fixed **row skeleton** (Kaycee's-Mod model; lengthened 2026-07-07 from 12 rows / 5 combats — the act ended in 3-4 fights, too short for the deck/veterancy/relics to snowball): fight rows (`FIGHT_ROWS [0, 3, 9, 15]`, elite bands at `ELITE_ROWS [6, 12]`) alternate with PAIRS of wayside rows, so every between-fight gap is exactly two non-fight stops (Inscryption cadence) dealt from event / wayside verb / recruit / shop / treasure; `REST_ROW = 16`, `BOSS_ROW = 17`. Fight count per route is constant by construction — **7 combats: 6 holds + keep — but their COMPOSITION varies by lane (2026-07-07 war-road pass)**: each elite band carries ONE General (dodgeable when the band is ≥2 lanes), and one wide plain fight row per act hides a THIRD, optional war-road General — the StS elite-hunt trade (greedy routes break up to 3 Generals for 3 relics; `_war_road_ok` makes the acceptance loop reject lattices where the fork couldn't land). Two guaranteed treasures (R7, R13) and two musters (R4, R10) ride the longer road (the 2nd treasure also feeds the relic economy — relics only drop at elites/treasure/shops/boss). An acceptance loop in `_generate_act_map` reseeds until the act has 24–36 sites and every route carries enough fights to open the lord gate. **Wayside halts** (`scenes/wayside.tscn`, `scripts/scenes/Wayside.gd`) are one-decision roadside verbs assigned at gen (`node.wayside_id` → `RunState.current_wayside_id`): drill_yard (push-your-luck +1/+1), standard_bearer (move a keyword between creatures), supply_cache (pick 1 of 3 war-material spoils — gift creature / next-fight boons / a commissioned card, never plain gold/heal). muster_scale was RETIRED 2026-07-02 (its sell-a-card verb moved into the Shop as the sutler's buy-back); the handler stays so old saves resolve, but the deal never deals it. Their permanent card changes ride the card-upgrade mod stack (`apply_wayside_upgrade`, paths `drill`/`grant_kw`/`strip_kw`) — mods compose Inscryption-style (a drilled creature can also carry a banner and be forged); the drill entry keeps a TOTAL stacks counter capped at `DRILL_MAX_STACKS`.

The map screen is two layers: **MapTerrain** (`scripts/scenes/MapTerrain.gd`) draws the static plate, and since 2026-06-29 it renders in **war-table mode** (`SIMPLE_BACKDROP := true`): nodes on a fixed left→right lane grid (camp 0.075·w → keep 0.80·w, `cy 0.535·h`, lane pitch `0.100·h` — tuned so the outer lanes clear the top cartouche and the sheet edge; the bottom legend band was RETIRED 2026-07-07 — unstruck tokens print their own engraved site names (SITE_LABEL in _draw_sites, waysides print their verb) and hover tooltips carry the deep intel), dead-straight roads, and a **generated deckled coastline** built per act around the node field (`_build_simple_coast`: convex hull over all stops + camp + Etna's foot, inflated 86px, noise-resampled — every stop is on land BY CONSTRUCTION). The chart is STAGED as a physical object (`_paint_simple_backdrop`): a deckled parchment sheet (`_sheet_poly`, inset 28) pinned by corner tacks to the same dark wood war table Combat plays on, casting a shadow; the SEA is paper (a darker sepia wash + waterline rings + graticule — never a colour), the island a lit parchment shape with per-cell mottle + an anisotropic lamplight band along the march corridor, faint biome tints with engraved terrain marks (`_draw_simple_marks` — pines/peaks/furrows keyed to the SAME biome mesh the terrain tooltips read), rivers, foxing, compass + fleet in the SE sea. Two LIVE layers finish it (never in the bake — full-rect alpha bakes opaque): `_paper_item`, real paper fiber (`assets/backgrounds/map_parchment.jpg`) multiplied over the plate via a blend_mul shader that lerps the fiber toward white (canvas MUL is raw SRC·DST — modulate cannot fade it), riding the view transform so grain scales when leaning in; and a lamplight vignette (`_vignette_tex`) drawn screen-fixed in `_draw_ui`. Medallion enamels are pulled ~16% toward gray in `_draw_medallion` so the tokens sit in the sepia world. Etna sits EAST of the keep (`0.905·w, 0.315·h`); scorch is centered on `_etna_peak` and grows per act; claimed stops glow warm amber (`_draw_claimed_glow`, ink layer). The full painted-Sicily campaign renderer (winding spine, political dyes, two-dress zoom) is still in the file behind `SIMPLE_BACKDROP = false`. **MapView** (`scripts/scenes/MapView.gd`) extends it with the game layer: invisible hover/click buttons over the painted site chips (tooltips carry encounter + mutator intel), node → scene flow, top HUD, the standing-order chip (gate objective + province tally, `_place_gate_banner`), deck viewer, per-act meta-relic pickers, and the return-to-map save checkpoint. `scenes/map_proto.tscn` renders MapTerrain alone (sandbox). HUD positions must derive from `size.x` — the stretch canvas is the 1600×900 project viewport, and hardcoded window-pixel x coordinates land off-canvas. The chart zooms/pans (wheel + drag; opens auto-focused on the army standard). Perf structure: the plate paints on `PlateItem` (child canvas item — every `_draw_*` plate function takes a target CanvasItem `tgt`; zoom/pan only move the item's transform), offscreen `bake_mode` clones collapse it to one 2× texture (geography per act, full plate per open), and `RunState.map_plate_cache` carries mesh + geo texture across opens within an act. The plate is frozen while on screen: per-frame animation belongs in `MapPulseOverlay`; new plate layers go in `PlateItem._draw`'s ink block (they bake in automatically). Gotcha: a zero-size Control is culled when its transform isn't identity — `_plate_item.size` must stay the real plate rect. Map verify loop: `tools/_shot_map_states.tscn` (windowed, editor closed) renders 6 states (act 1 full/open/zoom/mid-run + acts 2-3) to `_shot_a*.png`; `tools/_probe_terrain_tags.gd` (headless) checks terrain-tag variety + bridge detection over the generated coast.

### Card upgrade system

Slay-the-Spire-style **"+" upgrades**: every draftable card has one hand-crafted upgraded version. Rest sites offer the "Forge +" action — the player picks a card, sees a before/after preview, and confirms. No path picking, no random rolls. Camp also offers **Hold a Wake** (2026-07-04, only when the Roll of the Fallen has names): pick one fallen soldier; its shade (folded stats while the card still marches, printed stats if mustered out) opens the NEXT fight in front-left via `next_combat_gift_creature` — a real 3-way camp fork (heal / forge / wake), and since camp sits right before the keep, the wake usually arms the boss fight.

**Veterancy ladder** (solo campaign memory, `RunState.creature_kills` per deck_uid): 3 kills = epithet ("Pikeman the Grim"), 6 = +1/+1, **10 = the war school** — a modal at the top of the next player phase offers Armored / Swift / Thorns, written as a permanent `war_school` mod entry (Combat `_offer_war_school`; round-1 catch-up sweep covers thresholds crossed on a fight's last kill and pre-rung saves; headless sessions auto-pick the first school so probes/autorun never stall).

- Per-card upgrade deltas live in `CardDB.UPGRADES` (atk/hp/cost/value/keywords/sub-effect bumps, plus optional desc override). `CardDB.get_plus_upgrade(id)` returns the delta; `CardDB.is_upgradeable(id)` filters out curses.
- The upgrade is applied by `RunState._apply_upgrade` via the `"plus"` path → `_apply_plus_upgrade(data)` merges the delta into the card data and stamps `is_upgraded: true`.
- Custom-spell resolvers in `Combat.gd` read `dmg_bonus`, `slay_draw`, `extra_draw`, `extra_mana`, `ricochet_hits`, etc. from the merged card_data, so + versions actually hit harder / draw more / give more mana.
- A handful of creature passives (Royal Guard, Corpse Eater, Vengeance, Vampire Lord, Riteforge, Warchief) read `card_data.is_upgraded` directly and bump their tick value.
- Specialty upgrade paths — `butcher` (now granted by the War Chest's "Butcher's Kindness" opener), `mirror_twin` / `fortify_neg` (legacy — their events were cut in the 2026-07-03 pool remake; the arms stay so old saves fold) — keep their dedicated paths in `_apply_upgrade`. Events also write the wayside `grant_kw` path: the Pensioned Master teaches a chosen creature Armored/Swift/Thorns permanently.

Mods are tracked in `RunState.card_upgrades` keyed by `deck_uid` — **each value is an ordered Array of mod entries (Inscryption stacking model)**: a card can be drilled, carry a transferred keyword, AND be forged; entries fold in the order earned. The "+" forge is the only once-per-card path — `has_upgrade_path(i, "plus")` is the forge filter; `is_card_upgraded(i)` now means "carries any mod"; the " +" name suffix marks the forged state only. `get_upgraded_card_data(uid)` returns the folded data. **Upgrades are applied at draw time in Combat** via the `deck_uid → card_data` lookup — drawing a card looks up its uid and uses the upgraded data dict. Legacy single-entry saves are shape-migrated (wrapped into arrays) on load.

The Whetstone relic upgrades the "Reforge" rest banner to forge **two** cards instead of one (once per act).

### Card2D (`scripts/Card2D.gd`)

PanelContainer-based card (~6,600 lines, includes pixel-measured frame layout). Supports creatures (ATK/HP display) and spells (SPELL label, no stats). Drag from hand above play threshold to play. Battlefield creatures show floop indicator. `take_damage()` handles Armored and Last Stand. `temp_atk_buff` for this-turn buffs; `persistent_atk_buff` + `persistent_atk_buff_rounds` for multi-round buffs (Butcher's Cleaver). `effective_atk()` is the canonical "what's my real ATK right now" — always prefer it over raw `current_atk + temp_atk_buff` reads.

### Card data schema

Creatures: `id, name, type:"creature", cost, atk, hp, rarity, keywords[], desc`. Optional: `on_enter{}, on_death{}, floop{}, adj_buff{atk,hp}, wither:int, passive:String, extra_damage:int`.

Spells: `id, name, type:"spell", cost, rarity, keywords[], desc, spell{type,value,...}, targeting:String`. Targeting: "enemy_creature", "friendly_creature", "any_creature", "any", "none".

### Adding content

- **New card**: add to `CardDB.CARD_POOL` (include all fields per schema above) AND add a `CardDB.UPGRADES` entry for its "+" version. Missing UPGRADES entries get a default fallback (+1/+1 creature or -1 cost spell) so they still upgrade cleanly, but hand-crafted entries feel better.
- **New relic**: add to `RelicDB.RELICS`, implement effect check in Combat.gd.
- **New keyword**: add to `KeywordEffects.KEYWORDS`, implement in dispatchers, add to Card2D display, AND register a white-silhouette device SVG (`assets/icons/keywords/<kw>.svg`, 512×512, single `fill="#fff"` path — game-icons.net kit style) in `GameTheme._load_keyword_icons()`. The loader is an explicit allow-list: an unregistered keyword silently gets NO bottom-margin device on cards. Run a headless `--import` after adding the SVG.
- **New spell type**: add `spell.type` handler in Combat.gd `_resolve_spell()` or `_resolve_custom_spell()`. If you add a custom damage spell, declare `dmg_bonus` in its UPGRADES entry and add `+ plus_dmg` to the damage line in the resolver.
- **New encounter**: add to `EncounterDB.ENCOUNTERS` with name, act, type, hp, passive_id, passive_desc, deck, reinforcement. Add passive handler to Combat.gd if passive_id is non-empty. Optional reactive passive: add to `REACTIVE_PASSIVES` and handler case in `_dispatch_reactive`.
- **New event**: add to `Event.gd` EVENTS dictionary with name, desc, choices with effects. **The pool's design bar (2026-07-03 remake, 30 events as of 2026-07-07): one concept per event, and the payoff should touch the BUILD or the FIGHTING** (keyword grants, whole-deck swaps, specific cards via `add_card_id`, max-HP stakes, next-fight boons) — not just re-price gold/HP/Curse. Until bespoke Midjourney art lands at `assets/events/<event_id>.png`, set an `"art": "<other_event_id>"` stand-in — the bespoke file auto-wins once it exists (art from cut events stays on disk for exactly this; don't point two live events at the same stand-in). Optional per-event fields: `"mood"` (bone / ember / gilt / verdigris — tints the title + scrim ink) and `"ambience"` (AudioBank loop dir name; gracefully no-ops until the asset exists). ## Gotchas

- Combat.gd builds all HUD in code, not in the scene editor
- Spell targeting uses `_input()` override, not the card drag system
- `KeywordEffects` accesses combat state via the ctx (Combat instance) directly — Combat is always the ctx
- Enemy deck is `Array[Dictionary]` (card data dicts from EncounterDB), not card IDs. Legacy fallback builds random dicts from CardDB
- Token creatures have synthetic card_data created in `summon_token()`, not from CardDB
- MapView, Shop, Rest, Event, and the starting-relic-pick screen all build UI programmatically; their `.tscn` files only have Background + script (map.tscn has no Background at all — the MapTerrain plate is the background)
- `current_atk + temp_atk_buff` should never be read directly — always go through `card.effective_atk()` so `persistent_atk_buff` (Butcher's Cleaver) is included
- Reactive `double_on_death` re-runs the dying enemy's on_death effect directly via `KeywordEffects._run_on_death(...)` to avoid recursion through `dispatch_on_death → _dispatch_reactive`
- `_short_pause(duration)` is a real timer-based pause (uses `create_timer().timeout`) — the parameter is honored, not ignored

## Card layout (Card2D)

**The LIVE hand-card layout is `_build_chart_proto()` (v9 "illuminated writ", 2026-06-11)** — the card IS the campaign's aged parchment with the document furniture printed on it. The sheet itself is `WritLeaf` (seeded deckled silhouette — the contour ink and edge toast are drawn along the SAME wobbled path, so the organic edge never separates from its shading); interior ageing is the seeded `ParchmentPlate` painter (washes/foxing/fibers, clipped 3px inset). Furniture: per-rarity metal double rules over an ink keyline (bronze/silver/gold/pewter; curse = bone on murk-stained paper), art mounted big as an ink-matted gilt-filleted plate with metal plate-mark squares on its corners (nothing is ever pinned over the painting), the name on an `InkCartouche` — a swallowtail metal-edged banner — in gilt Cinzel (auto-shrinks long names), a faceted rarity gem set in an ink mount top-center, rules text written straight on the page in **Alegreya** (`GameTheme.font_card_body`, wght 500/760, scoped to cards only — HUD/menus keep Nunito) inside a hairline ink box with metal corner ticks (keyword gold is re-inked `#7a4f10` there — the tooltip gold `#e8b547` washes out on paper), keyword devices ink-stamped in the bottom margin, and stats as pressed wax seals (`WaxSeal` class — seeded irregular blob per card+stat). Battlefield tokens are `_build_compact_layout` in the same material kit (38px wax seals via the shared `_chart_seal`, 18px outlined numerals). **Geometry gotcha: the Card2D control is natively 225×300 — absolute offsets are real pixels; only `_center_at_point` maps the 300×400 design space** (where v6/v3 numbers like `(150, 213)` live). Cost/ATK/HP keep the historical 56px corner boxes so `_build_baked_overlay_layout` numerals land on them. A/B harnesses live in `tools/card_redesign_v6/` (`render_v7.tscn` = current, `render_cards.tscn` = v6/v3). Everything below describes the SUPERSEDED v3 painted-frame layout, kept for reference:

### Card text positioning (v3 layout — superseded)

Text on cards (cost, name, type, description, ATK, HP, FLOOP) is positioned by **pixel-measured POINT_* constants** in [scripts/Card2D.gd](scripts/Card2D.gd), each pointing at the center of a painted region in the 300×400 source frame texture.

**To tune or re-derive these positions, run:**

```
python tools/measure_frame.py
```

It scans `assets/frames/frame_creature_common.png` pixel-by-pixel — looking for the red orb's bright-red core, the banner's dark-gray interior, the gold divider scroll, the tan parchment well, etc. — and prints a copy-pasteable block of `POINT_* := Vector2(...)` constants with the bbox center of each region. Replace the matching constants in `Card2D._build_full_layout_v3`'s header.

**Eyeballing positions does not work.** Earlier attempts had `POINT_NAME` 20px above the actual painted banner because the banner's gold trim above the dark interior visually fooled the measurement. The script reads pixel values directly, so it can't be fooled the same way.

**Layout uses point-anchored centering, not anchor rects.** The helper `_center_at_point(label, point, size)` anchors a label to a single point with symmetric `offset_left/right/top/bottom = ±size/2`. This avoids two Godot quirks: (1) `Label.vertical_alignment = CENTER` misaligns when the rect is smaller than the font's line box; (2) asymmetric anchor rects make `horizontal_alignment = CENTER` compute the visual midpoint inconsistently. POINT_* is "where the center goes," SIZE_* is "how much room the label gets" — keep SIZE_* generous (≥36px tall) so Godot's centering works.

**Font setup** lives in [scripts/GameTheme.gd](scripts/GameTheme.gd) `_load_assets()`. Three fonts:
- `font_display` — Cinzel Variable wrapped in FontVariation with `wght: 600` (SemiBold) for names, type, FLOOP
- `font_stat` — same Cinzel but `wght: 800` (Black) for cost / ATK / HP numerals — matches AAA card-game stat-orb conventions (Hearthstone, MtG Arena)
- `font_body` — Nunito Regular for descriptions

Both Cinzel variations set `spacing_bottom = -3` to optically center caps-only text (caps don't use descender space, so geometric center renders ~1.5px high). If text still looks high, increase the negative value; if low, push toward 0.
