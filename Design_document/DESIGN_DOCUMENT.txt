BURNING MEADOW — Game Design Document (v1.0 Implementation)
=============================================================

1. OVERVIEW
-----------

Burning Meadow is a lane combat roguelike deckbuilder built in Godot 4.6
(gl_compatibility renderer, 2D). The player navigates a branching map across
3 acts, fighting premade encounters on a 4x4 board -- 4 lanes wide x 2 rows
(front/back) per side. Combat is simultaneous with a Swift pre-phase, plus
floop abilities, sacrifices, and spells. Inspired by Card Wars (lane combat,
floop abilities) and Slay the Spire (roguelike meta-progression, map structure,
shop/rest/event nodes). The back row is play/queue space, not a separate
combat tier -- front rows attack first and are attacked first.

Core Loop:
  Main Menu -> Starting Relic Pick (programmatic overlay) -> Map ->
  Combat / Shop / Rest / Event -> Card Reward -> Map -> ... -> Act Boss ->
  Next Act (fresh map) -> ... -> Act 3 Boss -> Victory / Game Over

Scene transitions use get_tree().change_scene_to_file(). Run state is
checkpointed to user://run_N.save every time the player commits to a map node,
so quitting and relaunching resumes at that room. The save is cleared on death
or final victory.

3. COMBAT SYSTEM
-----------------

3.1 Board Layout

  4 lanes x 2 rows per side: each side has a FRONT row and a BACK row, mirrored
  across the centre line. 8 player slots (front 0..3 / back 0..3) face 8 enemy
  slots in the same layout. Front and back are mechanically identical -- both
  rows attack each turn -- but the front row resolves first and is also hit
  first. The back row is effectively queue space (room to maneuver), not a
  separate combat tier. A column is "empty" for face-damage purposes only when
  BOTH the opposing front and opposing back lanes were empty at start of
  combat. Canonical accessors in Combat.gd are `_player_field` / `_enemy_field`
  (front) and `_player_back` / `_enemy_back`, surfaced via `_row_array(is_enemy,
  row)` with ROW_FRONT = 0 and ROW_BACK = 1.

3.2 Round Flow (Current Implementation)

  FIGHT START (once, before round 1)
    |-- _place_starting_board() seats the encounter's opening creatures on the
    |     enemy front row (back row only used as overflow). Act / encounter
    |     type sets the starting count.
    +-- _start_round() runs for the first time -> round_number becomes 1.

  ROUND START
    |-- Tick down persistent ATK buffs (Butcher's Cleaver etc.)
    |-- Keyword effects: Regenerate heals 1, Wither reduces ATK
    |-- Encounter passive start-of-round triggers
    |-- Mana refills to base + relic bonuses + up to 1 banked (Ice Cream
    |     uncaps banking)
    |-- Enemy intents assigned and displayed
    |-- Escalation check (round >= ESCALATION_REINFORCE_ROUND etc.)
    |-- Player draws 4 cards (Courier's Bag: +1 on turn 1)
    +-- PLAYER TURN begins

  PLAYER TURN (free actions in any order)
    |-- Play creatures from hand (drag above play line)
    |     +-- Lane selected by mouse position, rejects occupied slots in both
    |         rows of the chosen column
    |-- Play spells (drag above play line, then click target)
    |-- Toggle Floop on battlefield creatures (click)
    |     +-- Flooping PREVENTS the creature from attacking this turn
    |-- Sacrifice once per turn (S key or button)
    +-- End Turn (E key or button)

  END TURN
    |-- Resolve Floop abilities (flooped creatures skip combat; player floops
    |     fire ON_PLAYER_FLOOP reactives)
    |-- Resolve enemy non-attack intents
    |-- SWIFT PHASE: Swift creatures strike first, front row then back row,
    |     each side alternating lane-by-lane
    |-- PLAYER ATTACK PHASE: player front row attacks (lanes 0->3), then
    |     player back row attacks (lanes 0->3). Each column's front opposing
    |     creature is hit first; if it is dead or never existed, the back-row
    |     creature is exposed; if both opposing slots in the column were empty
    |     at start of combat, the attack lands as face damage.
    |-- ENEMY ATTACK PHASE: mirror order -- enemy front, then enemy back.
    |-- Ranged creatures attack random targets (back row preferred, then front)
    |-- Piercing excess -> opposing back row first, then face
    |-- Thorns reflect 1 damage back (bypasses Armored)
    |-- Deaths processed, on-death effects trigger (ON_CREATURE_DEATH
    |     reactives fire here)
    |-- Berserker growth (+1 ATK if attacked)
    |-- Cleanup dead creatures (REMOVED from fight, not recycled)
    |-- Discard hand (Retain cards kept)
    |-- Enemy places 1-2 creatures from its ordered deck onto the enemy front
    |     row (back row as overflow). Escalation may double-place.
    |-- Assassin self-destruct check
    |-- Encounter end-of-round passives
    |-- Check win/loss
    +-- Next round starts

3.3 Combat Phases Detail

  SWIFT PHASE: Creatures with Swift attack before sequential combat. Resolves
  front-row first then back-row, alternating sides lane-by-lane (player lane 0,
  enemy lane 0, player lane 1, enemy lane 1, ...).

  SEQUENTIAL PHASE: Player attacks first -- front row lanes 0->3, then back row
  lanes 0->3. Then the enemy mirrors -- enemy front 0->3, then enemy back 0->3.
  Each attacker targets the opposing creature in the same column: front first;
  if the front is dead/empty the back-row creature is hit; if BOTH opposing
  slots in the column were empty at combat start, the attacker deals face
  damage. If an attacker kills its target, the target does NOT retaliate.

  RANGED: Ranged creatures skip normal column combat. They attack a random
  enemy creature, preferring back-row targets (then front, then face if none
  remain). Their column still counts toward face-damage rules.

  PIERCING: When a creature with Piercing kills its opponent, excess damage
  carries through to the opposing back-row creature in the same column if one
  exists; otherwise it hits the enemy hero's HP.

  THORNS: When a creature with Thorns is attacked, it deals 1 damage back to
  the attacker (bypasses Armored).

3.4 Sacrifice System

  Once per turn, the player can sacrifice a friendly creature on the
  battlefield as a free action. This triggers the creature's on-death effect.
  Activated via S key or HUD button. Visual: valid sacrifice targets get red
  border highlight during sacrifice mode.

  Sacrifice is NOT a widespread keyword/cost system -- it's primarily the free
  once-per-turn action above. A handful of individual cards opt into sacrifice
  as part of their own effect (Bloodsworn is the only creature that REQUIRES a
  sacrifice to play; Offering, Fuel the Pyre, Blood Pyre's floop, Mass Grave,
  and Apocalypse fold sacrifice into their resolution). The vast majority of
  cards never touch the sacrifice mechanic at all.

3.5 Floop System

  Creatures with a Floop ability can be toggled on the battlefield by clicking
  them. A flooping creature CANNOT ATTACK that turn — it activates its special
  ability instead. This makes every floop a real decision: use the ability or
  deal combat damage. Visual: blue "FLOOP" indicator and blue border. Player
  floops fire the ON_PLAYER_FLOOP reactive passive hook. Echo Staff relic
  triggers each floop twice. "Adjacent" for floops means same-row lane neighbours
  on the flooping creature's row; buff_adjacent_atk also reaches the column-mate
  in the other row.

  Floop Types (dispatched in Combat._resolve_floop_ability):

    DAMAGE: damage_any, damage_opposing, damage_opposing_splash,
      damage_opposing_heal, damage_all_enemies, damage_all, damage_face,
      damage_self_opposing, drain, execute, slay_draw, unleash_atk,
      graveyard_damage, discard_top_damage

    BUFF / HEAL: heal_self, heal_adjacent, heal_all_friendly, grow_atk,
      grow_per_enemies, buff_all_atk_permanent, buff_target_hp,
      buff_tokens_atk, buff_adjacent_atk

    DEFENSE: temp_armored, grant_armored_all, shield_adjacent, buff_thorns,
      grant_thorns_adjacent, redirect_adjacent, stun_opposing

    CARD / ECONOMY: draw, scry, reorder_deck, filter_draw, raise_dead,
      gain_gold, gain_mana, discount_next, spawn_token_hand

    MOVEMENT: relocate, challenge

    SUMMON / TRANSFORM: summon_random, summon_token, kill_adjacent_summon,
      steal_atk, devour_adjacent, copy_opposing_floop, swap_atk, become_copy,
      blood_sacrifice

3.6 Spell System

  Spells are played from hand like creatures (drag above play line). Targeted
  spells enter targeting mode -- click a valid target to resolve. Non-targeted
  spells resolve immediately.

  Targeting Types:
    none ................... Resolves immediately (AoE, self-buff, draw)
    enemy_creature ......... Must click an enemy creature
    friendly_creature ...... Must click a friendly creature
    any_creature ........... Click any creature on the board
    any .................... Click any creature or hero

  Spell Effect Types:
    damage ................. Deal X to target creature
    damage_face ............ Deal X to enemy hero
    damage_all_enemies ..... Deal X to all enemy creatures
    damage_all ............. Deal X to ALL creatures (both sides)
    buff_atk ............... Target creature +X ATK (permanent or this-turn)
    buff_hp ................ Target creature +X HP
    buff_all_atk ........... All friendly creatures +X ATK
    heal ................... Remove X damage from target creature
    draw ................... Draw X cards
    custom ................. Special handler in Combat.gd

  Custom Spells: shove, gambit, blood_tithe, reckless_charge, scrap, barricade,
  second_wind, reposition, lightning, offering, grave_pact, fuel_the_pyre,
  pillage, echo_spell, kings_command, unholy_bargain, mass_grave, dark_pact,
  war_chant, grave_robbery, cataclysm, soul_swap, apocalypse, adrenaline,
  bloodletting, turbo, concentrate, recycle, inferno, overwhelming_force,
  lay_on_hands, mending_light, banish, time_snare, holy_smite

3.7 Deck System

  Draw pile and discard pile store card IDs (strings). When a card is drawn,
  CardDB.get_card_data(id) is called to get the card data.

    - Dead player creatures are REMOVED from the fight entirely (not recycled)
    - Discarded hand cards go to discard pile (for deck recycling)
    - Exhausted spells go to exhaust pile (removed from fight)
    - Retained cards stay in hand at end of turn
    - When draw pile is empty, discard pile is shuffled into draw pile

  This means your deck shrinks as creatures die in combat. Card draw becomes
  valuable as you race against running out of playable cards.

3.8 Mana System

  Base mana: 3 per turn. Up to 1 unspent mana carries over to the next turn
  (Ice Cream relic removes the cap). Boss relics can permanently increase max
  mana by +1 each, at the cost of a significant downside.

  Mana generation sources:
    - Boss relics: +1 max mana permanently (with downside)
    - Regular relics: Lantern (turn 1 bonus), Happy Flower (every 3 turns),
      Ice Cream (full banking), Art of War (bonus if no cards played),
      Sundial (+2 every 3 shuffles)
    - Spell cards: Adrenaline, Bloodletting, Turbo, Concentrate, Recycle,
      Offering, Scrap, War Chant
    - Creature floops: Mana Sprite (gain 1), Leyline Conduit (gain 2)
    - Creature passive: Leyline Conduit (+1 mana per turn while alive)

3.9 Enemy AI

  Enemies place 1-2 creatures per round from a premade ordered deck (from
  EncounterDB) during _post_combat_sequence (i.e. at the end of the round,
  ready for the player's next turn). The first 2 rounds always place 1; elites
  and bosses always place 2; normal fights place 2 on a 1-in-3 roll.

  Placement priority is always front-row first, back-row only as overflow:
    Elite ..... targets the player's strongest column first, then other
                player-occupied front lanes.
    Boss ...... shuffled across empty front lanes.
    Regular ... blocks player-occupied front columns first, then any empty
                front lane.
  Any unfilled remainder is then filled into back-row slots (lanes 0..3,
  shuffled). When the deck runs out the encounter's reinforcement creature is
  appended infinitely. Past ESCALATION_REINFORCE_ROUND (round 8) regular fights
  double-place each round, and past round 12 the reinforcement gains +1/+1 per
  round.

5. KEYWORD SYSTEM (16 Keywords)
--------------------------------

  Armored ........... Takes 1 less damage from creature attacks (min 1)
  Swift ............. Attacks before simultaneous combat phase
  Ranged ............ Attacks back-row enemies first, then front. Blocked
                      column is fine. Lane still counts toward face-damage rules
  Thorns ............ Deals 1 back to anything that attacks it (bypasses Armored)
  Regenerate ........ Heals 1 HP at start of each round
  Summon ............ Summons 1/1 token in adjacent empty lane on play
  Last Stand ........ First lethal hit leaves it at 1 HP instead
  Piercing .......... Excess kill damage hits the opposing back row, then face
  Sacrifice ......... Must kill a friendly creature to play this card.
                      Listed for completeness, but only ONE creature in the
                      whole card pool (Bloodsworn) actually carries this as a
                      play-cost keyword. A few spells/floops fold sacrifice
                      into their resolution (see 3.4) -- they don't tag the
                      keyword. Not a tribal-style mechanic; not a build-around.
  Exhaust ........... Removed from fight after use (not recycled)
  Retain ............ Kept in hand instead of discarding at end of turn
  Wither ............ Loses ATK at start of each round (min 0)
  On-Enter .......... Effect triggers when creature is placed on board
  On-Death .......... Effect triggers when creature dies
  Floop ............. Skip attack to use special ability (toggle)
  Adj. Buff ......... Neighboring creatures get stat bonus

  On-Enter Types (KeywordEffects._run_on_enter): damage_opposing,
    damage_opposing_draw, damage_random_player, damage_all_enemies, draw,
    gain_gold, atk_per_cards_played, damage_face, debuff_opposing_atk,
    discard_random, copy_friendly, copy_opposing_keywords, copy_last_dead,
    look_top, cast_random_spell

  On-Death Types (KeywordEffects._run_on_death): damage_opposing_lane,
    damage_opposing, damage_all_enemies, summon, bonus_mana,
    return_to_hand_once, damage_face, debuff_all_player_atk, damage_adjacent


5.1 TRIBE SYSTEM -- NOT IMPLEMENTED

  Tribes (Wild / Undead / Order / Arcane) were planned in earlier drafts but
  are NOT present in code: no creature in CardDB.gd carries a tribe field, and
  the proposed tribal payoff cards (Pack Hunter, Fanatic, Pyre Keeper, Battle
  Sage) were never added. The card lists in section 4 have had their [Tribe]
  tags stripped to reflect current code. Card-to-card synergy still exists
  (Bannerman buffs all friendlies, Gravedigger draws on ally death, Corpse
  Eater scales with friendly deaths) but operates on "friendly creature"
  rather than tribal membership. Whether to reintroduce tribes is an open
  design decision; the original four-tribe intent is preserved in version
  history.

7.10 Reactive Passives
----------------------

Beyond the start/end-of-round passive in 7.1-7.9, ten encounters carry a
second layer: a REACTIVE passive that fires the moment the player takes a
specific action. This is the system's main answer to "what makes each fight
feel mechanically distinct?" -- the base passive sets the rhythm, the reactive
passive punishes a specific play pattern.

Triggers and their meanings:

  ON_PLAYER_SPELL      -- fires when player resolves a spell card.
  ON_PLAYER_SACRIFICE  -- fires when player sacrifices a creature.
  ON_PLAYER_FLOOP      -- fires when a player flooper resolves its ability.
  ON_PLAYER_SUMMON     -- fires when a player places a creature (hand or token).
  ON_CREATURE_DEATH    -- fires when ANY creature on either side dies.
  ON_PLAYER_DRAW       -- fires when player draws beyond the standard 4-card hand.

Each reactive passive runs ONCE per qualifying event and is independent of the
encounter's normal start/end-of-round passive. Reactive effects are skill-
expression levers: the player can avoid the trigger by adapting their plan
(e.g. don't sacrifice into Cultist Enclave; don't spell-spam vs Archlich).

Reactive lineup (per encounter):

  Orc Warband           ON_PLAYER_SPELL     Chieftain +1 ATK permanent
  Necromancer's Tower   ON_CREATURE_DEATH   enemy on-death triggers twice
  Cultist Enclave       ON_PLAYER_SACRIFICE 2 face damage
  Haunted Crypt         ON_PLAYER_FLOOP     1 damage to the flooping creature
  Demon Vanguard        ON_PLAYER_FLOOP     1 damage to the flooping creature
  The Puppeteer         ON_PLAYER_SUMMON    summon a 2/2 Puppet
  Mirror Temple         ON_CREATURE_DEATH   all surviving enemies heal 1
  Executioner's Block   ON_PLAYER_DRAW      1 face per extra card past 5
  The Archlich          ON_PLAYER_SPELL     summon a 1/1 Bone Shard
  The Void Walker       ON_PLAYER_DRAW      exile an extra card from deck

Example -- Necromancer's Tower:
  Base passive: when an enemy dies, summon a 1/2 Skeleton in a random lane.
  Reactive (ON_CREATURE_DEATH): the dying enemy's own on-death effect runs
  twice. So a Bone Knight (on-death: summon 2/2) summons two 2/2s AND the
  Tower's passive then drops a 1/2 Skeleton -- one death produces three new
  bodies. The reactive trigger re-runs the dying card's on-death directly
  rather than dispatching through the death pipeline, so it doesn't recurse
  through itself.

Example -- The Archlich:
  Base passive: enemy creatures cannot be reduced below 1 HP by creature
  attacks; only spells/effects can finish them. Reactive (ON_PLAYER_SPELL):
  summon a 1/1 Bone Shard. The two stack into a deliberate puzzle -- the
  player needs spells to finish enemies, but each spell adds a fresh body.
  Wide AOE (Apocalypse, Earthquake) wins this fight; spamming Fireball loses
  it.

Reactive passives are defined in REACTIVE_PASSIVES inside EncounterDB.gd; the
combat dispatcher is _dispatch_reactive(trigger, source_card, lane_idx) in
Combat.gd.


8. MAP & PROGRESSION
----------------------

8.1 Map Structure

  Each act map is procedurally generated as a 15-row x 7-column grid using a
  Slay-the-Spire-style algorithm. The map renders horizontally (player walks
  left -> right toward the boss), but the data axes still call row the
  start->boss axis and col the lane axis.

  Generation steps (RunState._generate_act_map):
    1. Walk NUM_PATHS = 4 paths from row 0 to REST_ROW (row 13). Each step
       moves +/-1 column or stays, with a no-crossing rule so two diagonals
       never form an X. Path #2 must start on a different column than path #1.
       Where a destination cell is already populated, candidates get double
       weight so paths prefer to merge (organic, convergent landmarks).
    2. Row 0 = all Combat. Row 13 (REST_ROW) = all Rest sites.
       Rows 1..12 roll node types from a cumulative probability table:
         Shop  10%, Rest 12%, Elite 10%, Event 22%, Combat 46%.
       Rules:
         - Elite and Rest cannot appear before MIN_ELITE_ROW (row 5).
         - Rest cannot appear on the row just below REST_ROW.
         - Elite / Shop / Rest may not follow the same type on any incoming path.
         - Sibling nodes sharing a parent must have distinct types.
         If 200 retries fail, the slot falls back to Combat.
    3. A single Boss node (BOSS_ROW = 14) is placed in the center column.
       Every populated REST_ROW node connects to it, so all paths converge.
    4. Encounters are dealt out of EncounterDB by type (combat / elite / boss),
       shuffled by the run seed so each map plays differently.

8.2 Node Types

  Combat (sword icon) ...... Standard fight from EncounterDB
  Elite (skull icon) ....... Harder fight, better rewards (rare-weighted)
  Boss (crown icon) ........ Act boss, must defeat to advance
  Rest (campfire icon) ..... Heal to full, upgrade a card, or remove a card
  Shop (diamond icon) ...... Buy cards, relics, potions, remove cards
  Event (? icon) ........... Random choice encounter with tradeoffs

  All node icons sit on inked plates with a hand-drawn dashed parchment route
  between them. Visited nodes dim and gain a checkmark; the player's current
  position is marked with a red "YOU" chevron.

8.3 Act Progression

  After defeating an Act boss, the player advances to the next act with a fresh
  map. After Act 3's boss (THE DEVIL), the game is won.

8.4 Card Reward Rarity Weights

                Common    Uncommon    Rare
  Act 1         70%       25%         5%
  Act 2         50%       35%         15%
  Act 3         35%       35%         30%
  Elite         0%        70-95%      5-30%
  Boss          0%        0%          100%

  Reward offers 3 cards (4 with Scout's Emblem). Player picks 1 (2 with
  Collector's Tome), or skips.


9. CARD UPGRADE SYSTEM
------------------------

Available at Rest Sites. Three upgrade paths:

9.1 Sharpen
  Creature: +2 ATK (+3 with Blacksmith's Hammer)
  Spell:    +2 spell damage value (+3 with Blacksmith's Hammer)

9.2 Fortify
  Creature: +2 HP (+3 with Blacksmith's Hammer)
  Spell:    -1 mana cost (min 0)

9.3 Imbue
  Creature: Add keyword from [Piercing, Swift, Thorns, Regenerate].
            2 random choices shown (3 with Blacksmith's Hammer).
  Spell:    Choose: Add Retain keyword, OR double effect value + add Exhaust

Upgraded cards display with "+" suffix (e.g., "Footman +"). Upgrades tracked
per deck index via UID system and applied at draw time.

11. REST SITES
---------------

Three options (pick one):
  1. REST ...... Heal to full HP.
                 Disabled at max HP, or blocked entirely by the
                 Coffee Dripper downside ("Blocked by Coffee Dripper").
  2. UPGRADE ... Choose a card, then pick Sharpen / Fortify / Imbue.
                 Disabled when every card is already upgraded, or blocked
                 entirely by the Fusion Hammer downside.
  3. REMOVE .... Remove one card from the deck. Disabled when deck size <= 1.

  - Hand auto-sorted by cost after drawing.
  - Tooltips with full card info and keyword descriptions.
  - Targeted spells use a spell-targeting overlay (click-to-resolve) handled
    via Combat._input(), not the card-drag system.

13.7 Battlefield
  - 4x4 board (4 lanes x front/back rows per side).
  - Lane glow during card drag:
      Green highlight on valid target lane
      Red highlight on occupied lanes
      Dim glow on other empty lanes
  - Sacrifice mode: red border highlight on valid targets
  - Floop toggle: blue "FLOOP" indicator and blue border

13.8 Visual Feedback
  - HP flash on damage (red pulse with size increase)
  - Screen shake on significant damage (CanvasLayer offset)
  - Reshuffle notification when draw pile refreshes
  - Floating gold-spend / gold-gain numerals (GameTheme.spawn_floating_text)
  - Floating combat damage and heal numbers

13.9 Persistence
  - In-progress runs save to user://run_N.save (3 slots) on every node visit;
    relaunching offers Continue from the most recent slot. The save is
    cleared on death or final victory.
  - MetaState tracks cross-run win/loss counts to user://meta.save and gates
    ascension tier unlocks.

13.10 Admin/Debug
  - F1: Instant win (sets enemy HP to 0)

16. AUDIO SYSTEM
------------------

The audio layer is intentionally thin: a single autoload (`AudioBank`) loads
SFX variants and music tracks from disk, plays them through Godot's
AudioServer buses, and no-ops gracefully whenever a file is missing -- so the
game runs identically with or without the audio folder populated. Volume,
bus setup, and persistence live in `UserSettings`.

16.1 AudioBank API (scripts/AudioBank.gd)
  - play_sfx(event, pitch_jitter=0.06, volume_db=0.0)
      Picks a random variant from assets/audio/sfx/<event>/ and plays it
      through a 12-player round-robin pool on the SFX bus. Pitch is jittered
      by +/- pitch_jitter so rapid-fire plays don't sound mechanical.
  - play_music(track, fade_seconds=1.0)
      Crossfades to assets/audio/music/<track>.{ogg,wav,mp3} via an A/B
      AudioStreamPlayer pair. Same-track call is a no-op. Stream's loop
      flag is forced on so ambient beds don't stop after one play.
  - play_music_random(candidates, fade_seconds=1.0)
      Picks one track from the array and crossfades to it. The
      currently-playing track is excluded from the pool, so consecutive
      fights never start on the same song when the pool has 2+ entries.
  - stop_music(fade_seconds=0.6)
      Fades both A/B players to silence and stops them.
  - Missing files: every loader and resolver returns early on absent
      directories / streams, so the game tolerates a fully empty
      assets/audio tree without raising errors.

16.2 Music slots
  Each scene calls play_music() (or play_music_random()) on entry. Combat
  picks per node type and act:

  - main_menu .............. Title screen (MainMenu.gd)
  - map .................... Overworld / map view (MapView.gd)
  - shop ................... Shop scene (Shop.gd)
  - rest ................... Rest site (Rest.gd)
  - event .................. Event / story node (Event.gd)
  - victory ................ GameOver win screen (GameOver.gd)
  - defeat ................. GameOver lose screen (GameOver.gd)
  - combat_elite ........... All elite fights (any act)
  - combat_boss ............ Act 1-2 boss fights
  - combat_boss_act3 ....... Act 3 boss only (heavier symphonic-metal track)

  Standard fight pools (random pick via play_music_random, excludes the
  previously-played entry so back-to-back fights never repeat):

      Act 1 .. [combat, combat_act1_b]
      Act 2 .. [combat_act2, combat_act2_b]
      Act 3 .. [combat_act3, combat_act3_b]

16.3 SFX events
  All triggered via AudioBank.play_sfx(event). Each event folder may hold
  multiple variants; one is chosen at random per play.

  - card_play .......... Player plays a creature (Combat._play_card)
  - spell_cast ......... Player casts a spell (Combat._resolve_spell)
  - card_draw .......... Card drawn into hand (Combat._draw_card)
  - card_discard ....... End-of-turn discard sweep (Combat)
  - hit ................ Attack lands on a creature (Card2D.take_damage)
  - hit_hero ........... Player or enemy hero takes damage (Combat)
  - death .............. Creature dies (Card2D destruction path)
  - floop .............. A floop ability activates (Card2D)
  - heal ............... Creature is healed
  - coin ............... Gold gained / spent (Shop, Reward)
  - turn_start ......... Round banner appears (Combat); first round of
                         combat plays at volume_db=+3.0 as a louder cue
  - victory ............ Combat won (Combat)
  - defeat ............. Combat lost / run ended (Combat)
  - button_click ....... Any major button press

16.4 Licensing
  The soundtrack is a mix of CC0 (Public Domain) and CC-BY 3.0 tracks
  sourced from OpenGameArt.org. CC-BY 3.0 tracks require ongoing
  attribution; the credit lines are kept visible to players in the in-game
  Credits screen (scripts/scenes/Credits.gd) and mirrored in
  assets/audio/music/MUSIC_CREDITS.md. Required attributions:

  - "A Fight in the Fields", "Out Of Time", "The Fallen" -- Jonathan Shaw
      (www.jshaw.co.uk), from his RPG Orchestral Essentials packs
  - "The Tread of War" -- Jonathan Shaw, Johan Brodd (jobromedia), and
      cynicmusic (built on cynicmusic's "Battle Theme A")

  All SFX are Kenney CC0 (Interface Sounds 1.0); attribution is not
  required but is given in Credits anyway. Track-to-file mapping for both
  music and SFX lives in the two credits files alongside source URLs.

16.5 Settings
  Volume is controlled from the Settings overlay (gear icon, top-left of
  every scene; Esc also opens it) with three sliders in the AUDIO section:

  - Master ... bus 0 ("Master"), default 100%
  - Music .... "Music" bus, default 70% (full music drowns out SFX)
  - Effects .. "SFX" bus, default 100%

  Sliders feed UserSettings.set_master_volume / set_music_volume /
  set_sfx_volume; each setter calls linear_to_db, applies the new value via
  AudioServer.set_bus_volume_db, mutes the bus at 0, and persists the value
  to user://settings.save (JSON). The Music and SFX buses are created at
  startup by UserSettings._setup_audio_buses() and routed to Master.
  AudioBank's pooled players are pre-assigned to these buses on construction.

  A separate "Mute on Focus Loss" toggle (default ON) silences the Master
  bus while the game window is unfocused, restoring volume on focus return.


17. ROADMAP / KNOWN GAPS vs GENRE PARITY
------------------------------------------

This section catalogues the systems and presentation pieces that were
identified as gaps when Burning Meadow v1.0 was compared against the
contemporary roguelike-deckbuilder bar (Slay the Spire, Monster Train,
Wildfrost, Inscryption Act 1, Cobalt Core). Items marked NOT IMPLEMENTED
are absent from the current build. Items marked PARTIAL have an existing
foundation in code; their "Current state" section describes what already
ships, and the "Still missing" / "Planned" section describes what would
close the gap. Each item is written in the same spirit as 5.1 (TRIBE
SYSTEM).

17.1 Alternate Characters / Classes -- NOT IMPLEMENTED

  Current state: One playable hero. The starter deck is fixed (4x Goblin,
  4x Brute, 1x Sprite, 1x Troll). The same draftable pool of ~104 cards is
  rolled on every run regardless of intent.

  Gap vs genre: Slay the Spire ships four characters, each with its own
  ~75-card pool and distinct mechanical identity. Monster Train pairs 5
  clans for 20 combos. Wildfrost has 3 tribes x 3 leaders. A single-hero
  deckbuilder caps at one strategic vocabulary -- after first clear, every
  subsequent run opens the same way.

  Planned (not implemented): three alt characters that REUSE the existing
  card/enemy pool rather than requiring a fresh content layer. Each leans
  on a slice of the current card pool to give that hero an identity.

    THE NECROMANCER (sacrifice / on-death tribe; 22 starting HP)
      Starter deck: 4x Skeleton (1/1, on-death: draw 1, new card), 2x Bone
      Acolyte (1/2, floop: sacrifice friendly to summon 2/2), 2x Ratling,
      1x Blood Pyre, 1x Offering. Reward pool biases sacrifice / on-death
      cards into common/uncommon weight: Bloodsworn, Mass Grave, Corpse
      Eater, Warden of Graves, Grave Robbery, Dark Pact, Fuel the Pyre,
      Necromancer, Vampire Lord. Frail HP forces the player to USE the
      sacrifice economy rather than tanking.

    THE WITCH (spell-only / no-creature opener; 20 starting HP)
      Starter deck: 4x Flame Bolt, 4x Slash, 2x Provision. Cannot play
      creatures from her starter; the board fills via spell side-effects
      (Chaos Imp's random-spell-on-enter chain, summon-from-spell cards,
      a hero "Familiar" 1/1 token she generates each round). Hero ability:
      every spell cast also deals 1 face damage. Reward pool biases spells.

    THE MARSHAL (formation / banner / token tribe; 28 starting HP)
      Starter deck: 4x Footman (renamed Brute), 2x Pikeman, 2x Squire
      Captain, 1x Battle Drummer, 1x War Cry. Identity is adjacency,
      tokens, and stacking ATK buffs. Reward pool biases Royal Guard,
      Bannerman, Paladin, Iron Bastion, Battle Hymn, King's Command,
      Inspire.

  Implementation skeleton (notes for future work):
    - RunState.starter_character: String, set at the new "character pick"
      step before starting-relic pick.
    - CardDB.get_starter_deck(character_id) -> Array[String]
    - CardDB.roll_card_reward gains a character_id filter that re-weights
      certain cards from rare->uncommon or uncommon->common for the
      matching hero (cheap to implement: a per-character "promotions"
      dict mapping card_id -> rarity_shift).
    - RelicDB.roll_relic_reward gains the same bias (Bone Pile guaranteed
      to surface for Necromancer, Worn Spellbook for Witch, Banner of
      Unity for Marshal).
    - MetaState tracks wins-per-character so the ascension cell count
      can grow with character count rather than being capped at the
      single-hero footprint.

17.2 Run History / The Memorial Wall -- NOT IMPLEMENTED

  Current state: MetaState tracks total runs / victories / defeats /
  fastest floor / unlocked ascension. No per-run data is stored. When a
  run ends there is no record of what the player actually tried -- no
  deck snapshot, no relic list, no path traversal, no seed -- only the
  cumulative win/loss counter ticking up.

  Gap vs genre: Slay the Spire stores roughly the last 50 runs with a
  full deck snapshot, relic list, floor reached, killing blow, gold
  accumulated, and per-floor decision log. Players replay defeats in
  their head and learn from them. Monster Train, Wildfrost, and even
  Inscryption (the Act 1 dead-card list) all carry similar memory
  hooks. No history means the player can't reflect, and the meta is
  structurally amnesiac.

  Planned (not implemented): THE MEMORIAL WALL -- a scene accessed from
  the main menu. Thematically a dusk meadow with small ember-candles
  marking each completed run (lit blue for victories, red for deaths,
  dimmed for old entries past slot 50). Clicking a candle opens that
  run's record:

      Hero ............ Marshal / Witch / Necromancer (per 17.1)
      Outcome ......... Victory at floor 14, OR "Killed by Iron Vanguard
                        on floor 9 of Act 2"
      Ascension ....... A3
      Final deck ...... grid of Card2D nodes with upgrades applied
                        (re-rendered from cached card_ids + upgrades)
      Relics .......... icon row grouped by tier
      Path ............ thumbnail of each act's map with route drawn
      Seed ............ "BM-A3F4C2..." (clickable to copy for replay)
      Duration ........ 1h 47m

  Storage: append-only JSON list in user://run_history.save, capped at
  100 entries with FIFO eviction. Written once at GameOver, not per-node,
  to avoid disk churn. Each entry is ~2-3KB; 100 entries fits in 300KB.

  Why a wall and not a table: BM's tone ([[burning-meadow-tone]]) is
  multi-register, and the burning-meadow imagery wants a visual metaphor
  for memory rather than a spreadsheet. The wall reads as story; the
  table reads as stats. The data is the same -- the framing isn't.

17.3 Card-Play Animation & Spell VFX Layer -- PARTIAL

  Audit note: a first-pass spell VFX layer ALREADY EXISTS in the code.
  Combat._play_spell_cast_vfx() at Combat.gd:5723 routes spells to
  color-coded particle bursts (warm red for damage, deep red for face /
  AoE damage, gold for ATK buffs, green for heal, blue for draw, purple
  for custom). Combat.spawn_spell_burst() spawns an 18-particle one-shot
  with gravity and self-free. AudioBank.play_sfx("spell_cast") plays
  alongside. So "every spell has a visual" is cleared at a basic
  color-coded tier. What follows describes the gap from that tier to
  the genre bar.

  Current state: Cards snap from hand into their lane slot with no
  intermediate motion. Spells resolve as instant state changes plus a
  generic "spell_cast" SFX. There are NO per-archetype visual effects
  for spells -- Apocalypse, Earthquake, Lightning, Flame Bolt, Holy
  Smite, and Time Snare all look identical visually (zero VFX). The
  total visual-effect budget is CanvasLayer screen shake, CPUParticles2D
  ember bursts on sacrifice and piercing exits, and HP color flashes.

  Gap vs genre: this is the single biggest "feels prototype" tell.
  Hearthstone / MtG Arena ship per-card on-cast VFX as table stakes.
  Even Slay the Spire (2017 indie) gives every attack and skill its own
  tween, color, and particle hit. Cobalt Core spent disproportionate dev
  time on calibrated screen-shake-per-impact. Wildfrost's squash-and-
  stretch IS the game feel. BM currently sits near the 2014 mobile
  card-game motion bar.

  Planned (not implemented): a tiered VFX layer, built in this order.

    TIER 1 (cheap, mandatory): card-play tween from hand to lane slot
    via a small arc (Tween, ~0.35s, ease_out, +5% scale punch at lane
    impact, settle to 100%). Sacrifices and on-death exits already use
    ash-burst particles -- extend the same vocabulary to play arrival
    so motion language stays consistent.

    TIER 2 (medium): per-archetype spell VFX, six families. Each family
    is one particle preset plus one tween pair (~50 lines per family).
    Cards map to a family by spell type or by a new tag in CardDB.

        FIRE ........ Flame Bolt, Fireball, Inferno, Fuel the Pyre
                      (rising orange particle cone + screen warm)
        SHOCK ....... Lightning, Holy Smite, Time Snare
                      (white-blue zigzag via Line2D + brief flash)
        BLIGHT ...... Dark Pact, Mass Grave, Bloodletting, Apocalypse,
                      Curse, Unholy Bargain
                      (purple sweep + skull-mote particles)
        BLESSING .... Patch Up, Lay on Hands, Mending Light, Battle
                      Hymn, Inspire, War Cry
                      (golden upward shimmer + soft bloom)
        EARTH ....... Earthquake, Shove, Reposition, Cataclysm,
                      Overwhelming Force
                      (brown dust + 6px screen shake along Y)
        MIND ........ Concentrate, Adrenaline, Gambit, Echo, Banish,
                      Soul Swap, Grave Pact
                      (slow pale sweep + pulse on target frame)

    TIER 3 (rich, optional): unique VFX for the boss-tier rare spells
    (Apocalypse, Cataclysm, Inferno, Overwhelming Force, King's
    Command). These should be the "you built toward this card" wow
    moments. One bespoke effect each. Only build if budget remains.

  Implementation order: TIER 1 first (it touches every card), TIER 2
  next (greatest "feels like a real game now" jump), TIER 3 last.

17.4 Nested Keyword Tooltips & Information Layer -- PARTIAL

  Audit note: keyword COLORIZATION in card descriptions ALREADY WORKS.
  KeywordEffects.colorize_keywords() (KeywordEffects.gd:46) wraps any
  keyword display name found in card.desc with BBCode gold tags
  ([b][color=#e8b547]...[/color][/b], 5.1:1 contrast / WCAG AA on the
  parchment well). Card2D's description label has bbcode_enabled = true
  (Card2D.gd:2020) so the gold renders. Matching is case-insensitive,
  word-boundary safe, longest-first ("Last Stand" matches before
  "Last"). KeywordEffects.tooltip_for(keyword) provides a static
  glossary string. So players ALREADY see which words are mechanical
  keywords. What's missing is HOVER popups on those gold spans, nested
  chaining, encounter-passive-name hover, and a top-level COMPENDIUM
  scene -- see below.

  (Original "card tooltips show the full card description plus a static
  keyword glossary panel in the corner" framing remains accurate for
  the hover-popup gap.)

  Gap vs genre: Slay the Spire ships nested keyword tooltips as one of
  its most-praised UX features. Hovering "Vulnerable" on a card pops
  an explainer; if that explainer mentions "Frail", hovering Frail
  inside the popup chains another popup. The information graph is
  navigable from any card without leaving the hover. Hearthstone, MtG
  Arena, and Inscryption (Act 1's lexicon) all do versions of this.
  BM's 16 keywords plus ~30 floop / spell / encounter-passive terms
  are a real cognitive load and a static glossary doesn't scale.

  Planned (not implemented):
    - Card description gets keyword spans wrapped in a hover hook.
      Card2D parses card.desc for known keyword tokens at build time
      and substitutes RichTextLabel BBCode spans.
    - Hovering a keyword span pops a small parchment tooltip
      (~300x120, anchored to the keyword's screen position) using
      KeywordEffects.KEYWORDS[name].description.
    - If the tooltip's text mentions another keyword, that token is
      ALSO a hover hook (chained). Nested tooltips shrink slightly
      and offset 20px so the chain is readable.
    - Encounter passive panel gets the same treatment: passive names
      and reactive trigger names (ON_PLAYER_SACRIFICE) are hoverable
      and explained.
    - Add a top-level COMPENDIUM scene, accessed from the main menu
      AND the in-combat help overlay. One tab per system: Keywords,
      Floop Types, Spell Types, Reactive Triggers. Every term on one
      searchable page so a stuck player can step out of combat and
      look something up without quitting the run.

  The information IS in the game (KeywordEffects, EncounterDB, CardDB
  all hold the descriptions). It's just locked behind a static panel
  instead of woven into the card text itself.

17.5 Animated Card Hover / Hand Juice -- PARTIAL

  Audit note: Card2D ALREADY has a real hover state. On mouse-enter
  (Card2D.gd:3846) the card lifts 80px (not 30 as the older draft
  said), scales to 1.15x, resets rotation to 0, z-indexes to 10, and
  sets a GILT_BRIGHT border. A hover detail panel renders after
  UserSettings.tooltip_delay seconds (0 = instant). Mouse-exit
  restores everything. Drag suppresses hover and shrinks the card to
  0.85x (Hearthstone / Cross Blitz convention).

  Still missing: tilt-toward-cursor, neighbor-push (adjacent cards
  don't shift sideways), tween-based easing (current hover uses raw
  Vector2 assignments, not eased curves), and squash-and-stretch
  arrival.

  Gap vs genre: hand juice is the polish gold standard for card-game
  feel. Wildfrost's hand bounces with squash-and-stretch on hover.
  MtG Arena's cards tilt toward the cursor in 3D. Even STS does a
  clean lift + slight rotation. The hand is where the player's eye
  spends the most time, and BM's hand currently moves more like an
  inventory than a deck.

  Planned (not implemented):
    - Hover begins a tween, 0.18s ease_out, that does THREE things:
        1. Lift the card up 30px (already present), keep this.
        2. Rotate the card around its lifted pivot to point gently
           AT the cursor -- max +/- 8 degrees, scaled by cursor
           distance from card center. Updates each frame while hover
           is held.
        3. Push the LEFT neighbor card 14px left and the RIGHT
           neighbor card 14px right, each with their own 0.12s
           ease_out tween, so the hovered card has breathing room.
    - After 0.6s of continuous hover, fade in a card-preview panel
      (320x440) anchored above the card, showing the full art at
      higher zoom with full description below. This panel REPLACES
      the current tooltip and is where the nested keyword tooltips
      (17.11) live.
    - On drag start, the lift + rotation + neighbor-push reset
      immediately so the card snaps to the cursor without hand-juice
      fighting the drag.

  One tween system, one set of curves. Two days of work; the hand
  starts feeling like a card game instead of a spreadsheet row.
